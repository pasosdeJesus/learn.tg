## Phase 1 — Church directory + minimal reputation (priority)

**Goal:** a public church directory that shows verified churches and their
reputation, with the minimum reputation data needed to make the directory
useful. This phase generates visible value (the directory) without waiting for
the full reputation system.

### 1. Church directory

A public listing of churches that pdJ has verified. Each entry shows the church
profile and its reputation. The directory is the public surface of the
reputation system.

#### 1.1 Fields shown per region

| Field | Region type 1 | Region type 2 |
|-------|---------------|---------------|
| Church name | shown | alias |
| City, country | shown | 🌍, country hidden |
| Denomination | shown | shown |
| Lead pastor (link to public profile) | shown | hidden or alias |
| Reputation (tier + points) | shown | shown |
| `guide_score` (aggregated) | shown (only if reputation ≥ 0) | hidden |
| `amount_member` (aggregated) | shown (only if reputation ≥ 0) | hidden |

`amount_member` is `COUNT(*)` of `usuario` rows with `church_id = church.id`
(lead pastor, co-pastors, leaders, members). It is an aggregate per church,
never a per-person list.

Churches with negative reputation show the reputation but **not** `guide_score`
nor `amount_member`.

#### 1.2 Listing states

| State | When | Effect |
|-------|------|--------|
| **Listed** | Church verified, no active evidence | Shown with positive reputation |
| **Listed with caution** | Active evidence of dishonesty/abuse against lead pastor or co-pastor | Shown with reputation capped at -50, `guide_score`/`amount_member` hidden |
| **Not listed** | (a) not yet verified, (b) region type 2 without consent, (c) third-party evidence not verifiable by pdJ | Excluded from the directory |

#### 1.3 Who maintains the directory

- **pdJ (verifiers):** create, verify, list, unlist churches; record evidence; apply reputation.
- **Pastors:** claim their church (`/api/directory/churches/[id]/claim`), request corrections, opt in/out of public visibility in region type 2.

### 2. Minimal reputation (Phase 1)

#### 2.1 Church reputation (positive, minimal)

| Activity | Points | Frequency |
|----------|--------|-----------|
| Church registered | +10 | One time |
| Pastor verified | +20 | One time |
| Course completed by member | +2 each | Per member |

#### 2.2 Pastor reputation (positive, minimal)

| Activity | Points | Frequency |
|----------|--------|-----------|
| Pastor verified | +10 | One time |
| Course completed | +5 per course | Per course |

#### 2.3 Negative reputation (Phase 1)

Negative reputation is applied when pdJ records verified evidence against a
pastor or co-pastor. The evidence is the source of truth; the church reputation
is derived from it.

| Cause | Automatic | Effect on the church |
|-------|-----------|---------------------|
| Dishonesty | yes | Church reputation capped at -50 |
| Sexual abuse | yes | Church reputation capped at -50 |
| Zionism | no | Recorded, no automatic effect on the church (Phase 1) |
| Other | no | Extensible (Phase 2) |

Rules:

- **Pastor principal or co-pastor** with active evidence of `dishonesty` or
  `sexual_abuse` → church capped at -50.
- **Multiple active evidences against the same pastor** → the penalty is applied
  **once** (still -50, not accumulative).
- **Leader** with active evidence → church penalized -20 (no cap).
- **Member** with active evidence → church penalized -10 (no cap).
- **Zionism** → recorded with file, but the church is **not** penalized
  automatically in Phase 1.
- At least one file must be attached to each evidence record.
- The church is still listed in the directory, with negative reputation.
- `guide_score` and `amount_member` are hidden while the negative reputation is
  active.
- No compensation: while the evidence is active, the church cannot show a
  positive reputation, no matter how many points its members accumulate.

### 3. Database schema (Phase 1)

#### 3.1 `pastorreputation`

```sql
CREATE TABLE pastorreputation (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER REFERENCES usuario(id) NOT NULL,
    reputation_score INTEGER DEFAULT 0,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 3.2 `reputationevidence`

```sql
CREATE TABLE reputationevidence (
    id SERIAL PRIMARY KEY,
    pastorreputation_id INTEGER REFERENCES pastorreputation(id) NOT NULL,
    evidence_reason VARCHAR(50) NOT NULL,   -- 'dishonesty', 'sexual_abuse', 'zionism', 'other'
    evidence_notes TEXT,                     -- private, pdJ only
    recorded_by INTEGER REFERENCES usuario(id) NOT NULL,
    recorded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    resolved_at TIMESTAMP,                   -- NULL = active
    resolved_by INTEGER REFERENCES usuario(id),
    resolution_notes TEXT
);
```

#### 3.3 `reputationevidencefile`

```sql
CREATE TABLE reputationevidencefile (
    id SERIAL PRIMARY KEY,
    reputationevidence_id INTEGER REFERENCES reputationevidence(id) NOT NULL,
    file_path VARCHAR(255) NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_mime VARCHAR(100),
    file_size INTEGER,
    uploaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

At least one file per evidence record (enforced by the API and by a DB check on
insert).

#### 3.4 `churchreputation`

```sql
CREATE TABLE churchreputation (
    id SERIAL PRIMARY KEY,
    church_id INTEGER REFERENCES church(id) NOT NULL,
    reputation_score INTEGER DEFAULT 0,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

`churchreputation` does **not** store the reason. The reason lives in
`reputationevidence`; the score is derived.

#### 3.5 `church` (existing) — added columns

```sql
ALTER TABLE church ADD COLUMN is_listed BOOLEAN DEFAULT TRUE;
ALTER TABLE church ADD COLUMN listing_reason VARCHAR(50);
ALTER TABLE church ADD COLUMN consent_public BOOLEAN DEFAULT TRUE;
```

#### 3.6 `msip_pais.tipo_region` (existing)

The classification lives in `msip_pais.tipo_region` (1 = region type 1,
2 = region type 2, `NULL` = unclassified). The directory applies it to decide
what to show. No new table.

#### 3.7 Trigger: recalculation

`AFTER INSERT OR UPDATE ON reputationevidence` → recalculate
`churchreputation.reputation_score` for the church of the affected pastor.

- The trigger recalculates **only the church of the affected pastor**.
- It applies the cap at -50 if there is at least one active evidence of
  `dishonesty` or `sexual_abuse` against the lead pastor or a co-pastor.
- It applies -20 if the active evidence is against a leader (no cap).
- It applies -10 if the active evidence is against a member (no cap).
- The penalty is applied **once** per role, even if the same person has multiple
  active evidences.
- `zionism` is recorded but does not change the score (Phase 1).

## Phase 2 — Full reputation

**Goal:** the complete reputation system, built on Phase 1.

### 8. Positive reputation (full)

#### 8.1 Church reputation

| Activity | Points | Frequency |
|----------|--------|-----------|
| Church registered | +10 | One time |
| Pastor verified | +20 | One time |
| Course completed by member | +2 each | Per member |
| Referral (church to another) | +15 | Per referral |
| Donation received | +1 per $10 USDT | Ongoing |
| AEE participation | +20 | Per event |
| Report submitted | +5 | Per report |

#### 8.2 Pastor reputation

| Activity | Points | Frequency |
|----------|--------|-----------|
| Pastor verified | +10 | One time |
| Course completed | +5 per course | Per course |
| Church members active | +1 per member | Per active member |
| Referral (pastor to another) | +20 | Per referral |

#### 8.3 Inactivity penalty

Active in a month if at least one of: completes a guide/course, submits a
crossword, makes or receives a donation, participates in an AEE event, submits
a report, or any action logged in `userevent`.

| Inactive period | Penalty |
|-----------------|---------|
| 1 month | -2 |
| 3 months | -10 |
| 6 months | -30 |
| 12 months | Reset to 0 |

### 9. Negative reputation (full)

#### 9.1 Blocking roles

| Role | Effect on the person | Effect on the church |
|------|----------------------|----------------------|
| Lead pastor (`pastor`) | -100 | Church capped at -50 (not compensable) |
| Co-pastor (`co_pastor`) | -100 | Church capped at -50 (not compensable) |
| Leader (`leader`) | -100 | Church penalized -20 (not capped) |
| Member (`member`) | -100 | Church penalized -10 (not capped) |

#### 9.2 Block causes

| Cause | Automatic | Phase |
|-------|-----------|-------|
| Dishonesty | yes | Phase 1 |
| Sexual abuse | yes | Phase 1 |
| Zionism | no | Phase 1 (recorded, no automatic effect) |
| Other | no | Phase 2 (extensible) |

#### 9.3 No compensation

A blocked church cannot show a positive reputation, no matter how many points
its members accumulate.

```
Church reputation =
  if lead pastor OR any co-pastor has active evidence of dishonesty/abuse:
    min(calculated_score, -50)
  else: calculated_score
```

#### 9.4 Effects

| Reputation level | Effect on pastor | Effect on church |
|------------------|------------------|------------------|
| -100 | Cannot register on learn.tg; cannot be pastor of any church | Church capped at -50 |
| -50 | — | No church fund access; not featured in ranking |

#### 9.5 Change of pastor

| Scenario | Effect on church |
|----------|------------------|
| Lead pastor or co-pastor with active evidence | Church reputation capped at -50 (not compensable) |
| Evidence resolved | The cap is lifted; the church keeps its own score |
| New lead pastor assumes | Church keeps its own score (does not adopt the new pastor's) |
| Church becomes orphaned | Church keeps its own score (does not reset to 0) |

#### 9.6 Appeal process

| Step | Description |
|------|-------------|
| 1. Request | Affected pastor submits appeal |
| 2. Evidence | Pastor presents evidence of change or accountability |
| 3. Review | pdJ reviews the case |
| 4. Decision | pdJ decides to restore reputation (to 0 or positive) |

|------|--------------|-------|
| Bronze | 1-49 | 🥉 |
| Silver | 50-99 | 🥈 |

### 12. Database schema (Phase 2)

#### 12.1 `reputationhistory`

```sql
CREATE TABLE reputationhistory (
    id SERIAL PRIMARY KEY,
    entity_type VARCHAR(20),
    entity_id INTEGER NOT NULL,
    previous_score INTEGER,
    new_score INTEGER,
    change_reason VARCHAR(100),
    changed_by INTEGER REFERENCES usuario(id),
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 13. Algorithm (Phase 2)

#### 13.1 Church reputation calculation

Aggregated from §8.1 minus inactivity penalty (§8.3) and the cap from active
evidence (§9.3).

#### 13.2 Pastor reputation calculation

Aggregated from §8.2 minus inactivity penalty (§8.3). Returns -100 immediately
if the pastor is blocked (§9.4).
