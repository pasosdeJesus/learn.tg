# R-#208: E2E hydration regression — ConnectWalletButton not rendered on Next 16 dev server

The Puppeteer E2E specs (`full-flow.spec.mjs` and the new
`pastor-journey.spec.mjs`) fail at their first step: the `Connect Wallet`
button never appears. `ConnectWalletButton` is a client component that is no
longer hydrating on the dev server after the Next.js 16 upgrade (REQ/205).

---

**Created:** 2026-08-18
**Status:** En curso (root cause por confirmar; diagnóstico en progreso)

**Related:** REQ/205 (Next.js 16.3.1 upgrade), REQ/207 (vitest 3.2.7)

---

## Symptom

```
── Step 1: Pastor connects wallet ──
✗ Connect Wallet not visible
```

- New spec `apps/nextjs/e2e/specs/pastor-journey.spec.mjs` (pastor Sierra
  Leona) fails at `Connect Wallet not visible`.
- `full-flow.spec.mjs` — which previously passed — now fails at the **same**
  point. This proves the regression is in the dev server, not in the new spec.
- In Puppeteer, `buttonCount: 0` at +5s, +15s and +30s after
  `domcontentloaded`. The page text never contains `Connect Wallet` /
  `Conectar Billetera`.
- The dev server `https://learn.tg:9001` is already serving **Next.js 16.3.1**
  (the redeploy from REQ/205), not the older 15.5.x.

## Root cause (hypothesis)

`ConnectWalletButton` is a `'use client'` component. It returns `null` until
`useAuthAddress()` reports `isWalletCheckComplete` (i.e. until
`window.ethereum` is inspected in a `useEffect`). If the client bundle does
**not hydrate**, that `useEffect` never runs, `isWalletCheckComplete` stays
`false`, and the button is never painted.

The dev server was rebuilt with Next.js 16 + Webpack + SWC-WASM (REQ/205).
The most likely triggers, in order of probability:

1. **Incomplete SWC-WASM install on the dev server.** Next 16's on-demand WASM
   download leaves `node_modules/next/wasm/@next/swc-wasm-nodejs/` empty
   (see REQ/205 §2.7). The `make swc-wasm` workaround was applied locally but
   may not have been re-applied on the remote dev server, so the dev compile
   silently fails to produce (or produces a broken) client bundle.
2. **Dev server started without `--webpack`.** Next 16 defaults to Turbopack,
   whose native `next-swc` bindings don't exist on OpenBSD. If the dev server
   process was restarted without `--webpack`, compilation/hydration breaks.
3. A Next 16-specific change in how `useSession()` (next-auth) + `'use client'`
   hydration behaves under Webpack, only reproducible on the live dev server.

## Strategies to resolve (exact next steps)

1. **Verify the dev server SWC-WASM workaround** (most likely fix):
   - Check `node_modules/next/wasm/@next/swc-wasm-nodejs/` on the dev host has
     both `wasm.js` and `wasm_bg.wasm` (not empty).
   - If empty, run `make swc-wasm` (copies them from
     `node_modules/@next/swc-wasm-nodejs/`).
   - Confirm the dev server is started with `--webpack` (`bin/dev` /
     `next dev -p 9001 --webpack`).
   - Restart the dev server.
2. **Reproduce locally with the debug console** to confirm the logs and isolate
   where hydration stops:
   ```sh
   cd apps/nextjs
   sh -c 'ulimit -d 7340032 && . ../.env && exec node_modules/next/dist/bin/next dev -p 4000 --webpack'
   # open http://localhost:4000/en?debug=1
   ```
   Expected logs if hydration runs: `useAuthAddress: checking wallet
   availability`, `useAuthAddress: eth_accounts=…`, `ConnectWalletButton:
   rendered …`. If none appear, hydration itself is failing.
3. **Run the new spec with debug** against the (fixed) dev server:
   ```sh
   cd apps/nextjs
   CHROME_PATH=/usr/local/bin/chrome IPDES=learn.tg PUERTOPRU=9001 CHAIN_ID=11142220 \
     node e2e/specs/pastor-journey.spec.mjs
   ```
4. **Re-run the full E2E suite** once the dev server hydrates:
   ```sh
   cd apps/nextjs
   CHROME_PATH=/usr/local/bin/chrome make test-e2e
   ```
5. Adjust the new spec's profile fields if any don't map exactly
   (`registration`, `denomination`, `position_israel_gaza`,
   `church_relationship`, etc.).
6. Update `doc/e2e-testing.md` with the new spec and the Next 16 dev-server
   hydration failure + workaround.
7. Note: `apps/.env` is currently in full-local mode (not proxy). To return to
   proxy mode: `cp apps/.env.bak.full-local apps/.env`.
