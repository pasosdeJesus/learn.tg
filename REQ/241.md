# R-#241: Offline Guide Reading


**Link:** https://github.com/pasosdeJesus/learn.tg/issues/241

**Status:** In progress (2026-09-15, branch `mvppwa`) — reading a **visited**
guide offline works (IndexedDB Markdown cache + the R-#240 page cache); the
offline progress queue is pending.
**Created:** 2026-09-15
**Type:** Feature
**Priority:** High
**Dependencies:** R-#240

---

### 1. Objective

Allow users to read course guides offline. When a guide is visited online, its content and images are cached. When offline, the guide is served from cache. Progress is saved locally and synced when connection returns.

### 2. Changes

**Already provided by R-#240 (2026-09-15):** the service worker caches the page
routes (`/[en|es]/*`, `NetworkFirst`, 24 h) and `/_next/static` (`CacheFirst`,
7 days), and `components/OfflineBanner.tsx` is mounted in the app shell. So a
guide that was **already visited** should render offline without extra work;
this REQ's remaining work is caching the Markdown/HTML in IndexedDB (to render
guides that were never visited while online) and the offline progress queue.

**Cache guide content:** ✅ done

- In `app/[lang]/[pathPrefix]/[pathSuffix]/page.tsx`, after fetching the guide with `authedGet` (the standard same-origin mechanism of R-#235: session cookie, no API token), the raw Markdown is cached in IndexedDB through `useCachedGuide`. ✅
- When the browser is offline, or when the request fails, the page renders the cached Markdown with `htmlDeMd` and shows "Mostrando la copia guardada: tu dispositivo está sin conexión." ✅
- Cache the rendered HTML too (avoid re-processing Markdown offline): ⬜ not done — `htmlDeMd` is cheap (remark/rehype in memory) and caching HTML would double the stored size.
- Service worker caches the page route itself (`NetworkFirst`). ✅ (R-#240)
- Images of the guides and site icons (`/img/*`, `/icons/*`): ✅ cached by the
  service worker (`CacheFirst`, 30 days) — added in R-#240 §2 for this REQ.
- Storage: `lib/offline-guide-db.ts` (IndexedDB `learn-tg-offline` → `guides`, with an in-memory fallback when IndexedDB is unavailable).

**New hook `lib/hooks/useCachedGuide.ts`:** ✅ done

- `getCached()` reads the guide Markdown from IndexedDB, `save()` writes it, `remove()` deletes it.
- Reports `isOffline` (from `useOfflineStatus`) and `isFromCache` so the page can mark the copy it is showing.
- The page decides: offline → cache first, network as fallback; online → network, then cache on failure.

**Update `useGuideData`:** 🟡 not needed for the guide itself

- When offline, use cached course data (from `useCourse` cache): the course catalog
  comes from `/api/course-catalog`, which the R-#240 service worker already
  caches (`NetworkFirst`, 1 h). A dedicated IndexedDB course cache is pending.
- When offline, use cached guide data. ✅ (handled in the page, not in this hook,
  which only composes `useCourse` + navigation)

**Progress offline:** ✅ done in R-#242 (the progress is the crossword result)

- Store `guide_usuario` progress in IndexedDB when offline: the answer payload
  is queued in `lib/offline-queue-db.ts` (store `pending`), together with the
  URL it has to be replayed to.
- Sync when online: `lib/hooks/useOfflineQueue.ts` replays it on mount and on the
  browser `online` event, in page context so the session cookie authorizes it.

**Hook actually used instead of `lib/hooks/useOfflineProgress.ts`:**
`lib/hooks/useOfflineQueue.ts` (`pending`, `enqueue`, `flush`, `refresh`). The
name is shared with R-#242 because the queue is generic (URL + body), not tied
to guides.

### 5. Testing plan

**Unit tests** (new): ✅

- `useCachedGuide` saves/reads the cached Markdown and reports `isOffline` /
  `isFromCache` (`lib/hooks/__tests__/useCachedGuide.test.ts`, 6 tests).
- `lib/offline-guide-db.ts` round-trip: save, read, overwrite, delete

Note: jsdom has no IndexedDB, so these tests exercise the in-memory fallback;
installing `fake-indexeddb` would let them cover the real store.

**Manual tests** (documented in `doc/pdj-wallet-testing.md`):

1. Open `learn.tg:9001/en/gdcluster/guide1` online.
2. Turn off connection.
3. Reload: guide 1 still visible.
4. Mark guide as read offline.
5. Turn on connection.
6. Verify progress synced.
