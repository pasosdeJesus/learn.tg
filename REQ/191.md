# R-#191: Full-Flow E2E Test — Session Persistence Across Navigations

The `full-flow.spec.mjs` puppeteer test fails at Step 9 (UBI Claim) because
the SIWE session is lost after multiple page navigations.

## Problem

```
Step 2: SIWE complete — token persisted (9ea1fe8cbb...)
Step 3-8: Multiple navigations (courses, donate, profile, guide, crossword)
Step 9: Claim button not found — session lost
```

The test wallet connects successfully via SIWE in Step 2, but after ~7 page
navigations the NextAuth session becomes stale and the claim button
(which requires authentication) is no longer rendered.

## Root Cause

NextAuth `useSession()` relies on a JWT cookie. During client-side navigation
(App Router `Link` or `router.push`), the session can be lost due to
[NextAuth bug #5719](https://github.com/nextauthjs/next-auth/issues/5719).

The `WalletEventListener` component (R-#186) mitigates this by storing the
session address and auth token in `localStorage`, and `useAuthAddress()` has a
fallback. However, the UI components that render the Claim button check
`useSession().data?.address` directly, which does NOT use the localStorage
fallback.

## Current Workaround in Tests

- `ensureSessionAlive()` checks both localStorage AND the session API.
- The `prod-landing-to-profile.spec.mjs` test connects once and navigates
  directly — fewer navigations → session survives.
- `church-persistence.spec.mjs` was rewritten to use `setupSIWEMock` instead
  of `simulateSIWE`.

## Proposed Solutions

### Option A: Fix Claim Button to Use `useAuthAddress`

All UI components that check authentication should use `useAuthAddress()`
instead of `useSession()` directly, since `useAuthAddress()` has the
localStorage fallback.

```tsx
// Before
const { data: session } = useSession()
if (!session?.address) return null

// After  
const { address } = useAuthAddress()
if (!address) return null
```

### Option B: Refresh Session Before Each Navigation

Add session refresh logic to `WalletEventListener` or the layout that
refreshes the NextAuth session before each client-side navigation.

### Option C: Reduce Test Steps

Split `full-flow.spec.mjs` into smaller focused tests, each with fewer
navigations.

## Acceptance Criteria

- [ ] `full-flow.spec.mjs` passes against the dev server without session loss
- [x] Claim UBI button is found at Step 9 consistently — fixed `CeloUbiButton` to use `sessionAddress` (localStorage fallback) instead of `session` for disabled state
- [ ] Disconnect button is found at Step 10
