# R-#191: Full-Flow E2E Test — Session Persistence Across Navigations

The `full-flow.spec.mjs` puppeteer test fails at Step 9 (UBI Claim) because
the SIWE session is lost after multiple page navigations.

## Problem

```
Step 2: SIWE complete — token persisted (9ea1fe8cbb...)
Step 3-8: Multiple navigations (courses, donate, profile, guide, crossword)
Step 9: Claim button not found — session lost
```

The test wallet connects successfully via SIWE in Step 2, but after ~7 page
navigations the NextAuth session becomes stale and the claim button
(which requires authentication) is no longer rendered.

## Root Cause

NextAuth `useSession()` relies on a JWT cookie. During client-side navigation
(App Router `Link` or `router.push`), the session can be lost due to
[NextAuth bug #5719](https://github.com/nextauthjs/next-auth/issues/5719).

The `WalletEventListener` component (R-#186) mitigates this by storing the
session address and auth token in `localStorage`, and `useAuthAddress()` has a
fallback. However, the UI components that render the Claim button check
`useSession().data?.address` directly, which does NOT use the localStorage
fallback.

## Current Workaround in Tests

- `ensureSessionAlive()` checks both localStorage AND the session API.
- The `prod-landing-to-profile.spec.mjs` test connects once and navigates
  directly — fewer navigations → session survives.
- `church-persistence.spec.mjs` was rewritten to use `setupSIWEMock` instead
  of `simulateSIWE`.

## Proposed Solutions

### Option A: Migrate All Components to `useAuthAddress` (RECOMMENDED)

All UI components that check authentication must use `useAuthAddress()` instead
of `useSession()` directly, since `useAuthAddress()` has the localStorage
fallback. This is the root fix — not a workaround.

**Components already migrated:**
- `CeloUbiButton`: uses `sessionAddress` (localStorage fallback) ✅

**Components still using `useSession()` (all already have `useAuthAddress` too):**
- `[pathPrefix]/[pathSuffix]/page.tsx` — guide page: partial login check + button visibility
- `[pathPrefix]/page.tsx` — course page: scholarship data
- `profile/page.tsx` — profile: auth check
- `page.tsx` — landing: course loading
- `Header.tsx` — address display
- `WalletEventListener.tsx` — disconnect detection
- `VerificationScheduler.tsx` — auth token for booking
- `NewChurchDialog.tsx`, `DeleteVerifiedDataDialog.tsx` — form submission tokens

**Assessment**: All critical components already use `useAuthAddress` in parallel. The `useSession()` calls are mainly for partial login guards and NextAuth-specific features. The CeloUbiButton fix was the primary blocker for Step 9.

**Step 1 failure** (full-flow): "Connect Wallet not visible" — likely a test environment issue (page doesn't fully render before test checks), not a session persistence bug. 10/11 other specs pass including prod-landing-to-profile which does the same connect flow.

### Option B: Refresh Session Before Each Navigation (REJECTED)

Adds overhead without solving the root cause. Only consider if PWA requires
offline session persistence beyond localStorage.

### Option C: Reduce Test Steps (REJECTED)

Hides the problem instead of solving it.
