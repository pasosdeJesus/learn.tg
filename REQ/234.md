### 1. Objective

Convert `learn.tg` into a **Progressive Web App (PWA)** that works **offline-first** in low-connectivity contexts (Seria/Falaba, Sierra Leone), while enabling a self-custodied in-app wallet and pluggable tools built as packages (starting with `gdcluster`).

### 2. Motivation

The current app assumes a stable internet connection. Users in Seria/Falaba experience:

- **Unstable electricity** — devices can't stay charged
- **Intermittent signal** — no internet for hours at a time
- **Two SIMs (Orange/Africell)** — users choose whichever works at the moment
- **High data costs** — every byte matters

Without a PWA, learn.tg is unusable in these contexts. With a PWA, the core learning experience can happen offline, and synchronization can happen when the opportunity arises.

Additionally, the ecosystem already has a **real tool built as a package**: `gdcluster` (R-#35). The PWA must be able to load `gdcluster` **dynamically** and let it work **offline-first** with its own data.

---

### 3. Vision (long-term)

The PWA is designed to work offline-first with:

- **Self-custodied in-app wallet** (R-#236, R-#237, R-#238): the user creates a wallet in the browser, encrypted with a PIN, and signs SIWE and transactions locally. No external wallet required.
- **Offline learning** (R-#241): guides are cached after first visit and readable offline. Progress is saved locally and synced when connection returns.
- **Offline crosswords** (R-#242): crosswords are cached and completable offline. Submissions are queued and synced when connection returns.
- **Service worker** (R-#240): caches static assets, the app shell, and the offline fallback page.
- **Installable PWA** (R-#243): users add learn.tg to their home screen.
- **Multi-chain** (E-#177): Celo today, Cardano in the future.
- **Pluggable tools**: tools (engines) are loaded dynamically from packages, starting with `gdcluster`.

**PWA Core Principles:**

| Principle | Description |
|-----------|-------------|
| **Offline-first** | The app works without connection; the network is a bonus |
| **Cache-first** | Static assets are cached; the app loads instantly |
| **Background sync** | Data is synchronized when the connection returns |
| **Installable** | Users can add learn.tg to their home screen |
| **Pluggable tools** | Tools (engines) are loaded dynamically from packages |
| **Lightweight** | The core bundle stays small; tools are loaded on demand |

### 4. Acceptance criteria (PWA level)

- [ ] learn.tg is installable as a PWA (manifest + service worker)
- [ ] The app loads offline (service worker caches static assets)
- [ ] The offline fallback page is shown when a route is not cached
- [ ] An offline indicator is shown when the user loses connection
- [ ] The app works in PWA standalone mode
- [ ] Guides can be read offline (cached after first view)
- [ ] Crosswords can be completed offline (answers stored in IndexedDB)
- [ ] Progress is saved locally and synced when connection is available
- [ ] SIWE signing works offline (in-app wallet)
- [ ] The MVP (R-#244) is demonstrated on the dev site

Each individual REQ has its own acceptance criteria. This list is the PWA-level aggregate.

---

### 5. Out of scope

- Native mobile app (PWA only)
- Full offline support for all tools (only cacheable tools)
- Background sync for Cardano (future, E-#177)
- Push notifications (future)
- Offline UBI claims (requires connection)
- Offline donations (requires connection)
