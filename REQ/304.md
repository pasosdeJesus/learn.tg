# R-#304: Un miembro (no pastor) ve y pulsa «Crear un clúster» en la página del clúster

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/304
**Created:** 2026-11-21
**Updated:** 2026-11-21
**Status:** Proposal — reportado por el revisor del curso el 2026-11-20; la API ya lo impide,
falta la interfaz
**Type:** Fix de producto (UI) en la página del clúster
**Priority:** Media — no se crea nada (la API responde 403), pero se ofrece una acción que no
existe para esa cuenta y el mensaje que la explica está escrito y sin usar.

## Summary (EN)

A member who is not a pastor sees the **Create a cluster** button and the creation form on
`/{lang}/cluster`; pressing it fails with `403 Only pastors can create clusters`. The API is
right; the page should not offer the action. The copy that explains it (`notPastor`) already
exists in the page's dictionary and is never used.

## 1. Síntoma

Reporte del revisor del curso (2026-11-20):

> "Non pastora should not be able to create a cluster. They shouldn't see the button
> Create a cluster."

Hoy la cuenta ve el botón, abre el formulario (nombre interno, alias, invitar pastores) y sólo
al enviar recibe el error de la API.

## 2. Evidencia

- `apps/web/app/[lang]/cluster/page.tsx:174` — la tarjeta de creación se pinta con
  `status === 'none'` (y el formulario en `:189` con `showCreate`), sin mirar el rol de la
  cuenta. El texto `notPastor: 'Only lead pastors of a verified church can create a cluster.'`
  (línea 58; español en la 79) **no se usa en ningún sitio**.
- `packages/gdcluster/src/routes/gd-cluster.ts:42` — la API sí lo impide:
  `if (user.church_relationship !== 'pastor') → 403 Only pastors can create clusters`.
- `packages/gdcluster/src/routes/gd-invitations.ts:23-31` — `/api/cluster/status` devuelve
  `{ hasCluster: false, noChurch: true }` cuando la cuenta no tiene iglesia de pastor, pero **no
  dice el rol**: la página no puede distinguir "miembro" de "pastor sin iglesia registrada".
- El mensaje de la interfaz promete una regla más estricta que la de la API:
  `church_relationship` es lo que la persona declara; lo que confirma el verificador es
  `verified_church_relationship` (tabla `usuario`, valores `pastor`/`leader`/`member`).

## 3. Qué cambiar

1. **Que el estado diga quién puede crear.** `/api/cluster/status` devuelve `canCreate: boolean`
   y `why` (p. ej. `not_pastor` | `no_church` | `no_course` | `country_not_allowed` |
   `cluster_completed`), calculado con la misma regla que `POST /api/cluster`. Así la página no
   duplica la lógica y el mensaje siempre coincide con la API.
2. **Ocultar la acción**, no sólo deshabilitarla: sin botón ni formulario, y el aviso que
   corresponda (`notPastor` u otro) en su lugar. El aviso debe decir la verdad de la regla
   elegida en (3).
3. **Decidir la regla**: ¿basta `church_relationship = 'pastor'` (lo que hace la API hoy) o se
   exige `verified_church_relationship = 'pastor'` (lo que promete el texto)? Cualquiera de las
   dos es defendible; la interfaz, la API y el texto deben decir lo mismo.
4. **Mantener la defensa en la API** (no quitarla): el 403 se queda como segunda barrera.
5. Vocabulario neutro: "Only lead pastors of a verified church can create a cluster" / "Sólo el
   pastor principal de una iglesia verificada puede crear un clúster", sin marcar género en el
   texto.

## 4. Criterios de aceptación

- [ ] Una cuenta con `church_relationship = 'member'` (o `leader`) **no ve** el botón «Crear un
  clúster» ni el formulario; ve el aviso que explica por qué.
- [ ] Un pastor sin iglesia registrada ve el aviso correspondiente (no el de "no pastor").
- [ ] El 403 de `POST /api/cluster` sigue ahí (defensa en profundidad) y hay prueba unitaria de
  la ruta de estado para cada rol.
- [ ] E2E: una billetera `member` abre `/{lang}/cluster` y no encuentra el botón (añadir al
  `cluster-page.spec.mjs` o a una spec corta nueva, sin gastar pastores).
- [ ] El texto de la interfaz coincide con la regla que aplica la API.

## 5. Cómo reproducir

1. Entrar con una cuenta cuyo `church_relationship` no sea `pastor` (una `member` del registro
   E2E sirve).
2. Abrir `/{lang}/cluster`.
3. Hoy: se ve «Crear un clúster» y el formulario; al enviar, `403 Only pastors can create
   clusters`.
