# R-#268: Problems in production

Problems in production (operator report, 2026-09-27): offline PWA behaviour and the
Global Disciples donations.

## Offline (PWA)

1. **The course page fell into the offline fallback.** Offline,
   `https://learn.tg/en/a-relationship-with-Jesus` showed "You are offline" and the
   list of courses saved on the device, instead of the course presentation and its
   guides. The download of a course warmed the service worker cache with each guide
   page and its crossword, but never with the course page itself.

2. **A deactivated course stayed in the offline library.** That list included
   "GoodDollar" (`1. GoodDollar and UBI`), a course that is no longer presented in
   `/en/`. The offline catalog was requested without the filter the course list uses
   (`filtro[busconBilletera]=true`), so `GET /api/course-catalog` answered with every
   course of the language — including deactivated ones, whose two flags are off — and
   they were downloaded. A copy already on the device was never removed either.

3. **The figures of a guide were missing offline.** Offline, a downloaded guide
   opened (and its crossword could be completed and submitted) but without its
   images: they had never been requested, so no cache held them.

Confirmed as correct behaviour (no change): `/en/gdcluster` offline answers
"Error offline" when this wallet has not bought that course.

## Donations (Global Disciples)

4. **"replacement transaction underpriced".** After buying the course, donating to
   the GD course vault failed with `An unknown RPC error occurred … Details:
   replacement transaction underpriced` (viem `writeContract`, `transfer(address,
   uint256)`), and the same happened when donating to a country fund from
   `gdcluster/ranking`. A donation to a course, cluster or country can carry **two**
   ERC-20 transfers (USDT and SLEARN) and `useContractPayment` sends them one after
   the other; the second reused the nonce of the first, still pending in the mempool,
   and the RPC rejected it. The same race is described in
   `e2e/specs/vault-both-donate.spec.mjs`, which passes explicit nonces to avoid it.

## Resolution

| Problem | Change |
|---|---|
| 1 | `downloadCourse` also warms the course page (`lib/offline-course-download.ts`) |
| 2 | `listAccessibleCourses` requests the catalog with the site's filter; `pruneUnavailableCourses` deletes the copy of a course that left the catalog (`downloadAllAccessible`, `result.removed`) |
| 3 | `guideImageUrls` + `warmImageCache` save the guide figures in `learntg-images`, whose `/img\|icons/` rule now ignores `Vary` |
| 4 | `@pasosdejesus/usdt@0.1.3` → `lib/send-transfers.ts`: a transfer waits for the previous receipt and a rejected transfer is retried, so the second one never reuses a pending nonce (`useContractPayment` uses it; the host wrapper in learn.tg went back to a thin re-export) |
| 5 (found while verifying) | The automatic sync did not keep the course presentation (subtitle, summary, extended description) nor the figure: `listAccessibleCourses` now reads them, the record stores them, `courseFromDownloaded` exposes them and `isCacheableImage`/`warmImageCache` save the figure; a copy without them refreshes itself |
| 6 (found while verifying) | Donating with a wallet on the other chain reached the raw viem `ChainMismatchError`: `DonateModal` now runs `ensureWalletChain` before the ERC-20 and the native CELO paths and explains it (ES/EN), like the checkout |

Tests: `lib/__tests__/offline-course-download.test.ts`,
`lib/__tests__/offline-course-sync.test.ts`,
`lib/hooks/__tests__/useCourse.test.ts`,
`components/__tests__/DonateModal.test.tsx`; the engine sequencing has its own suite in
`m` (`packages/usdt/src/lib/__tests__/send-transfers.test.ts`).

## Verification on the deployed sites (2026-09-27/28)

Operator, offline on the phone, after the first deploy:

- the course page opens with its guides and its progress (problem 1 fixed);
- guide 1 shows its image (problem 3 fixed);
- "GoodDollar" is no longer listed among the saved guides (problem 2 fixed).

Two gaps appeared in that same round, both fixed here:

- **The course presentation and figure were still missing offline**: the automatic sync
  (`listAccessibleCourses`) did not read them, so the record kept no subtitle, summary,
  extended description or figure. Now the presentation travels in the descriptor, the
  record stores it, `courseFromDownloaded` exposes it, the figure is warmed
  (`isCacheableImage`) and a copy without it refreshes itself (like the guide titles).
- **Donating (course 103) failed with the raw viem error** "The current chain of the wallet
  (id: 11142220) does not match the target chain for the transaction (id: 42220 - Celo)":
  `DonateModal` had no chain pre-flight. It now calls `ensureWalletChain` before both the
  ERC-20 and the native CELO paths and explains the mismatch (ES/EN) instead of letting the
  viem error through (R-#266).

Deployment checked in the served bundles of both sites (`learn.tg` and `learn.tg:9001`):
`PayDiag] flow v2.2`, `nonce collision, retrying` and `receipt wait failed, sending anyway`
are present, so the engine sequencing (`@pasosdejesus/usdt@0.1.3`) is live; the previous
host wrapper is gone. The dev-site specs
(`in-app-wallet-payments`, which funds the in-app wallet with two sequential transfers, and
`premium-course-checkout`) pass with 0 failures against the deployed site.
