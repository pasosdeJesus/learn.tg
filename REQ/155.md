## 1. Contract Design: `ClusterFundsV2.sol`

> **https://github.com/pasosdeJesus/learn.tg/issues/214:** V2 replaces `ClusterFunds` (V1). A full copy of V1 plus contribution functions that credit 100 % to the fund. Deployed on celoSepolia `0xcA9c6A93746caF5E8f5Debd3A0a4A710d0E11b2A` (new SLEARN `0x9fBa3A2Ca...`), owned by the backend.

### 1.1 Purpose
- Receive and manage USDT and SLEARN donations for clusters and countries
- **Country donations:** If clusters exist in the country → split equally among them. If no clusters → accumulate in country fund for future distribution
- When a new cluster forms in a country with accumulated funds → redistribute country funds equally among all clusters (including the new one)
- **Yield (Phase 2):** pdJ can deposit idle USDT in AAVE V3 while funds wait for GD contact; yield stays with the fund (70% cluster, 30% pdJ)
- Provide transparency through events

**Phase 2 note:** AAVE yield implementation (Section 4) is Phase 2 — not required for the Global Disciples pilot. The contract will be upgraded to support AAVE after the pilot.

### 1.2 Relationship with Existing Contracts

| Contract | Relationship |
|----------|--------------|
| `LearnTGVaultsV4` | Receives SLEARN from vaults for scholarships |
| `SLEARN.sol` | Can mint SLEARN for donations to clusters |
| `USDT` | Receives USDT donations for clusters |
| `AAVE V3 on Celo` | Yield generation for idle funds (Phase 2) |

### 1.3 Contract Functions

#### Donation Functions

Donations follow the calldata-stuffing pattern: users send USDT/SLEARN via `transfer()` to the backend wallet. The backend verifies on-chain and calls `processDonation()` to allocate.

| Function | Description |
|----------|-------------|
| `processDonation(bytes32 txHash, address clusterWallet, address donor, uint256 usdtAmount, uint256 slearnAmount)` | Process a verified incoming donation: distribute fees via `feeWallets`, remainder to cluster |
| `processCountryDonation(bytes32 txHash, string countryCode, address donor, uint256 usdtAmount, uint256 slearnAmount)` | Process a verified incoming donation to a country fund |

**Fee system (2026-08-10):** replaces the old fixed `pdjTreasury` + `pdjPercentage`. It now uses configurable arrays:

| Function | Description |
|---------|-------------|
| `setFeeConfig(address[] wallets, uint8[] percentages)` | Configures destination wallets and percentages. The sum must be ≤ 100 %. The remainder goes to the cluster/country |
| `getFeeConfig()` | Retorna `(wallets, percentages)` actuales |

**Cashback (2026-08-10):** the contract handles cashback directly:
- USDT → `slearn.mintAndReserve(donor, 10%)` (requires MINTER_ROLE on SLEARN)
- SLEARN → `slearn.transfer(donor, 10%)`

| Function | Description |
|---------|-------------|
| `setDonorCashbackPct(uint8 pct)` | Configures the cashback % (0-50). Default: 10 % |
| `donorCashbackPct()` | Returns the current cashback % |

#### Contribution Functions (V2 — https://github.com/pasosdeJesus/learn.tg/issues/214)

**GD course payments:** 10 % of the payment is routed to the buyer's country/cluster fund **without** fees or cashback. The buyer already receives their reward through `SLEARN.processPayment`; charging fee+cashback again left only 8 % of the payment in the fund (double charge). See https://github.com/pasosdeJesus/learn.tg/issues/214.

| Function | Modifier | Description |
|----------|----------|-------------|
| `processClusterContribution(bytes32 txHash, address clusterWallet, uint256 usdtAmount, uint256 slearnAmount)` | `onlyOwner` | Credits **100 %** of the routed amount to the cluster fund (no fees) |
| `processCountryContribution(bytes32 txHash, string countryCode, uint256 usdtAmount, uint256 slearnAmount)` | `onlyOwner` | Credits **100 %** of the routed amount to the country fund (no fees) |

Both with replay protection (`processedTx`), `whenNotPaused` and `nonReentrant`. They also serve as the entry point of the V1→V2 migration.

**Replay protection:** Each `txHash` is recorded on-chain after processing. `require(!processedTx[txHash], "Already processed")`.

#### Transfer Functions

| Function | Modifier | Description |
|----------|----------|-------------|
| `redistributeCountryFunds(string countryCode, address[] clusters)` | `onlyOwner` | Called by backend when a new cluster forms. Distributes country fund equally among all clusters in that country. Max 100 clusters per call. |
| `releaseClusterFunds(address clusterWallet)` | `onlyOwner` | Transfer ALL accumulated USDT/SLEARN from contract to cluster's wallet. Requires `clusterFunds[clusterWallet].verified == true`. |
| `releaseCountryFunds(string countryCode, address recipient)` | `onlyOwner` | Transfer ALL accumulated USDT/SLEARN from country fund to a recipient. |

**Note:** No `withdrawFunds` function. `releaseClusterFunds` transfers directly to the cluster's `multisig_address`. No two-step release+withdraw needed.

#### Admin Functions

| Function | Modifier | Description |
|----------|----------|-------------|
| `setFeeConfig(address[] wallets, uint8[] percentages)` | `onlyOwner` | Configure fee recipients and percentages. Sum ≤ 100%. Rest to cluster/country. |
| `setClusterVerification(address clusterWallet, bool verified)` | `onlyOwner` | Mark cluster as verified (required before `releaseClusterFunds`) |

#### View Functions

| Function | Description |
|----------|-------------|
| `getClusterBalance(address clusterWallet)` | Get USDT and SLEARN balance of a cluster |
| `getCountryBalance(string countryCode)` | Get USDT and SLEARN balance of a country |
| `getClusterFunds(address clusterWallet)` | Get all fund information for a cluster |
| `getCountryFunds(string countryCode)` | Get all fund information for a country |
| `getFeeConfig()` | Get current fee wallets and percentages |

### 1.4 Events

| Event | Description |
|-------|-------------|
| `ClusterDonation(address donor, address clusterWallet, uint256 usdt, uint256 slearn)` | Donation processed for a cluster |
| `CountryDonation(address donor, string countryCode, uint256 usdt, uint256 slearn)` | Donation processed for a country |
| `ClusterContribution(address clusterWallet, uint256 usdt, uint256 slearn)` | Course payment contribution to a cluster (V2) |
| `CountryContribution(string countryCode, uint256 usdt, uint256 slearn)` | Course payment contribution to a country (V2) |
| `FeeConfigUpdated(address[] wallets, uint8[] percentages)` | Fee configuration changed |
| `FeeDistributed(address recipient, uint256 usdt, uint256 slearn)` | Fee sent to a recipient |
| `DonorCashback(address donor, uint256 usdtBacking, uint256 slearnReturned)` | Cashback sent to donor |
| `DonorCashbackPctUpdated(uint8 newPct)` | Cashback percentage changed |
| `ClusterFundsReleased(address clusterWallet, uint256 usdt, uint256 slearn)` | Funds released to cluster |
| `ClusterRemoved(address clusterWallet, string countryCode, uint256 usdt, uint256 slearn)` | Cluster dissolved, funds → country |
| `ClusterVerified(address clusterWallet, bool verified)` | Cluster verification status changed |

**Removed events (2026-08-10):** `PdjTreasuryUpdated`, `PdjPercentageUpdated`, `PdjFeeDeducted` — replaced by `FeeConfigUpdated` + `FeeDistributed`.

### 1.5 Constructor

```solidity
constructor(address _usdt, address _slearn, address _pdjTreasury, address initialOwner)
```

**Defaults (2026-08-10):** `feeWallets = [_pdjTreasury]`, `feePercentages = [10]`, `donorCashbackPct = 10`. The contract ships ready with 10 % pdJ + 10 % cashback + 80 % cluster.

**Post-deploy:** `hardhat/scripts/setClusterFundsFees.ts` grants `MINTER_ROLE` to ClusterFunds on SLEARN (required for `mintAndReserve`).

**V2 (https://github.com/pasosdeJesus/learn.tg/issues/214):** same constructor and defaults. The deploy writes `deployments/ClusterFundsV2/{network}.json`; the app reads the V2 address through `getClusterFundsAddress()` (see https://github.com/pasosdeJesus/learn.tg/issues/214, Step 3).

### 2.3 Donation Distribution

| Recipient | % | Description |
|-----------|-----|-------------|
| Cluster / Country Fund | 80 % | After fees (10 %) and cashback (10 %). Via `ClusterFunds` |
| pdJ Treasury | 10 % | Via `feeWallets[0]`. Configurable with `setFeeConfig` |
| Donor cashback | 10% | USDT→`mintAndReserve`, SLEARN→`transfer`. Via `donorCashbackPct` |

**Two entry paths (https://github.com/pasosdeJesus/learn.tg/issues/214):**

| Path | Function | Fund receives |
|--------|---------|--------------|
| **Direct donation** (ranking) | `processDonation` / `processCountryDonation` | 80% (after 10% fee + 10% cashback) |
| **GD course payment** (10 % routed) | `processClusterContribution` / `processCountryContribution` | **100 %** of the routed amount (no fees) |

## 3. Contact with Global Disciples

### 3.1 Checkbox-Based Tracking

Contact with GD happens outside the platform. The platform tracks progress via **checkboxes** that cluster members and pdJ mark manually.

```mermaid
flowchart TB
    A[Cluster completes GD course] --> B[Cluster marks: ✅ Sent email to GD]
    B --> C[pdJ marks: ✅ pdJ contacted GD]
    C --> D[Wait for GD response]
    D --> E[pdJ marks: ✅ GD responded]
    E --> F[pdJ marks: ✅ Release funds]
    F --> G[Funds transferred to cluster wallet via ClusterFunds.releaseClusterFunds]
```

### 3.2 Checkbox Permissions

| Checkbox | Who can mark | Description |
|----------|-------------|-------------|
| ✅ Cluster sent email to GD | Cluster (any pastor) | Cluster confirms they contacted GD |
| ✅ pdJ contacted GD | pdJ (admin) | pdJ confirms parallel contact |
| ✅ GD responded | pdJ (admin) | GD confirmed contact with cluster |
| ✅ Release funds | pdJ (admin) | Triggers `releaseClusterFunds()` on-chain |

### 3.3 Status Display (derived, not stored)

Status is derived from checkboxes — no `status` column:

| Checkboxes marked | Display in Ranking |
|-------------------|-------------------|
| None | "⏳ Pending" |
| Cluster sent only | "â Cluster sent" |
| Cluster + pdJ sent | "✅ Ambos enviaron" |
| + GD responded | "✅ Contacto confirmado" |
| + Released | "💰 Funds released" |

### 3.4 Contact Tracking Storage

```sql
CREATE TABLE gdcontact (
    id SERIAL PRIMARY KEY,
    cluster_id INTEGER REFERENCES cluster(id) UNIQUE,
    cluster_sent_at TIMESTAMP,        -- cluster marked: "we sent email"
    pdj_sent_at TIMESTAMP,            -- pdJ marked: "pdJ contacted GD"
    gd_responded_at TIMESTAMP,        -- pdJ marked: "GD responded"
    released_at TIMESTAMP,            -- pdJ marked: "release funds" → triggers releaseClusterFunds()
    release_reason VARCHAR(50),       -- 'gd_confirmed' (Phase 1) or 'timeout' (Phase 2)
    course_completed_at TIMESTAMP,    -- When cluster completed GD course
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_gdcontact_cluster_id ON gdcontact(cluster_id);
```

### 3.5 Fund Release

When pdJ marks the ✅ Release funds checkbox:

1. Backend calls `ClusterFunds.releaseClusterFunds(clusterWallet, usdtAmount, slearnAmount)`
2. If funds were in AAVE (Phase 2), contract withdraws first, distributes 30% yield to pdJ Treasury and 70% to cluster
3. Contract transfers USDT/SLEARN to the cluster's `multisig_address`
4. `gdcontact.released_at` is set to NOW
5. Event logged in `userevent` (`funds_released`)

### 3.6 Who Calls `redistributeCountryFunds`?

`redistributeCountryFunds` is called by the **learn.tg backend** (signing with `PRIVATE_KEY`) **after** a new cluster is successfully created in the database (via #152). The backend detects that the cluster belongs to a country that has accumulated funds and calls the function.

## 4. Yield Strategy for Idle Funds (Phase 2 — Post-Pilot)

This section is **Phase 2** and will be implemented **after** the Global Disciples pilot, not before. The contract will be upgraded to support AAVE in Phase 2.

### 4.1 Overview

Funds in `ClusterFunds` sit idle while waiting for GD contact + release (weeks to months). Since pdJ custodies these funds, pdJ can put them to work safely.

**Yield Distribution:**

| Recipient | % | Purpose |
|-----------|-----|---------|
| Cluster/Country Fund | 70% | Added to the same fund, visible in ranking |
| pdJ Treasury | 30% | Covers operational costs (servers, APIs, development) |

**Design principle:** Most yield stays with the cluster that generated it. pdJ takes a smaller share to cover real operational costs — transparent and visible in the dashboard.

### 4.2 Implementation

| Aspect | Decision |
|--------|----------|
| **Protocol** | AAVE V3 on Celo (USDT only) |
| **Who deposits** | pdJ admin (backend signed with `PRIVATE_KEY`) |
| **Who holds aUSDT** | `ClusterFunds` contract (not a separate wallet) |
| **When to deposit** | After donation, before release (admin-triggered or automatic) |
| **When to withdraw** | Automatically when `releaseClusterFunds()` is called |
| **Yield tracking** | On-chain balance difference tracked per cluster/country |

### 4.3 Transaction Table for AAVE

All AAVE operations are recorded in the existing `transaction` table:

```sql
-- AAVE deposit
INSERT INTO transaction (
    usuario_id, wallet, crypto, type, amount, balance_impact, date, hash,
    categoria, subcategoria, metadata
) VALUES (
    :usuario_id, :wallet, 'USDT', 'aave_deposit', :amount, -:amount, NOW(), :hash,
    'aave', 'deposit', '{"cluster_id": 1}'
);

-- AAVE withdrawal
INSERT INTO transaction (...) VALUES (
    :usuario_id, :wallet, 'USDT', 'aave_withdrawal', :amount, :amount, NOW(), :hash,
    'aave', 'withdrawal', '{"cluster_id": 1, "yield": 0.15}'
);
```

**Note:** Requires adding `'aave_deposit'` and `'aave_withdrawal'` to the `transaction` type CHECK constraint.

### 4.4 Events

| Event | Description |
|-------|-------------|
| `YieldGenerated(address indexed clusterWallet, uint256 yieldUsdt)` | Yield earned from idle funds |
| `YieldDistributed(address indexed clusterWallet, uint256 clusterShare, uint256 pdjShare)` | Yield split between cluster and pdJ |
| `ClusterDonation(address indexed donor, address indexed clusterWallet, uint256 usdtAmount, uint256 slearnAmount)` | Donation to cluster |
| `CountryDonation(address indexed donor, string countryCode, uint256 usdtAmount, uint256 slearnAmount)` | Donation to country |
| `CountryFundsRedistributed(string countryCode, uint256 usdtAmount, uint256 slearnAmount, uint8 clusterCount)` | Country funds distributed equally |
| `ClusterFundsReleased(address indexed clusterWallet, uint256 usdtAmount, uint256 slearnAmount)` | Funds released to cluster |

## 10. Acceptance Criteria

- [x] Contract can receive USDT via ERC-20 `transfer()` and SLEARN via ERC-20 `transfer()` (whitelisted in SLEARN)

- [x] `processCountryDonation()` distributes: feeWallets + donorCashback + remainder to country
- [x] `processClusterContribution()` / `processCountryContribution()` (V2, https://github.com/pasosdeJesus/learn.tg/issues/214): credit 100 % of the routed amount to the fund (GD course payments)
- [ ] Country donations: split equally among existing clusters in that country
- [ ] Country donations: accumulate in country fund when no clusters exist
- [ ] `redistributeCountryFunds()` called by backend when a new cluster forms
- [ ] `releaseClusterFunds()` transfers USDT/SLEARN directly to cluster wallet
- [ ] `releaseCountryFunds()` transfers USDT/SLEARN from country fund
- [ ] On cluster dissolution, all cluster funds → country fund
- [x] ClusterFunds deployed + verified on celoSepolia
- [x] Replay protection: each `txHash` processed only once
- [x] Fee config: `feeWallets=[pdjTreasury]` at 10%, `donorCashbackPct=10` → 80/10/10
- [x] MINTER_ROLE granted to ClusterFunds on SLEARN for mintAndReserve

- [x] Users can donate USDT and SLEARN to clusters via single `transfer()` transaction (no approve)
- [x] `[Donate]` button on every country and cluster row in ranking
- [x] Every donation recorded in `transaction` table with `categoria='donation'`, `subcategoria='cluster'` or `'country'`

- [ ] Cluster can mark "we sent email to GD" checkbox (authenticated, cluster pastor only)
- [ ] pdJ can mark "pdJ contacted GD", "GD responded", and "release funds" checkboxes (admin)
