# R-#202: Unified Payment/Donation Modal

Design a single modal component that handles all value transfers — course
donations, GD cluster/country donations, course payments, and future methods
(Stripe, mobile money).

---

## Current State

`DonateModal.tsx` (~250 lines) tightly coupled to course donations via
`courseId`, `useContractPayment`, `/api/add-donation`, and backend wallet.
Adding GD cluster/country donations would duplicate most UI logic.

## Target Architecture

Single `PaymentModal` component configurable via a `PaymentTarget` object.
The modal handles the **client-side flow** (amount input, gas estimation, wallet
transfer to backend). The **backend** interprets the endpoint and calls the
appropriate contract.

```typescript
type PaymentTarget =
  | CourseDonation | ClusterDonation | CountryDonation
  | CoursePayment
  // Future:
  | StripePayment

interface BaseTarget {
  type: string
  title: string
  description: string
  cryptoAmounts: boolean       // show USDT/SLEARN inputs
  maxButton: boolean
  splitInfo?: string
  rewardInfo?: string
}

interface CourseDonation extends BaseTarget {
  type: 'course-donation'; courseId: number
  splitInfo: '70% scholarships / 20% operations / 10% SLEARN reward'
  rewardInfo: '~{{0}} SLEARN'
}

interface ClusterDonation extends BaseTarget {
  type: 'cluster-donation'; clusterWallet: string; clusterName: string
  splitInfo: '85% cluster / 15% pdJ'
}

interface CountryDonation extends BaseTarget {
  type: 'country-donation'; countryCode: string; countryName: string
  splitInfo: '85% country fund / 15% pdJ'
}

interface CoursePayment extends BaseTarget {
  type: 'course-payment'; courseId: number; price: number
  cryptoAmounts: true; maxButton: false
  // SLEARN discount: 10% off if 100% SLEARN, 5% off if 50% SLEARN/50% USDT, 0% if 100% USDT
  slearnDiscount: boolean
  // Split: 80% vault / 20% operations (inspired by SLEARN-WHITEPAPER.md)
  // For GD course: part of pdJ share → user's church cluster or country (see REQ #155)
}

interface StripePayment extends BaseTarget {
  type: 'stripe'; stripePriceId: string
  cryptoAmounts: false; maxButton: false
  // StripePayment can be applied to any target: course payment, donation, etc.
  // When stripe is selected, crypto inputs are hidden — Stripe handles UI.
}
```

### StripePayment (future)

A centralized payment modal where users choose between **crypto** (wallet) or
**fiat** (Stripe). When Stripe is selected, the crypto inputs are hidden and
Stripe Elements handle the payment UI. The backend processes the Stripe
webhook and calls the same contract logic as the crypto path. Applicable to
all target types (donations and course payments).

### SLEARN Discount (future) — see REQ #148 for full spec

Course payments support SLEARN discounts: 10% off (100% SLEARN), 5% off
(50% SLEARN), 0% off (100% USDT). REQ #148 defines burning, BURNER_ROLE,
mixed payments, and referral rewards. The PaymentModal handles UI only:
discount display and amount calculation.

### GD Course Payment Split (future)

For the GD course specifically, a portion of pdJ's operational share goes to
the user's church cluster or country fund (see REQ #155 — ClusterFunds). This
is configured per-course in the engine manifest, not hardcoded in the modal.

## On-Chain Flow per Target

| Target | Recipient | Backend Callback |
|--------|-----------|------------------|
| `course-donation` | Backend wallet | `POST /api/add-donation` |
| `cluster-donation` | Backend wallet | `POST /api/gdcluster/donations/verify` |
| `country-donation` | Backend wallet | `POST /api/gdcluster/donations/verify` |
| `course-payment` | Backend wallet | `POST /api/pay-course` (TBD) |
| `stripe` | Stripe | Stripe SDK → webhook → same backend logic |
