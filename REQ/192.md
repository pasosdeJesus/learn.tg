## Phase 2 Features

### 1. Registration Photo Verification (Admin)

When a pastor declares a church, they upload a `registration_photo`. The admin must be able to verify this document during the interview.

**Admin UI:**

| Field | Action |
|-------|--------|
| Registration photo | View photo (opens in new window) |
| Registration number | View/edit |
| `registration_verified` | Toggle `true`/`false` |

**Endpoint:** `PATCH /api/admin/church/[id]`

**Process:**
1. Admin views the registration photo via `/api/user/id-photo/[churchId]?side=registration`
2. Admin confirms document is valid
3. Admin sets `registration_verified = true`
4. Church is marked as "verified" on public page

### 2. Pastor Wallet (Phase 2)

**Objective:** Add a wallet address field to the pastor's church record so the church can receive funds.

**Field:** `church.wallet_address` VARCHAR(42)

**Where to collect:**
- Pastor dialogue when declaring a church
- Admin can edit via `/api/admin/church/[id]`

**Why:** Required for clusters and country funds (R-#155).

### 3. Church Curation and Deduplication (Phase 2)

**Problem:** Users may declare duplicate churches (same name, same city) multiple times.

**Solution:** Admin interface for merging duplicates (already in R-#190).

**Additional:**
- Notification when duplicate is detected (future)
- Auto-suggestion of existing churches when user types a name

### 4. SLEARN Bonus (On-Chain) — desde el fondo de iglesias

Reemplazar el stub de `POST /api/admin/pastor-bonus` por una transferencia real
de SLEARN desde el **fondo para iglesias** (`churchesWallet` de `SLEARN.sol`).

**Elegibilidad (actualizada 2026-08-14):**
- Pastor (`church_relationship = 'pastor'`).
- País piloto: Colombia o Sierra Leona (`usuario.pais_id` en `[170, 694]`).
- No sionista: `usuario.position_israel_gaza = 'no'`.
- **Puntaje de perfil > 90** (`usuario.profilescore > 90`).
- Iglesia verificada: `church.registration_verified = true` (el verificador
  confirmó el documento de registro de la iglesia).
- No pagado antes (sin bonus previo en `transaction`).
- **Mientras haya recursos**: el fondo de iglesias debe tener ≥ 44 SLEARN.

> Nota: la elegibilidad se simplificó a `puntaje de perfil > 90` en lugar de
> exigir cada campo verificado por separado (el puntaje ya engloba nombre, país,
> email, WhatsApp/Telegram, ubicación, lugar de culto, GoodDollar y entrevista).

**Notificación:**
- Al verificador: el `PATCH /api/admin/church/[id]` y `PATCH /api/admin/user/[id]`
  devuelven el resultado del bonus (`{ bonus: { awarded, amount, hash } }`) y el
  modal de admin muestra un toast al otorgarse.
- Al pastor: se inserta un registro en la tabla `notifications` (R-#162 fase 1)
  y puede consultarse vía `GET /api/notifications`.

**Disparo automático:** el bonus se otorga automáticamente al verificarse los
datos (sin botón manual):
- `PATCH /api/admin/user/[id]` — tras verificar los datos del pastor.
- `PATCH /api/admin/church/[id]` — tras verificar el registro de la iglesia
  (`registration_verified = true`).
Ambos llaman `awardPastorBonus()` que valida la elegibilidad completa.

**Origen de fondos:**
- El bonus sale del **fondo de iglesias** (`SLEARN.churchesWallet`), que
  recibe el 5% de `processPayment` (`_distributeChurches`). NO del backend
  principal.
- El backend firma con `CHURCHES_WALLET_PRIVATE_KEY` (la llave del
  `churchesWallet`), no con `PRIVATE_KEY`.

**Ver el saldo del fondo (nuevo):**
- Endpoint `GET /api/churches/fund` que devuelve el saldo SLEARN (y USDT) del
  `churchesWallet`, para que un pastor sepa cuánto queda.

**Landing page para pastores (onboarding):**
- Páginas `/gdcluster/pastors` (EN) y `/redgd/pastores` (ES) con el componente
  `GdPastoresLanding`.
- Muestran: invitación al curso GD, requisitos (pastor + país piloto +
  puntaje > 90 + documento de registro + no-sionista), el bono de 44 SLEARN y
  el saldo del fondo de iglesias (SLEARN).
- Incluyen el **camino de onboarding** para un pastor nuevo: (1) curso
  Web3 & UBI para billetera y plataforma, (2) completar perfil + proponer
  entrevista (más de 90 puntos y 44 SLEARN automáticos al verificar los
  documentos), (3) reclamar UBI diario, (4) opcional crucigramas para ganar
  USDT/SLEARN, (5) curso GD pagable con SLEARN/USDT (si falta USDT en Sierra
  Leona → `stable-sl.pdJ.app`).
- Sección "por qué es importante el curso GD" sin revelar el contenido (se
  descubre al pagar).

**Requirements:**

1. **Get pastor wallet**: Query `billetera_usuario.billetera` for the pastor's
   wallet address.
2. **Validate eligibility**: pilot + complete profile + church registration
   verified + non-Zionist + not paid.
3. **Check fund balance**: leer `SLEARN.balanceOf(churchesWallet)` ≥ 44e2.
4. **Transfer SLEARN**: `SLEARN.transfer(pastorWallet, 44e2)` signed with
   `CHURCHES_WALLET_PRIVATE_KEY`.
5. **Wait for confirmation** + **Store tx hash** + **Handle errors**.

**Technical Details:**

- **Contract**: SLEARN (ERC-20, 2 decimals) on Celo
- **Amount**: 44 SLEARN (= 4400 in contract units, `44 * 10^2`)
- **Network**: Determined by `NEXT_PUBLIC_NETWORK` env var
- **Fondo de iglesias**: `NEXT_PUBLIC_CHURCHES_WALLET_ADDRESS` +
  `CHURCHES_WALLET_PRIVATE_KEY` (la llave del fondo, no la del backend)
- **Library**: `viem` (already in dependencies)

**Implementación real:** `packages/rewards/src/lib/pastor-bonus.ts` (motor `@learn-tg/rewards`, REQ/35 — `isEligiblePastor` +
`awardPastorBonus`), invocada desde `PATCH /api/admin/user/[id]` y
`PATCH /api/admin/church/[id]` al verificarse los datos.

**Edge Cases:**

- **Insufficient SLEARN balance**: Return error, log, do NOT record as paid
- **Network timeout**: Retry once, then fail with clear message
- **Pastor has no wallet**: Return error "pastor has no wallet address"
- **Already paid**: Check `transaction` table for existing bonus to avoid duplicates

**Dependencies:**

- `viem` (already installed)
- `lib/deployments.ts` (`getSlearnAddress`)
- `SLEARNAbi` de `@/abis/SLEARN.json`
- `@pasosdejesus/m/blockchain` for SLEARN_ADDRESSES
- `erc20Abi` from `viem` or hardcoded

- [x] Bonus awarded automatically when verification completes (no manual button)
- [x] Bonus only for pastors in pilot countries (Colombia / Sierra Leone)
- [x] Bonus only with complete verified profile (except GoodDollar)
- [x] Bonus only with profile score > 90 (`usuario.profilescore > 90`)
- [x] Bonus only with church registration verified (`registration_verified = true`)
- [x] Bonus only for non-Zionist pastors (`position_israel_gaza = 'no'`)
- [x] Bonus only while the churches fund has ≥ 44 SLEARN
- [x] Transaction hash is stored in `transaction` table
- [x] If transfer fails, error is returned (not silently swallowed)
- [x] Duplicate bonuses are prevented (check `transaction` table first)
- [x] Verifier is notified via toast when the bonus is awarded
- [x] Pastor is notified via in-app notification (`notifications` table, R-#162 phase 1)
- [x] Pastor can see the remaining churches fund balance (`GET /api/churches/fund` + landing page `/gdcluster/pastors` / `/redgd/pastores`)
- [x] Landing page shows requirements + onboarding path (Web3 & UBI → profile → UBI → crosswords → GD) + "why GD matters" without revealing content + `stable-sl.pdJ.app` hint
