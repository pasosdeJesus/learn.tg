# R-#212: F-#212 Transaction failure when paying for GD course with Brave browser

## Problem Description
During testing in the development environment (Sepolia), attempts to pay for the Global Disciples (GD) course using the Brave browser resulted in consistent transaction reverts.

**Symptoms:**
- Error message in browser console: `The contract function "transfer" reverted with the following reason: Error processing the transaction`.
- The transaction failed during the initial `transfer` from the student wallet to the backend wallet.
- The same transaction with the same wallet succeeded in Google Chrome using the OneKey extension.

## Investigation Findings
1. **Wallet Balance:** The student wallet had sufficient SLEARN (44.00) and CELO (3.52) for gas.
2. **Contract State:** A diagnostic script confirmed that:
   - The contract (`0x9fBa...`) was **not paused**.
   - The destination backend wallet (`0x01a7...`) was correctly **authorized** to receive SLEARN transfers.
   - The student balance was correctly recognized by the contract.
3. **Browser Interference:** Since the technical state of the blockchain and the wallets was correct, and the flow worked in Chrome, the issue is attributed to **Brave's browser environment**. Potential causes include:
   - Brave Shields interfering with the injected `window.ethereum` provider.
   - Discrepancies in how Brave handles transaction simulations via the RPC before sending.
   - Timing or race conditions in Brave's handling of asynchronous extension calls.

## Conclusion
The application's transaction logic, including manual nonce management and server-side auto-approval, is functionally sound. Users experiencing "Error processing the transaction" on Brave should be advised to disable Shields for the site or use a different supported browser like Chrome.
