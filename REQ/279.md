# R-#279: Fix the count of guides paid in USDT

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/279

**Type:** Bug fix (course progress / leaderboard)

## 1. Symptom

A Sierra Leone student (user 631) completed 12 guides. The course pages mark almost every guide
with the 💵 (USDT) badge and the leaderboard's "Paid USDT" column counts 11 guides, while his
USDT scholarship total is only **2.79** (3 guides). The other 8 were paid in SLEARN.

## 2. Cause

`guide_usuario.amountpaid` holds the amount of **whichever token was paid**:
`packages/rewards/src/routes/check-crossword.ts` stores the raw USDT amount (6 decimals, e.g.
`930000` = 0.93) when the vault paid USDT, and the raw SLEARN amount (2 decimals, e.g. `93` =
0.93) when it paid only SLEARN. The V5 vault pays USDT and SLEARN **independently** (partial
payments), so a guide paid only in SLEARN leaves `amountpaid > 0`.

Three readers treated `amountpaid > 0` as "paid in USDT":

| Reader | Effect |
|---|---|
| `app/api/guide-status/route.ts` (`receivedScholarship`) | the 💵 mark on the course and guide pages |
| `lib/leaderboard-queries.ts` (`guide_usdt`, R-#278) | the "Paid USDT" column and its Platform Score component |
| `packages/rewards/src/routes/scholarship.ts` (`paidGuides`, `percentagePaid`, `amountScholarship`) | the course statistics card |

R-#278 §3 had copied the wrong rule from `guide-status`; this requirement corrects it.

## 3. Rule (source of truth)

A guide is **paid in USDT** iff a `transaction` row exists with `type = 'scholarship'`,
`crypto = 'usdt'` and `metadata->>'guideId'` = the guide's `actividadpf_id` (and, for the course
card, `metadata->>'courseId'` = the course). Symmetrically for **SLEARN** (`crypto = 'slearn'`).
`guide_usuario.amountpaid` is no longer used to decide the token.

## 4. Implementation

| Where | Change |
|---|---|
| `app/api/guide-status/route.ts` | `receivedScholarship` / `receivedSlearnScholarship` come from one `transaction` query over both cryptos (no `amountpaid`) |
| `lib/leaderboard-queries.ts` | the `guide_usdt` count uses `EXISTS (… t2.crypto = 'usdt' …)`, symmetric to the existing SLEARN count |
| `packages/rewards/src/routes/scholarship.ts` | `paidGuides` = the course's USDT transaction count, `percentagePaid` from it, and `amountScholarship` = the USDT transaction sum (instead of `SUM(amountpaid)`, which mixed units) |

## 5. Acceptance criteria

- [x] A guide whose `amountpaid > 0` but whose only scholarship `transaction` is SLEARN shows
      **no** 💵 and is **not** counted in `guide_usdt`.
- [x] A guide with a USDT scholarship `transaction` shows 💵 and counts in `guide_usdt`.
- [x] The course card's "Paid USDT" progress and its total scholarship match the USDT
      `transaction` rows.
- [x] An opted-out, region type 2 or not-completed user behaves as before (no new exposure).
- [x] `make type` and the affected suites green; `bin/audit-api-auth.mjs` at 0 failed;
      `node audit-crushrules.mjs` at 0 findings.

## 6. Testing

- `app/api/guide-status/__tests__/route.spec.ts`: a completed guide with a USDT transaction
  reports `receivedScholarship: true`; a completed guide with only a SLEARN transaction reports
  `receivedScholarship: false, receivedSlearnScholarship: true` (the exact bug).
- `lib/__tests__/leaderboard-queries.privacy.test.ts`: the `guide_usdt` SQL uses the `usdt`
  transaction predicate.
- `make test-engines` (the `@learn-tg/rewards` engine).

## 7. Out of scope

- Redefining or persisting `guide_usuario.amountpaid` (it keeps its dual meaning, documented in
  `ARCHITECTURE.md`).
- The vault paying SLEARN without USDT (partial payments) is V5's expected behavior; this
  requirement only fixes how the payment is **reported**.
