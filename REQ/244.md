## 4. Commands that actually work in this repo

The two new packages each ship their own `vitest.config.ts` (a plain object with
an alias map onto `apps/nextjs/node_modules`), which is exactly what `rewards`
and `gdcluster` still lack. Run them from the app, which owns the dependency
graph:

```bash
cd apps/nextjs

# Core wallet — verified 2026-09-15: 25 passed, 0 skipped, ~11 s
# (run `pnpm install` in packages/pdj-wallet once: Node needs viem there)
./node_modules/.bin/vitest run --root ../../packages/pdj-wallet \
  --config ../../packages/pdj-wallet/vitest.config.ts

# Next.js package — verified 2026-09-15: 15 passed, 7.5 s
./node_modules/.bin/vitest run --root ../../packages/pdj-wallet-next \
  --config ../../packages/pdj-wallet-next/vitest.config.ts

# learn.tg integration tests
make test-hooks test-components

# Full unit suite
make test

# Minimal E2E (see R-#245 §5)
CHROME_PATH=/usr/local/bin/chrome make test-e2e-spec SPEC=in-app-wallet
```

Fixed and measured on 2026-09-15 (branch `mvppwa`):

- Aliases for both linked packages were added to `apps/nextjs/vitest.config.ts`
  (`@learn-tg/pdj-wallet-next` first, then `@learn-tg/pdj-wallet`, which must
  stay in that order because Vite matches aliases by prefix), so the app suite
  resolves the linked package again: `make test-hooks` is **74 passed /
  2 skipped in 44 s** (it was 1 failed suite).
- The `useAuthAddress` mocks in `lib/hooks/__tests__/useGuideData.test.ts` now

  `tsc --noEmit -p tsconfig.test.json` is clean.

- The E2E suites run against the **dev site**, which has served this branch

## 5. Demo flow (acceptance)

Runnable now: the branch is deployed to the dev site and the wallet half of the
flow was exercised there on 2026-09-15 (`in-app-wallet` spec: create, unlock,
SIWE, session cookie, `/api/profile`). Steps 2-3 were also confirmed by the
operator on Android/Chrome (R-#243). Steps 8-9 (offline reload) still need a
**production build**, because `next dev` forces `NetworkOnly`.

1. Open `https://learn.tg:9001` in Chrome mobile.
2. Install the PWA (Add to Home Screen).
3. Open the PWA.
4. Tap "Use in-app wallet".
5. Create a wallet with a PIN.
6. Sign in via SIWE (in-app wallet).
7. Navigate to `/en/gdcluster/guide1`.
8. Turn off Wi-Fi and mobile data.
9. Reload: guide 1 is still visible.
10. Turn the connection back on.

## 7. Risks

- **`next-pwa` with the Next.js 16 App Router**: it generates the worker fine, but
  its **auto-registration does not work** in the App Router (it injects
  `register.js` into the webpack `main.js` entry, which does not exist there, and
  the injection is skipped silently). Confirmed on the dev site 2026-09-15:
  `/sw.js` 200, `getRegistrations()` empty, no registration code in any client
  chunk, while a manual `register('/sw.js')` worked. Mitigation applied:
  `components/ServiceWorkerRegistrar.tsx` registers it from the app (verified in
  Chrome: 1 registration, activated, controlled). `serwist` remains the
  alternative (R-#242) if next-pwa breaks with a future Next version.
- **Manifest collision**: `public/manifest.json` is diligent-records'
  (`start_url` `/en/diligent-records`, linked only from
  `app/[lang]/diligent-records/page.tsx:83-86`). Mitigation: learn.tg now has
  `public/manifest.webmanifest` linked from the root layout; the diligent one is
  untouched.
- **The service worker caches API GET responses for 1 h** (R-#240 §2). They are
  wallet-scoped URLs, but the data stays in the device cache; review before
  production (R-#243) and consider `NetworkOnly` for the sensitive endpoints.
- **~~The app test suite cannot resolve the linked package~~** — fixed: the
  `@learn-tg/pdj-wallet*` aliases are in `apps/nextjs/vitest.config.ts` and the
  `useGuideData` mocks carry the new fields (§4, §10).
- **IndexedDB unavailable** in some browsers. Mitigation: fall back to
  `MemoryStorage` (non-persistent) / the in-memory queue of the offline modules.
- **Wallet creation slow on low-end devices**: PBKDF2 runs 600,000 iterations.
  Mitigation applied: the dialog and the test page keep a `busy` state and
  disable their buttons (the create button shows `...`) while the key is derived.
- **~~`fake-indexeddb` is not installed~~** — fixed 2026-09-15: `pnpm install` in
  `packages/pdj-wallet` installs its declared devDependencies, so the
  `IndexedDBStorage` test runs (the core suite is 25 passed / 0 skipped).
