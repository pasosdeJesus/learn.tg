#### 1. Objective

Deliver a minimum viable PWA with an in-app wallet, working on the dev site. This is a subset of R-#236 to R-#243, focused on the demo.

#### 2. Scope (MVP)

**Included (from R-#236):**

- `createWallet`, `importWallet`, `unlockWallet`, `lockWallet`, `deleteWallet`, `hasWallet`, `getWalletInfo`.
- `signMessage`, `signSIWE`.
- `IndexedDBStorage`, `MemoryStorage`.
- `getInAppWalletProvider` (EIP-1193).

**Included (from R-#237):**

- `useInAppWallet`, `InAppWalletSetup`, `InAppWalletUnlock`.

**Included (from R-#238):**

- `WalletSelector` in learn.tg.
- `useAuthAddress` extended.
- `usePublicClient`, `useWalletClient`, `useWriteContract` extended.
- `Header` updated.

**Included (from R-#240):**

- `next-pwa` active.
- `public/manifest.json` for learn.tg.
- `app/offline/page.tsx`.
- `OfflineBanner`.

**Excluded (post-MVP):**

- `signTransaction`, `signTypedData`, `exportMnemonic`, `exportPrivateKey`.
- `FileStorage`.
- Offline queue (R-#242).
- Offline progress sync (R-#241).
- Install prompt (R-#243).
- Full E2E migration (R-#239).

#### 3. Demo flow

1. Open `https://learn.tg:9001` in Chrome mobile.
2. Install PWA (Add to Home Screen).
3. Open PWA.
4. Tap "Use in-app wallet".
5. Create wallet with PIN.
6. Sign in via SIWE (in-app).
7. Navigate to `/en/gdcluster/guide1`.
8. Turn off Wi-Fi and mobile data.
9. Reload: guide 1 still visible.
10. Turn on connection.

#### 4. Acceptance criteria

- [ ] PWA installs on Chrome mobile.
- [ ] User can create an in-app wallet.
- [ ] User can sign in via SIWE with the in-app wallet.
- [ ] Guide 1 is readable offline.
- [ ] `pnpm test` passes.
- [ ] `pnpm typecheck` passes.
- [ ] Demo works on `https://learn.tg:9001`.

#### 5. Risks

- `next-pwa` may not work with Next.js 16. Mitigation: fallback to `serwist` in R-#242.
- IndexedDB may not work in some browsers. Mitigation: fallback to `MemoryStorage` (non-persistent).
- In-app wallet creation may be slow on low-end devices. Mitigation: show progress.
