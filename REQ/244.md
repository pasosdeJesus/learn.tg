## 1. Objective

Deliver a minimum viable PWA with an in-app wallet, working on the dev site
(`https://learn.tg:9001`). This is a subset of R-#236 to R-#243, focused on a
demonstrable end-to-end flow.

## 2. Scope (MVP)

**Included, from R-#236 (core package):**

- `createWallet`, `importWallet`, `unlockWallet`, `lockWallet`, `deleteWallet`,
  `hasWallet`, `getWalletInfo`.
- `signMessage`, `signSIWE`.
- `IndexedDBStorage`, `MemoryStorage`.
- `getInAppWalletProvider` (EIP-1193).

**Included, from R-#237 (Next package):**

- `useInAppWallet`, `InAppWalletSetup`, `InAppWalletUnlock`.

**Included, from R-#238 (learn.tg integration):**

- `WalletSelector` in learn.tg.
- `useAuthAddress` extended.
- `usePublicClient` / `useWalletClient` (`lib/hooks/useWallet.ts`) and
  `useWriteContract` (`lib/hooks/useWriteContract.ts`) extended.
- `Header` updated.

**Included, from R-#240 (service worker):**

- `next-pwa` enabled for learn.tg. It is **already** a dependency
  (`next-pwa@^5.6.0`) and already configured in `next.config.ts`, but currently
  with `disable: true` and a cache limited to `diligent-records`.
- A learn.tg `manifest.json` linked from the root layout: today
  `public/manifest.json` describes **diligent-records** (`start_url`
  `/en/diligent-records`) and is linked only from that page, so learn.tg is not
  installable as itself (see R-#240 §2).
- `app/offline/page.tsx` (does not exist yet).
- `OfflineBanner`.

**Excluded (post-MVP):**

- `signTransaction`, `signTypedData`, `exportMnemonic`, `exportPrivateKey`.
- `FileStorage`.
- Offline submission queue (R-#242).
- Offline progress sync (R-#241).
- Install prompt and documentation (R-#243).
- Full E2E migration to the wallet core (R-#239).

## 4. Commands that actually work in this repo

Engine packages (`packages/*`) have **no `vitest.config.ts`** today and their
`package.json` `test` script points to a file that does not exist, so `pnpm test`
inside a package fails (corepack also resolves pnpm 11 here, which the repo does
not support — it is pinned to pnpm 10). Use the app's config:

```bash
# Unit tests of a package (run from the app, which owns the dependency graph)
cd apps/nextjs && ./node_modules/.bin/vitest run \
  --root ../../packages/pdj-wallet \
  --config "$(pwd)/vitest.config.ts"

# learn.tg integration tests
cd apps/nextjs && make test-hooks test-components

# Full unit suite
cd apps/nextjs && make test

# Minimal E2E (once the spec exists, see R-#245)
cd apps/nextjs && CHROME_PATH=/usr/local/bin/chrome make test-e2e-spec SPEC=in-app-wallet
```

If the new packages want their own `pnpm test`, add a `vitest.config.ts` that
extends `../../apps/nextjs/vitest.config.ts` (the `rewards` and `gdcluster`
packages are pending that same fix).

## 5. Demo flow (acceptance)

1. Open `https://learn.tg:9001` in Chrome mobile.
2. Install the PWA (Add to Home Screen).
3. Open the PWA.
4. Tap "Use in-app wallet".
5. Create a wallet with a PIN.
6. Sign in via SIWE (in-app wallet).
7. Navigate to `/en/gdcluster/guide1`.
8. Turn off Wi-Fi and mobile data.
9. Reload: guide 1 is still visible.
10. Turn the connection back on.

## 6. Acceptance criteria

- [ ] The PWA installs on Chrome mobile.
- [ ] The user can create an in-app wallet.
- [ ] The user can sign in via SIWE with the in-app wallet.
- [ ] Guide 1 is readable offline.
- [ ] `make test` passes.
- [ ] `pnpm typecheck` passes.
- [ ] The demo works on `https://learn.tg:9001`.

## 7. Risks

- **`next-pwa` with the Next.js 16 App Router**: it is installed and configured
  but disabled; enabling it may fail to generate the service worker. Mitigation:
  evaluate `serwist` in R-#242.
- **Manifest collision**: `public/manifest.json` is diligent-records'.
  Mitigation: give learn.tg its own manifest (e.g. `public/manifest.webmanifest`)
  linked from the root layout and leave the diligent one untouched.
- **IndexedDB unavailable** in some browsers. Mitigation: fall back to
  `MemoryStorage` (non-persistent).
- **Wallet creation slow on low-end devices**. Mitigation: show progress.
