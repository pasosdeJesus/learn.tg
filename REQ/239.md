**Created:** 2026-09-15

### 1. Objective

Replace the `setupSIWEMock` helper (exported by `@pasosdejesus/m/e2e`, which
mocks `window.ethereum` in the page) with the real `@learn-tg/pdj-wallet` core
running in Node.js. This makes the E2E tests more robust and closer to real
behaviour.

Verified state of the E2E helpers (2026-09-15):

- `e2e/helpers/e2e-auth.mjs` (`setupE2EAuth`) is the other wallet helper (13 files
  import it); it also signs with `viem` directly and is a candidate for the same
  migration later.
- `@pasosdejesus/m/e2e` still exports both `simulateSIWE` and `setupSIWEMock`, but
  **no spec here imports them any more**: the 5 specs that used `setupSIWEMock`
  (`connect-wallet-flow`, `diag-session`, `full-flow`, `prod-landing-to-profile`,
  `town-autocomplete`) now sign with the core. `simulateSIWE` was never used.
- `e2e/helpers/siwe-wallet-mock.mjs` (a local copy of `setupSIWEMock`) was dead
  code: **deleted**.
- `e2e/helpers/siwe-auth.mjs` was deleted in R-#233 Phase 2, when the API token
  was removed.

**Prerequisite discovered while implementing it:** the core could not be imported
from Node at all: `dist/` had extensionless relative imports and the package had
no `node_modules`, so `viem` was not resolvable from `packages/pdj-wallet`. Fixed
by building with `module`/`moduleResolution: nodenext` (explicit `.js`
extensions) and adding `pnpm install` to the package (R-#236 §2).

### 2. Changes

**New helper `e2e/helpers/in-app-wallet.mjs`:** ✅ implemented. It uses the real
core and, for the key, `FileStorage` (Node.js) instead of `MemoryStorage`:

```javascript
import { createTestWallet, importTestWallet, unlockTestWallet,
         deleteTestWallet, signSIWEForTest } from '../helpers/in-app-wallet.mjs'

// Fresh wallet (mnemonic) or the one in apps/.env:
const wallet = await createTestWallet()                     // { address, mnemonic, privateKey, path }
const envWallet = await importTestWallet(process.env.TEST_PRIVATE_KEY)

// The whole SIWE, in Node:
await installCoreWalletMock(page, { privateKey, address, chainId })  // before page.goto
await page.goto(base)
await signInWithCoreWallet(page, { privateKey, address, chainId, baseUrl: base })
```

How it works: `installCoreWalletMock` exposes a thin EIP-1193 shim in the page
(`eth_accounts`, `eth_chainId`, balances, receipts) whose `personal_sign` is
bridged to Node with `page.exposeFunction('__pdjWalletSign', …)` and signed by
`signSIWE` of the core. `signInWithCoreWallet` skips the UI: it reads the CSRF
token, builds the SIWE message (checksummed address, as `siwe` demands), signs it
with the core and POSTs `/api/auth/callback/credentials` from inside the page so
the NextAuth session cookie lands in the browser jar.

`waitForExternalConnect(page)` is the companion for specs written against the old
header: R-#238 replaced `ConnectWalletButton` with `WalletSelector`, so the
external wallet lives behind “Use external wallet”; the helper clicks it until
the “Connect Wallet” button shows up.

**Migrate the specs that use `setupSIWEMock`** (the real list):

- `connect-wallet-flow.spec.mjs`
- `diag-session.spec.mjs`
- `full-flow.spec.mjs`
- `prod-landing-to-profile.spec.mjs`
- `town-autocomplete.spec.mjs`

**In each spec** (what the migration actually did):

1. `await installCoreWalletMock(page, { privateKey: pk, address: addr, chainId })`
   before `page.goto` (replaces `setupSIWEMock(page, addr, pk, chainId)`).
2. The page's wallet calls sign through the core (Node), so SIWE is real.
3. Specs that need the session before touching the UI call
   `signInWithCoreWallet`; the rest click the header as a user would, after
   `waitForExternalConnect` switched the header to the external wallet.
4. `setupSIWEMock` / `simulateSIWE` are no longer imported anywhere.
