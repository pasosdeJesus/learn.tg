
# R-#226: Ranking of students of gdcluster per cluster and capabilities as program director

**Created:** 2026-09-07
**Status:** Propuesta
**Type:** Feature
**Priority:** Medium
**Dependencies:** #161 (GD course), #163 (Referral program), #220 (Cluster formation), #155 (Cluster/Country Funds), #35 (gdcluster engine)

---

## 1. Objective

Create a **ranking system** for students of the GD course (`gdcluster`) that evaluates their performance and capabilities to serve as **program directors** for their clusters. The ranking will be used to:

1. **Identify potential program directors** within each cluster
2. **Evaluate candidates** for the program director role
3. **Track progress** of students in the GD course
4. **Provide transparency** to cluster leaders and pdJ

---

## 2. Ranking Criteria

### 2.1 Performance Areas

| Area | Weight | Description |
|------|--------|-------------|
| **GD Course Completion** | 20% | Completion of all guides and crossword puzzles |
| **Referral Program Performance** | 20% | Number and quality of referrals (pastors and church members) |
| **Cluster Formation** | 15% | Participation in cluster formation (invitations, acceptances) |
| **Self-Assessment** | 15% | Scores from the ministry self-assessment test (R-#226) |
| **Community Attestation** | 15% | Scores from community attestation (R-#226) |
| **Leadership Experience** | 15% | Proven leadership in church or community |

### 2.2 Scoring System

| Level | Score | Description |
|-------|-------|-------------|
| **Excellent** | 85-100 | Strong in all areas, ready for program director role |
| **Good** | 70-84 | Strong in most areas, potential for program director |
| **Satisfactory** | 55-69 | Competent, needs development in some areas |
| **Needs Improvement** | 40-54 | Needs significant development |
| **Low** | 0-39 | Not ready for program director role |

## 4. Ranking Calculation

### 4.1 Formula

```
Total Score = (GD Course × 0.20) + (Referral Program × 0.20) + (Cluster Formation × 0.15) + (Self-Assessment × 0.15) + (Community Attestation × 0.15) + (Leadership Experience × 0.15)
```

### 4.2 Normalization

Each component is normalized to a 0-100 scale before weighting:

```
Normalized Score = (Raw Score / Max Score) × 100
```

### 4.3 Example

| Component | Raw Score | Max Score | Normalized | Weight | Weighted Score |
|-----------|-----------|-----------|------------|--------|----------------|
| GD Course | 22 | 25 | 88 | 0.20 | 17.6 |
| Referral Program | 18 | 25 | 72 | 0.20 | 14.4 |
| Cluster Formation | 20 | 25 | 80 | 0.15 | 12.0 |
| Self-Assessment | 32 | 40 | 80 | 0.15 | 12.0 |
| Community Attestation | 28 | 40 | 70 | 0.15 | 10.5 |
| Leadership Experience | 14 | 20 | 70 | 0.15 | 10.5 |
| **Total** | — | — | — | — | **77.0** |

## 6. Database Schema

### 6.1 New Table: `student_ranking`

```sql
CREATE TABLE student_ranking (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER REFERENCES usuario(id) NOT NULL,
    cluster_id INTEGER REFERENCES clustergd(id),
    gd_course_score INTEGER DEFAULT 0,      -- 0-100
    referral_score INTEGER DEFAULT 0,       -- 0-100
    cluster_score INTEGER DEFAULT 0,        -- 0-100
    self_assessment_score INTEGER DEFAULT 0, -- 0-100
    community_attestation_score INTEGER DEFAULT 0, -- 0-100
    leadership_score INTEGER DEFAULT 0,      -- 0-100
    total_score INTEGER DEFAULT 0,          -- 0-100
    level VARCHAR(20),                      -- excellent, good, satisfactory, needs_improvement, low
    calculated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(usuario_id, cluster_id)
);
```

### 6.2 New Table: `community_attestation`

```sql
CREATE TABLE community_attestation (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER REFERENCES usuario(id) NOT NULL,  -- The candidate being evaluated
    evaluator_id INTEGER REFERENCES usuario(id) NOT NULL, -- The person evaluating
    teaching_score INTEGER DEFAULT 0,        -- 0-10
    missionary_score INTEGER DEFAULT 0,      -- 0-10
    business_score INTEGER DEFAULT 0,        -- 0-10
    leadership_score INTEGER DEFAULT 0,      -- 0-10
    comments TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(usuario_id, evaluator_id)
);
```

### 6.3 New Table: `self_assessment`

```sql
CREATE TABLE self_assessment (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER REFERENCES usuario(id) NOT NULL,
    teaching_score INTEGER DEFAULT 0,        -- 0-10
    missionary_score INTEGER DEFAULT 0,      -- 0-10
    business_score INTEGER DEFAULT 0,        -- 0-10
    leadership_score INTEGER DEFAULT 0,      -- 0-10
    total_score INTEGER DEFAULT 0,           -- 0-40
    completed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(usuario_id)
);
```

## 8. Acceptance Criteria

### Ranking System
- [ ] Ranking is calculated based on six components (GD course, referrals, cluster, self-assessment, community attestation, leadership)
- [ ] Ranking is displayed per cluster and per country
- [ ] Ranking shows the "Ready" level (Excellent, Good, etc.)
- [ ] Ranking is updated automatically when components change
- [ ] Ranking is visible to cluster leaders and pdJ admins

### Self-Assessment
- [ ] Self-assessment test is available to students
- [ ] Self-assessment covers four areas: teaching, missionary, business, leadership
- [ ] Self-assessment scores are stored in the database
- [ ] Self-assessment can be updated by the student

### Community Attestation
- [ ] Community members can submit attestations for candidates
- [ ] Attestation covers the same four areas as self-assessment
- [ ] Attestation scores are stored in the database
- [ ] Attestation is used in the ranking calculation

### Integration
- [ ] Ranking integrates with GD course completion data
- [ ] Ranking integrates with referral program data
- [ ] Ranking integrates with cluster formation data
- [ ] Ranking is displayed in the cluster page (`/[lang]/cluster/[id]`)
- [ ] Ranking is displayed in the admin dashboard

---

## 9. Out of Scope

- Automated email notifications for ranking changes
- Public ranking (visible to all users)
- Ranking competition between clusters
- Historical ranking data (beyond current)
