# R-#211: F-#211 React state update warning during rendering in ConnectWalletButton

## Problem Description
During development, the server and browser consoles frequently log the following React warning:
`Cannot update a component (DebugConsole) while rendering a different component (ConnectWalletButton).`

This occurs because `ConnectWalletButton` triggers a state update during its render phase, which violates React's rendering lifecycle rules.

## Technical Context
The `ConnectWalletButton` component, or its interaction with parent components like `DebugConsole`, performs side-effect state updates (e.g., calling `setLoading` or similar) directly or indirectly while React is in the middle of calculating the UI tree.

## Impact
While the application remains functional, this behavior causes:
- Potential UI "flickering" or inconsistent component states.
- Unnecessary re-renders.
- Unpredictable behavior in future React versions (e.g., Concurrent Mode).

## Suggested Solutions

1. **Verify State Updates:** Identify all `useState` setters within `ConnectWalletButton` and ensure they are *never* called directly in the function body.
2. **Use Effects Correctly:** Ensure all side effects (fetching data, wallet status checks) that result in state updates are wrapped in `useEffect` hooks with correct dependency arrays.
3. **Event-Driven Updates:** Ensure state updates related to UI interactions (like clicking the connect button) are purely event-driven (`onClick`, etc.).
4. **Context/Parent Decoupling:** Investigate if the parent `DebugConsole` (or similar) is causing a re-render cycle due to prop drilling or shared context updates that occur too early in the lifecycle.
