## 1. Objective

Give every learner control over **what the platform publishes about their course
completions**, with two separate switches, and let them **revoke a credential (SBT)**
they no longer want to hold:

1. **Courses in general** — the learner decides whether their course completions are
   shown publicly at all.
2. **Christian-related courses** — a second, independent switch, whose **initial state
   follows the learner's country** (off where Christians are persecuted, on elsewhere,
   §3.1), that only has effect when the first one is on. Christian content is the one that
   exposes a person in a persecution context, so the safe state is the one the country
   determines: off where declaring that faith is dangerous, on where it is not.
3. **SBT issuance follows those switches**: a credential for a Christian-related
   course is **not minted** while the learner keeps that visibility off, because an
   on-chain token is public, permanent and enumerable from the wallet. The learner can
   enable the switch later and mint then, for the courses already completed.
4. **Self-revocation**: from the same settings page, a learner can revoke any SBT they
   earned, and it stops being published (and stops counting in the leaderboard).

A pseudonymous display name (`usuario.nusuario`, the only name the public profile
shows) makes opting in reasonable for some users in risky countries, but it is **not**
sufficient on its own: the wallet address is public and linkable, and a minted SBT is
permanent evidence in the chain. That is why the safe default is not to mint.

## 3. Design

### 3.1 User settings (new columns on `usuario`)

| Column | Type | Default | Meaning |
|---|---|---|---|
| `mostrar_cursos_publico` | `BOOLEAN` | `TRUE` | Publish my course completions. `TRUE` preserves today's behaviour; a learner opts **out**. |
| `mostrar_cursos_cristianos_publico` | `BOOLEAN` (tri-state) | depends on the country | **Additional** permission to publish completions of Christian-related courses. It only counts when `mostrar_cursos_publico` is also true (explicit AND), and it is the switch that authorises minting (4.4). |

The two flags are independent in the UI (two checkboxes, the second disabled while the
first is off) but **AND** in the decision, so no combination can publish Christian
completions without the general permission.

**Initial state depends on the country** (operator decision, 2026-09-23): in a country
whose government persecutes Christians the switch starts **off**; anywhere else it
starts **on** (there the prudent default protects nobody and only hides the course from
someone who could publish it). Implementation (migrations `20260923150546` for the column
and the trigger, `20260923152923` for the country list, `20260923155642` for the
undecided accounts and the automatic recompute):

- `msip_pais.persigue_cristianos BOOLEAN NOT NULL DEFAULT FALSE` marks those countries
  and `msip_pais.clasificado_cristianos BOOLEAN NOT NULL DEFAULT FALSE` says whether the
  country has been judged at all. **The trigger only acts on classified countries**, so
  an incomplete list can never publish someone from a persecuting country: while a
  country is unclassified the switch stays `NULL` = do not publish. The country list
  lives in its own migration, which the operator maintains;
- `usuario.mostrar_cursos_cristianos_publico` becomes **tri-state**: `NULL` = the learner
  never decided. Every R-#259 rule reads `NULL` as "do not publish" (`=== true`), the
  conservative default, so a learner with no country yet is safe;
- a `BEFORE INSERT` / `BEFORE UPDATE OF pais_id` trigger materialises the country-based
  value when the country is known (at signup it usually is not, so the value is set when
  the profile gets the country). **The country rules**: every time `pais_id` changes the
  trigger recomputes the switch with the new country (off in a persecuting country, on
  elsewhere); the learner can then change it by hand in `/[lang]/settings` and that value
  stays while the country does not change (the trigger ignores an update that brings the
  same `pais_id`);
- **verified against the dev DB and completed** (migration `20260923155642`, 2026-09-23):
  the trigger used to leave any non-`NULL` value alone, so (a) the 510 accounts without a
  country kept the old `false` default and never received their country's initial state
  when the country was set (Colombia stayed "do not publish"), and (b) an account
  materialised to `true` in a non-persecuting country kept publishing after moving to a
  persecuting one (Colombia → North Korea stayed `true`). The new migration sets those
  undecided no-country accounts back to `NULL` and the trigger now **recomputes with the
  new country whenever the country changes** (operator decision, 2026-09-23): a change to
  a persecuting country turns the switch off and a change to a non-persecuting one turns
  it on, even over a previous choice. Afterwards the learner can change it by hand and
  that value stays — the trigger does nothing when `pais_id` arrives with the same value,
  so saving the profile never overwrites a manual decision. Both cases were reproduced and
  re-checked in a `ROLLBACK`ed transaction (no country → Colombia `true`; → North Korea
  `false`; manual `true`; same country again `true`; → Colombia `true`), and the settings
  page states the country's reason (`defaultOn`/`defaultOff`);
- `GET /api/settings` returns `persecutionCountry` and `country` so the page can explain
  why the switch starts the way it does (it does not decide anything by itself).

### 3.2 Course classification (`cor1440_gen_proyectofinanciero.contenido_cristiano`)

- New column `contenido_cristiano BOOLEAN NOT NULL DEFAULT FALSE` plus an index.
- A migration marks the existing Christian courses by `prefijoRuta` (the list in §2),
  and `scripts/create-course.sh` + `doc/how-to-create-a-course.md` gain a required
  parameter so a new course declares its nature instead of inheriting `FALSE` silently.
- The flag is data, not logic: it is the only thing the visibility and minting rules
  consult (never the course title or a hardcoded id list).

### 3.3 Public surfaces that must honour the flags

| Surface | Change |
|---|---|
| `GET /api/user/[id]` | Filter the credentials by the owner's flags: `innerJoin` the course and drop rows whose course is `contenido_cristiano` unless the owner enabled both flags; drop **all** rows when `mostrar_cursos_publico` is false. The response must not include the hidden count. |
| `/[lang]/user/[id]` (page) | Renders what the API returns; add copy for the empty state ("this user has not published their completions") without revealing whether anything is hidden. |
| Leaderboard (`lib/leaderboard-queries.ts`) | `sbt_count` counts only publicly visible credentials (same predicate). `includeReligion`/`religion_nombre` must never be enabled on a public route; `usuario.religion_id`, `church_relationship`, `denomination`, `position_israel_gaza`, `church_id` and `place_of_worship*` must not appear in any public response (review `PUBLIC_ENDPOINTS`/advisories in `bin/audit-api-auth.mjs`). |
| `GET /api/crossword` / `/api/credential/[tokenId]` / `/api/transparency` | Review: the credential metadata endpoint is public by design (token metadata must not confirm who holds it); the transparency aggregates are per country, never per user. |
| `GET /api/credential/wallet/[wallet]` (`packages/rewards/src/routes/credential.ts`) | **Found while auditing**: it is public, keyed by wallet and lists the SBTs (plus `premiumSbtCount`), so it leaked the affiliation to anyone who knew the address. Now it applies the same predicate: no query at all when publishing is off (answers `404` when there is no donation either), and the premium count is filtered too. |
| Credential emission on-chain | See 4.4. |
| Local stores | The offline stores stay local, but they must be cleaned when the wallet is disconnected or deleted, as R-#256 requires for paid content; a shared phone must not keep a readable list of Christian courses after the user signs out. |

### 3.4 SBT issuance follows the setting

- `mintCourseCredential` is called only when the learner **may hold a public token** for
  that course: free/technical courses as today; a `contenido_cristiano` course only when
  `mostrar_cursos_publico AND mostrar_cursos_cristianos_publico` are true at the moment
  of the mint (the check runs server-side, in the engine, with the learner's session).
- When the switch is off, the completion is still recorded off-chain in
  `guide_usuario`/progress (so the guide, the score and the scholarship are unaffected);
  only the on-chain mint is skipped. `credential_emission` is **not** written (there is
  nothing on-chain to cache).
- **Late opt-in**: turning on the Christian switch offers to mint the credentials for the
  courses already completed (idempotent: the existing unique constraint plus the
  on-chain `hasCredentialOnChain` check). `POST /api/credentials/mint-missing`
  (authenticated) walks the courses completed at 100% with no emission and mints those
  the privacy rule allows, reporting the rest as `skipped: [{courseId, reason}]`.
  Turning it **off** does not burn anything by itself; it stops publishing and offers
  revocation (3.5).
- The learner-facing copy must say plainly that a credential is public and permanent,
  and that enabling the switch publishes the past completions too.

### 3.5 Self-revocation of SBTs

- **Settings UI**: the learner's own credentials (from `credential_emission` joined to
  courses), each with a "revoke" action behind an explicit confirmation that states the
  consequences (it stops being published, it leaves the leaderboard, and it cannot be
  re-issued automatically). Revoked rows stay visible to their owner, marked revoked.
- **Route**: `POST /api/credentials/revoke` — `authenticateUser` (session cookie), body
  `{ tokenId }`; the route resolves the `credential_emission` row **of that user** (never
  a tokenId supplied by the client alone) and calls
  `revokeCredential(userAddress, tokenId, amount)` through the backend wallet (the
  learner does not need gas; the session plus the explicit confirmation is the
  authorisation). It is **not** public: it must appear as authenticated in
  `bin/audit-api-auth.mjs`.
- **Confirm first**: whether the deployed `PasosDeJesusCredentials` allows the backend
  (MINTER_ROLE) to call `revokeCredential` or reserves it for `DEFAULT_ADMIN_ROLE`. If it
  is admin-only, the route enqueues a request and the operator executes it with
  `bin/m credentials:revoke-credential` (documented as the fallback, never a silent
  no-op). This verification is step 1 of the work, not an assumption.
  **Confirmed (2026-09-22)**: `revokeCredential` is `external onlyRole(MINTER_ROLE)
  whenNotPaused`, and the backend wallet (`PRIVATE_KEY`) already holds `MINTER_ROLE`, so
  the route burns directly; the operator fallback with `bin/m credentials:revoke-credential`
  stays documented for a paused contract or a role change.
- **Database**: `credential_emission` gains `revoked_at TIMESTAMPTZ` and
  `revoke_hash VARCHAR(66)`. Every public surface (3.3) excludes revoked rows; the
  leaderboard `sbt_count` too. The learner's own history keeps them for auditability.
- **Re-mint after a mistake**: allowed on request (the mint path is idempotent), with a
  note in the UI; it is a new emission row for the same (user, course).

### 3.6 The settings page

- New route `/[lang]/settings` (bilingual copy, en/es), linked from the header menu next
  to the profile. It holds: the two privacy switches, the list of own credentials with
  the revoke action, and a short explanation of the risk (a sentence about persecution
  contexts and about the wallet being public).
- **Decided**: a separate page (`app/[lang]/settings/page.tsx`), cleaner for a control
  that must be findable than a new section of an already crowded profile page.
  `PATCH /api/settings` saves the two flags (not `/api/profile`, which keeps personal
  data); `GET /api/settings` returns them plus the owner's credentials, the owner's
  `country` and whether it persecutes Christians (`persecutionCountry`), which the page
  uses for a `defaultOn`/`defaultOff` note under the Christian switch
  (`data-testid="christian-default-note"`) so the initial state does not look like a
  decision the learner already made.
- i18n keys in both languages; no PII and no affiliation in the event logs
  (`userevent` must not record which course was hidden).

## 4. Acceptance criteria

- [x] A learner can turn course-completion visibility off and the public profile
      (`GET /api/user/[id]` and `/[lang]/user/[id]`) stops listing their credentials,
      without revealing that anything is hidden.
- [x] With the general switch on and the Christian switch off, Christian-related course
      completions are **not** listed publicly, while the others are.
- [x] Christian-related completions never become public unless both switches are on
      (the AND is enforced server-side, not only in the UI; where Christians are
      persecuted the second switch starts off).
- [x] The Christian switch starts with the country's state: off in the 29 persecuting
      countries and on elsewhere; an account with no country stays undecided (`NULL` = do
      not publish) and takes its country's state when the country is set; **a country change
      recomputes the switch automatically** (a move to a persecuting country turns it off)
      and the learner can change it by hand afterwards, that value staying until the country
      changes again; the settings page explains why it starts on or off (migrations
      `20260923150546`, `20260923152923`, `20260923155642`).
- [x] No SBT is minted for a Christian-related course while the Christian switch is off;
      the guide, the score and the scholarship still work; the completion mints when the
      learner enables the switch (idempotent for already-minted ones).
- [x] The leaderboard `sbt_count` counts only the credentials the learner publishes, and
      no public response exposes `religion_id`, `church_relationship`, `denomination`,
      `position_israel_gaza` or church location.
- [x] A learner can revoke an SBT they hold; the revocation is executed on-chain (or
      enqueued for the operator if the contract restricts it, with the reason shown) and
      recorded in `credential_emission.revoked_at`/`revoke_hash`; the revoked credential
      disappears from the public profile and the leaderboard and stays visible to its
      owner as revoked.
- [x] Disconnecting or deleting the wallet clears the local lists that reveal Christian
      courses (offline stores), as R-#256 requires for paid content: landed with the
      R-#256 store (`clearPrivateCourseCopies()` on disconnect, wallet deletion and
      switch-off).
- [x] The new route(s) authenticate and `node bin/audit-api-auth.mjs` reports
      **0 failed** (59 passed / 0 failed); the migration for the flags and
      `contenido_cristiano` is reversible.
- [x] Unit tests for the visibility predicate (all four combinations of the two flags ×
      Christian/non-Christian course), for the mint gate and for the revocation guard;
      route tests for `GET /api/user/[id]` and the revoke route.
- [x] E2E: `e2e/specs/privacy-settings.spec.mjs` toggles the switch and checks the public
      profile with `fetch` (no cookies, the incognito equivalent), restoring the value
      afterwards; it skips itself until the page is deployed.
- [x] `make type`, the full unit suite and the touched E2E specs stay green.

## 5. Out of scope

- Hiding **participation** in the platform (the leaderboard handle, the wallet, the
  scholarships) — `excluir_leaderboard` covers full leaderboard exclusion and is not
  changed here.
- Anonymous/pseudonymous credentials (an SBT that does not reveal the holder) — that
  needs a different contract design.
- Deleting the off-chain learning history or the `transaction` rows (auditability and
  accounting).
- A general GDPR-style data export/erasure flow (R-#248 territory if it is opened).
- Retroactively burning credentials for courses the learner already published and then
  hid: the switch stops publishing, revocation is explicit and per credential.
