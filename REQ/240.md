### 1. Objective

Activate the service worker and configure it to cache static assets, the app
shell, and the offline fallback page. Give learn.tg its own PWA manifest.

### 2. Changes

**Current state before this REQ (verified 2026-09-15):** `next-pwa@^5.6.0` was
already a dependency of `apps/nextjs`, and `next.config.ts` already wrapped the
config in `withPWA` (`dest: 'public'`, `register: true`, `skipWaiting: true`) but
with **`disable: true`** and a `runtimeCaching` limited to `diligent-records` plus
`/_next/static`. So this REQ was about enabling and broadening it, not about
installing it.

**`next.config.ts`:** ✅ done

- `disable: pwaDisabled`, with `pwaDisabled = process.env.NEXT_PUBLIC_PWA_DISABLE === '1'`.
  **The PWA is generated in development too** (decided 2026-09-15), so the install
  flow can be tried on the dev site (`learn.tg:9001`); `NEXT_PUBLIC_PWA_DISABLE=1`
  turns it off in a build. Careful: in `next dev`, next-pwa still forces
  `NetworkOnly` and logs *"Build in develop mode, cache and precache are mostly
  disabled... offline support is disabled"*, while regenerating the worker on
  every compile (*"GenerateSW has been called multiple times"*), so **offline is
  only testable on a production build**. (An earlier revision of this REQ gated it
  on `pwaEnabled = NODE_ENV === 'production'`; the code no longer does.)
- `register: false`, and the registration lives in the app
  (`components/ServiceWorkerRegistrar.tsx`, mounted in `app/RootLayoutClient.tsx`):
  next-pwa's `register: true` injects `register.js` into the webpack `main.js`
  entry, which the App Router does not have, so the worker was generated and
  served while nothing registered it (found on the dev site 2026-09-15: `/sw.js`
  200, `getRegistrations()` empty, no registration code in any client chunk, and
  a manual `register('/sw.js')` working). Verified locally: 1 registration,
  activated, page controlled.
- `nextConfig.env.NEXT_PUBLIC_PWA_ENABLED` is `'1'` unless the build was disabled
  (`pwaDisabled`), and the registrar also honours `NEXT_PUBLIC_PWA_DISABLE`; when
  the flag is off the registrar **unregisters leftover workers and clears their
  caches** (a browser must not keep running stale code).
- `make pwa-clean` (run by `all`, `prod` and `bin/dev`) deletes the generated
  `public/sw.js` and the `workbox-*` / `fallback-*` / `worker-*` artifacts before
  a build, so nothing stale is served when the PWA is off. To retire a worker that
  is already deployed, `make pwa-kill-switch` copies `scripts/pwa-kill-switch.js`
  over `public/sw.js` (R-#243).
- Keep `skipWaiting: true`.
- `fallbacks: { document: '/offline' }` (typed as `PWAConfig['fallbacks']`
  because the published type demands all five fallback keys).
- `additionalManifestEntries: [{ url: '/offline', revision: null }]`: workbox
  only serves a document fallback that is **precached**, and `/offline` is a
  server-rendered route, so it must be added explicitly. The page is static (no
  user data), so `revision: null` is acceptable; a redeploy refreshes it with
  the service worker update.
- Extend `runtimeCaching`:
  - Static assets (`/_next/static/*`): `CacheFirst`, 7 days (already present).
  - Pages (`/en/*`, `/es/*`): `NetworkFirst`, 24 hours, 5 s network timeout.
  - API GET (`/api/*` with GET): `NetworkFirst`, 1 hour.
  - API mutations (`/api/*` with POST/PATCH/DELETE): `NetworkOnly`.
  - Images of the guides and icons (`/img/*`, `/icons/*` with
    png/jpg/jpeg/svg/webp/gif): `CacheFirst`, 30 days (R-#241 asks for the guide
    images to be available offline too).
- Keep the existing `diligent-records` entry (it caches another app served by
  this same Next app at `/[lang]/diligent-records`).
- `public/sw.js`, `public/workbox-*.js` and their `.map` stay out of git
  (`.gitignore`).

**Manifest — learn.tg needs its own:** ✅ done

- `public/manifest.json` **already exists but describes diligent-records**
  (`name: "Diligent Records"`, `start_url: "/en/diligent-records"`,
  `scope: "/en/diligent-records"`, icons under `/icons/diligent-records-*`).
- It is linked only from `app/[lang]/diligent-records/page.tsx`, which injects
  `<link rel="manifest" href="/manifest.json">` at runtime. `app/layout.tsx` has
  **no** manifest link, and `public/icons/` **does not exist** (the diligent
  manifest points at missing icons).
- Therefore: add a learn.tg manifest (e.g. `public/manifest.webmanifest`) with
  `name: "Learn.tg — Learn through games"`, `short_name: "Learn.tg"`,
  `start_url: "/"`, `scope: "/"`, `display: "standalone"`,
  `background_color: "#ffffff"`, `theme_color: "#2B6B4E"`,
  `orientation: "portrait"`, and 192x192 / 512x512 / maskable icons, and link it
  from the root layout metadata (`manifest: '/manifest.webmanifest'`). Leave the
  diligent one untouched.
- The source logo is `public/logo-learntg.png` (not under `/img/`), 246x244;
  the icons were generated from it with ImageMagick into
  `public/icons/learntg-{192x192,512x512,maskable-512x512}.png`.
- `app/layout.tsx` exports both `metadata.manifest` and
  `viewport.themeColor = '#2B6B4E'`.
