# R-#216: Rabby Wallet extension does not prompt to add Celo Sepolia (mobile does)

## Problem Description

When connecting a wallet with **Rabby Wallet** on learn.tg:

- **Mobile version**: automatically adds the **Celo Sepolia** network when
  connecting (works).
- **Browser extension**: does **not** prompt/offer to add the network — the
  user stays on the current network (or gets an error) and cannot complete the
  connection.

## Technical Context

The connection flow lives in `components/ConnectWalletButton.tsx`
(standard EIP-3326/3085):

1. `eth_chainId` — reads the current network (no prompt).
2. If it differs from the expected one → `wallet_switchEthereumChain({ chainId })`.
3. If the switch fails with `code === 4902` (network not added) →
   `wallet_addEthereumChain({ chainId, chainName, nativeCurrency: { symbol: 'CELO', decimals: 18 }, rpcUrls: [rpcUrl], blockExplorerUrls })`.
4. If the `add` fails → `addChainFailed` error.

Expected network data (from `.env`):

- `chainId`: `11142220` (Celo Sepolia, hex `0xAA044C`) — `expectedChainId` in the hook.
- `rpcUrl`: `NEXT_PUBLIC_RPC_URL`.
- `chainName`/`blockExplorer`: derived from `NEXT_PUBLIC_NETWORK`
  (celoSepolia → celo-sepolia.blockscout.com).

The Rabby extension injects `window.ethereum` (and `window.rabby`); its
"add chain" approval flow differs from the mobile one: mobile adds the network
without friction, while the extension requires approving the prompt in the
Rabby popup (or has it blocked/differently configured).

## Impact

- Users on the **Rabby extension** cannot connect to learn.tg (Celo Sepolia)
  from the browser: they stay on another network or see `addChainFailed`.
- Mobile works → inconsistent experience across platforms.
- The same Rabby account works on mobile (adds Celo Sepolia) but not on the
  extension — the issue is specific to the extension's approval flow, not the
  dApp payload.

## Diagnosis from the console (2026-08-29)

Log captured while connecting with the Rabby extension
(`/var/www/adJ-ia/tmp/c.txt`):

```
[auth] useAuthAddress: eth_accounts=["0xaa6591f006ca765a7e0bf7f1445b013a2873b94f"] available=true
Switch chain error: Object
```

**Key finding**: the wallet IS connected (`eth_accounts` returns the account,
`available=true`) — the flow dies at `wallet_switchEthereumChain`, which fails
with an error whose `code` is **neither 4902 nor 4001**. Because of that, the
code in `ConnectWalletButton.tsx` falls into the generic `else`
(`switchChainFailed`) and **`wallet_addEthereumChain` is NEVER called** — which
is why the extension never shows the "add network" prompt.

The console shows only `Object` — the real reason (code/message) is not logged.

## Suggested Solutions (diagnosis)

0. **Capture the full switch error** (highest priority): log
   `switchError.code`, `switchError.message` and `switchError.data` (or
   `JSON.stringify(switchError)`) in the `else` branch — currently only the
   bare object is logged. Likely candidates: `-32602` (invalid params), a
   Rabby-specific error such as `{ code: -32000, message: 'Switch chain
   failed' }`, or a "chain not found" message without code 4902.
1. **Reproduce and capture**: connect with the Rabby extension and log in the
   console: initial `eth_chainId`, `switchError.code`, and the exact
   `wallet_addEthereumChain` error (rejected with 4001? prompt never shown?).
   Does the Rabby popup ask to approve the "add chain"?
2. **Compare mobile vs extension (same account)**: the same Rabby account adds
   Celo Sepolia on mobile but not on the extension — narrows the issue to the
   extension's approval flow, not the dApp payload or chain data.
3. **Rabby settings**: check whether the extension has the "add chain" approval
   blocked/hidden (Rabby: Settings → Networks / "Allow adding chains").
4. **Add the network manually (immediate workaround)**: Rabby extension:
   Settings → Networks → Add network: Celo Sepolia, chainId `11142220`, RPC
   `https://forno.celo-sepolia.celo-testnet.org/`, symbol `CELO`.
5. **Verify the `add` payload**: `chainId` in the correct hex (`0xAA044C`),
   `rpcUrls` pointing to Celo Sepolia (not forno mainnet), `nativeCurrency`
   with `symbol: 'CELO'`.
6. **Detect Rabby** (`window.rabby` / EIP-6963) and log which API responds to
   `wallet_addEthereumChain`.

## Suggested Solutions (fix)

0. **Fall through to `wallet_addEthereumChain` on any non-4001 switch error**:
   today only `code === 4902` triggers the add. Rabby (and other wallets) can
   fail the switch with a different code/message when the chain is not added;
   treat any switch error that is NOT `4001` (user rejected) as "chain may be
   missing" and attempt the add.
1. **UX on `add` failure**: if `wallet_addEthereumChain` fails, instead of the
   generic `addChainFailed` error, show instructions to add the network
   manually (chainId 11142220 + RPC) — covers wallets with a different approval
   flow (Rabby extension).
2. **Flow order**: try `eth_requestAccounts` BEFORE the switch/add (some wallets
   handle the add better once the account is connected).
3. **Detect Rabby** (`window.rabby`) and, if applicable, use its own network
   flow (or show a Rabby-specific hint).
4. **Logging**: log `switchError`/`add` errors with detail (code, message) for
   remote diagnosis.
5. **Document on the site**: support note "Add Celo Sepolia in Rabby extension"
   (manual workaround) while the behavior is confirmed.
