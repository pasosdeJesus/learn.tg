# R-#215: Align testClusterFunds.ts with the ClusterFunds contract ABI

## Problem Description

The script `apps/hardhat/scripts/testClusterFunds.ts` (and its wrapper
`bin/testClusterFunds`) calls functions that the current `ClusterFunds`
contract **does not expose**:

- `cf.pdjTreasury()`
- `cf.pdjPercentage()`
- `cf.setPdJPercentage(99)`

Running it against a deployed `ClusterFunds` fails with:

```
TypeError: cf.pdjTreasury is not a function
    at main (scripts/testClusterFunds.ts:21)
```

## Technical Context

The current `ClusterFunds` (`contracts/ClusterFunds.sol`, inherits
`Ownable, ReentrancyGuard, Pausable`) does **not** store the treasury as a
public variable: it configures it as a *fee wallet* in the constructor
(`feeWallets.push(_pdjTreasury)`). The real contract API is:

- `getFeeConfig()` → `(address[] wallets, uint8[] percentages)`
- `setFeeConfig(address[] wallets, uint8[] percentages)` (owner only)
- `donorCashbackPct()` / `setDonorCashbackPct(uint8)` (reverts "Max 50%")
- `usdtToken()`, `slearnToken()`, `owner()`, `paused()`
- `getCountryBalance(string)`, `getClusterFunds(address)`,
  `getCountryFunds(string)`
- `processDonation`, `processCountryDonation`, `releaseClusterFunds`,
  `releaseCountryFunds`, `redistributeCountryFunds`, `removeCluster`,
  `setClusterVerification`, emergency flows (timelock)

The script is stale relative to an older version of the contract (or of
`ClusterFundsV2`) and went undetected because `bin/testClusterFunds` targets
the real network and is not part of the `contract:test` suite (which uses
`test/ClusterFunds.test.ts`, aligned with the current ABI).

Discovered in https://gitlab.com/pasosdeJesus/m/-/work_items/35 (Phase 6 — isolated contracts in the gdcluster engine)
while deploying and verifying a test `ClusterFunds` on celoSepolia:
`0xf3e9EA163F0b1A42753f3Cd20234411D0341210A`.

## Impact

- `pnpm testClusterFunds` (or `bin/testClusterFunds`) against a freshly
  deployed `ClusterFunds` fails with `TypeError` — deployments cannot be
  verified with the hardhat app script.
- Risk of "false OK" if someone fixes only the immediate error without
  aligning the remaining calls (e.g. `setPdJPercentage`).

## Suggested Solutions

1. **Align `apps/hardhat/scripts/testClusterFunds.ts` with the real ABI**
   (same fix already applied in the engine copy,
   `packages/gdcluster/contracts/scripts/testClusterFunds.ts`):
   replace `pdjTreasury()`/`pdjPercentage()`/`setPdJPercentage(99)` with
   `getFeeConfig()` and `setDonorCashbackPct(99)` (expected revert "Max 50%").
2. **Add a regression test**: have `contract:test` (ethereumjs) cover the
   script, or extend `test/ClusterFunds.test.ts` with the checks from
   `testClusterFunds.ts` (owner, fee config, cashback, revert on 99%).
3. Verify the fixed script against the test `ClusterFunds` on celoSepolia and
   against a real deployment before release.
