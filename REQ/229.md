# R-#229: Didnt allow to change name of a church from church editor of admin. Internal server error.

Didnt allow to change name of a church from church editor of admin. Internal server error.

---

**Created:** 2026-09-07
**Status:** ✅ **Resuelto (2026-09-09)** — pendiente de deploy

## Causa raíz

Al guardar cualquier cambio en la iglesia el servidor logueaba:

```
Error updating church: error: null value in column "pastor_whatsapp" of
relation "church" violates not-null constraint
```

`PATCH /api/admin/church/[id]` convertía `''`/`undefined` a `null` en **todas**
las columnas permitidas. `church.name`, `country_id`, `pastor_name` y
`pastor_whatsapp` son `NOT NULL`; muchas iglesias tienen `pastor_whatsapp = ''`
(la creación guarda `pastor_whatsapp || ''`), así que al editar solo el nombre el
formulario reenviaba `''` → `null` → 500, y el verificador solo veía
"Internal Server Error" (el cliente `adminFetch` muestra el `error` genérico que
devolvía la ruta).

## Arreglo

- `lib/safe-updates.ts`: `buildSafeUpdates(body, allowed, notNullFields)` — en
  columnas `NOT NULL` un valor vacío/ausente se **omite** (se conserva el valor
  actual); en nullable se mantiene `''`/`null`/`undefined` → `null`.
- `lib/church-updates.ts`: `CHURCH_NOT_NULL_FIELDS = {name, country_id,
  pastor_name, pastor_whatsapp}` + `buildChurchUpdates` (usado por el PATCH de
  iglesia).
- Mismo resguardo aplicado a `PATCH /api/admin/user/[id]` (`usuario.email` es
  `NOT NULL` editable): `buildSafeUpdates(body, ADMIN_EDITABLE_FIELDS, ['email'])`.
- El catch del PATCH de iglesia devuelve **400 con mensaje claro** si aún se cuela
  un not-null (`Algunos campos obligatorios no pueden quedar vacíos…`) en vez del
  500 genérico.

## Verificación

- `lib/__tests__/church-updates.test.ts` (5 tests): nombre + `pastor_whatsapp: ''`
  no envía el campo; nullable vacíos → null; campos no permitidos ignorados; caso
  usuario/email. `tsc` en 0. Prueba manual pendiente tras el deploy: editar el
  nombre de una iglesia con/ sin WhatsApp y guardar.
