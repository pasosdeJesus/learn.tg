## Part 2 — `next` 15.5.x → 16 (breaking, do second)

Migration already validated in sivel3 (REQ/63). Steps and recommendations:

### 2.1 Dependencies

```sh
pnpm add next@^16.0.0
```

React 19.2.x is already present and compatible.

### 2.2 Turbopack unsupported on adJ/OpenBSD → `--webpack`

Next.js 16 uses **Turbopack by default** (dev and build), which requires native
bindings (`next-swc`) that do not exist for `openbsd/x64`. Force Webpack:

```diff
# package.json
- "dev": "next dev",
- "build": "next build",
+ "dev": "next dev --webpack",
+ "build": "next build --webpack",
```

Also add `--webpack` in `bin/dev` and in the `Makefile` `all` and `prod`
targets (`pnpm exec next build --webpack`). `bin/prod.sh` runs `make` (→
`make all`), so the build is covered; `bin/start` runs `next start` (production
server), which does not compile and does **not** need `--webpack`.

### 2.3 `ulimit -d 7340032` (7G) before `next build`

V8 crashes (fatal GC, `Trace/BPT trap`) with the default data limit (1.5G)
during `next build` with Webpack. Raise it to 7G:

```sh
sh -c 'ulimit -d 7340032 && pnpm build'
```

Reflect this in the `Makefile` (`prod` target), as sivel3 does.

### 2.4 Remove `eslint` from `NextConfig`

The `eslint` option in `next.config.ts` no longer exists in v16:

```diff
- eslint: { ignoreDuringBuilds: true },
```

### 2.5 `next.config.ts` ESM — `__dirname` unavailable

Next.js 16 treats `next.config.ts` as an ES module. Use `import.meta.url`:

```typescript
import { fileURLToPath } from 'url';
import path from 'path';
const __dirname = path.dirname(fileURLToPath(import.meta.url));
```

### 2.6 Alias `@x402/*: false`

`@coinbase/cdp-sdk` (via wagmi → rainbowkit) imports `@x402/*` packages that are
not installed on adJ/OpenBSD. Alias them to `false`:

```typescript
webpack: (config) => {
  config.resolve.alias = {
    ...config.resolve.alias,
    '@x402/core': false,
    '@x402/core/client': false,
    '@x402/evm': false,
    '@x402/evm/exact/client': false,
    '@x402/evm/upto/client': false,
    '@x402/svm/exact/client': false,
  }
  return config
}
```

### 2.7 Verification

```sh
make type                                    # 0 errors
make test                                    # unit tests
sh -c 'ulimit -d 7340032 && pnpm build'      # production build with 7G
pnpm dev                                     # starts with --webpack
```

## General recommendations (to avoid tripping up)

1. **Order:** `vitest` first (isolated, low risk), then `next` (breaking). One
   commit per change.
2. **Work on a branch** and verify `make type` + `make test` before merging.
3. **Do not mix** with other changes (the `next 16` step touches `next.config.ts`,
   `bin/dev`, `Makefile`, `package.json`).
4. **Back up `next.config.ts`** before editing it (ESM + `eslint` + alias changes).
5. **If `next build` crashes with a fatal GC**, it is the `ulimit -d` issue (2.3),
   not a compilation error.
6. **Rollback:** `git revert` of the `next` commit is enough; no data migration.
7. After publishing, run `pnpm audit` to confirm the `vitest` critical and the
   `next` highs are gone.

## Fix: `bin/m req:list` roto por peer dep de `mpdj` (2026-08-17)

### Síntoma

Tras actualizar dependencias, `bin/m req:list` (y todos los comandos de
`mpdj`: `req:*`, `ai:framework`, `ai:principles`, `ai:skill`, `ai:adJ`,
`eng:credentials:*`) dejaron de funcionar: "Orden no encontrada".

### Causa raíz

`@pasosdejesus/mpdj@0.2.3` declara `@pasosdejesus/m: ^0.18.3` como **dependencia
dura**, pero learn.tg tenía `@pasosdejesus/m: ^0.17.3`. Eso produce **dos copias**
de `m` (dual package hazard): `mpdj` registra sus comandos en su copia de `m`
0.18.x, mientras `bin/m` ejecuta la de learn.tg (0.17.3). `contract-test@0.1.3`
adicionalmente declara `@pasosdejesus/m` como peer dependency. El `bin/m` traga
el error silenciosamente:

```js
// bin/m
try { await import('@pasosdejesus/mpdj') } catch {}  // ← error silencioso
await import('@pasosdejesus/m/m')
```

Como `mpdj` no registra sus comandos en la copia de `m` que ejecuta el CLI,
aparece "Orden no encontrada".

### Fix

```diff
# apps/nextjs/package.json
- "@pasosdejesus/m": "^0.17.3",
+ "@pasosdejesus/m": "^0.18.4",
- "@pasosdejesus/contract-test": "^0.1.1",
+ "@pasosdejesus/contract-test": "^0.1.3",

# apps/hardhat/package.json
- "@pasosdejesus/edr": "^0.1.0",
+ "@pasosdejesus/edr": "^0.1.1",
- "@pasosdejesus/contract-test": "^0.1.0",
+ "@pasosdejesus/contract-test": "^0.1.3",
```

### Verificación

| Comando | Resultado |
|---------|-----------|
| `bin/m req:list` | ✅ |
| `bin/m req:show 19` | ✅ |
| `bin/m ai:principles` | ✅ |
| `bin/m --help` (ai:framework, ai:skill, ai:adJ) | ✅ |

### Lección

Los paquetes `m`/`mpdj`/`contract-test` deben actualizarse **en conjunto**.
Una versión de `mpdj` que sube su peer dep de `m` deja roto el `bin/m` de los
proyectos que aún tienen la versión antigua de `m`, y el `try/catch` del
`bin/m` oculta el error. Ver m/REQ/42.md (dual package hazard + peer deps).
