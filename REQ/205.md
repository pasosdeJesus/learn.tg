## Part 2 — `next` 15.5.x → 16 (breaking, do second)

Migration already validated in sivel3 (REQ/63). Steps and recommendations:

### 2.1 Dependencies

```sh
pnpm add next@^16.0.0
```

React 19.2.x is already present and compatible.

### 2.2 Turbopack unsupported on adJ/OpenBSD → `--webpack`

Next.js 16 uses **Turbopack by default** (dev and build), which requires native
bindings (`next-swc`) that do not exist for `openbsd/x64`. Force Webpack:

```diff
# package.json
- "dev": "next dev",
- "build": "next build",
+ "dev": "next dev --webpack",
+ "build": "next build --webpack",
```

Also add `--webpack` in `bin/dev` and in the `Makefile` (`prod`/`build` targets).

### 2.3 `ulimit -d 7340032` (7G) before `next build`

V8 crashes (fatal GC, `Trace/BPT trap`) with the default data limit (1.5G)
during `next build` with Webpack. Raise it to 7G:

```sh
sh -c 'ulimit -d 7340032 && pnpm build'
```

Reflect this in the `Makefile` (`prod` target), as sivel3 does.

### 2.4 Remove `eslint` from `NextConfig`

The `eslint` option in `next.config.ts` no longer exists in v16:

```diff
- eslint: { ignoreDuringBuilds: true },
```

### 2.5 `next.config.ts` ESM — `__dirname` unavailable

Next.js 16 treats `next.config.ts` as an ES module. Use `import.meta.url`:

```typescript
import { fileURLToPath } from 'url';
import path from 'path';
const __dirname = path.dirname(fileURLToPath(import.meta.url));
```

### 2.6 Alias `@x402/*: false`

`@coinbase/cdp-sdk` (via wagmi → rainbowkit) imports `@x402/*` packages that are
not installed on adJ/OpenBSD. Alias them to `false`:

```typescript
webpack: (config) => {
  config.resolve.alias = {
    ...config.resolve.alias,
    '@x402/core': false,
    '@x402/core/client': false,
    '@x402/evm': false,
    '@x402/evm/exact/client': false,
    '@x402/evm/upto/client': false,
    '@x402/svm/exact/client': false,
  }
  return config
}
```

### 2.7 Verification

```sh
make type                                    # 0 errors
make test                                    # unit tests
sh -c 'ulimit -d 7340032 && pnpm build'      # production build with 7G
pnpm dev                                     # starts with --webpack
```

## General recommendations (to avoid tripping up)

1. **Order:** `vitest` first (isolated, low risk), then `next` (breaking). One
   commit per change.
2. **Work on a branch** and verify `make type` + `make test` before merging.
3. **Do not mix** with other changes (the `next 16` step touches `next.config.ts`,
   `bin/dev`, `Makefile`, `package.json`).
4. **Back up `next.config.ts`** before editing it (ESM + `eslint` + alias changes).
5. **If `next build` crashes with a fatal GC**, it is the `ulimit -d` issue (2.3),
   not a compilation error.
6. **Rollback:** `git revert` of the `next` commit is enough; no data migration.
7. After publishing, run `pnpm audit` to confirm the `vitest` critical and the
   `next` highs are gone.
