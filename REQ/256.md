# R-#256: Offline course download (free and purchased)

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/256 — create it with
`cd apps/nextjs && bin/m req:create "Offline course download"` if the number differs;
rename this file to the number the issue gets.

**Status:** Implemented (2026-09-22, branch `mvppwa`) — the per-course store, the
download button, `/offline` reading the store, the privacy rule for Christian
courses, the cleanup on switch-off/disconnect/wallet deletion, the 24 h

**Created:** 2026-09-21

**Priority:** High for the target audience — the students with the weakest connectivity

**Dependencies:** R-#240 (service worker, manifest, offline fallback), R-#242 (offline
crossword queue), R-#241 (guide cache), R-#244 (PWA + in-app wallet)

## 1. Objective

Let a learner **download a whole course** — its guides **and** its crosswords — so it is
readable and answerable offline **without having opened each page first**, refreshed
when the connection returns, and removable to free space:

- **Free courses**: anyone with the app can download them.
- **Purchased courses**: only while that wallet has access; another wallet on the same
  device must not see the content.
- The stored copy is revalidated at least **once every 24 hours** when online: if a
  guide's content or answers changed, the copy is refreshed and the user is told.

## 2. What exists today

- `lib/offline-guide-db.ts` caches the markdown of a **visited** guide (IndexedDB
  `learn-tg-offline` → `guides`) and `useCachedGuide` serves it when offline.
- `lib/offline-queue-db.ts` + `lib/hooks/useOfflineQueue.ts` queue submissions made
  offline and replay them (R-#242); `lastRejection` surfaces a server rejection.
- `lib/offline-catalog.ts` keeps the last course list seen and `/offline` lists the
  cached guides.
- The service worker (`next.config.ts`) caches visited pages (`/[en|es]/*`,
  NetworkFirst 24 h), `_next/static`, images and `api/*` GET (NetworkFirst 1 h); the
  `/offline` and `/[en|es]` shells are precached.
- **Missing**: an explicit per-course download, the crossword **without answers** for
  guides never fetched, the entitlement check per wallet, the revision/24 h
  revalidation, deletion, and the UI (size, "remove").

## 3. Design

1. **A per-course store.** New object store `courses` in `learn-tg-offline`:
   `{ key, courseId, lang, prefix, downloadedAt, revision, guides: [{ suffixRuta, markdown, puzzle }], bytes }`.
   `key` is `{lang}/{prefijoRuta}`; one record per course and language.
2. **Download button** on the course page (`app/[lang]/[pathPrefix]/page.tsx`):
   "Download for offline" with progress, the size it will take, and "Remove". The
   button is only offered when the wallet may read the course (free, or purchased by
   this wallet). `navigator.storage.estimate()` is used to warn about space on cheap
   phones.
3. **The crossword payload carries no answers.** Downloading a puzzle must store the
   layout and the clues, **never** the solution: no `letter` in the grid cells and no
   `word` in the placements. Reuse the **existing** `GET /api/crossword`
   (`apps/nextjs/app/api/crossword/route.ts`, in the `app/api` submodule): it already
   resolves the guide (`getCourseIdByPrefix`/`getGuideIdBySuffix`) and returns cells
   with `letter: ''` and no answers, so the work is to make its parameters
   offline-friendly (`courseId`/`guide` or the prefix/suffix pair) and keep stripping
   the solution — **not** to create a second endpoint.
4. **Validation without `answer_fib`.** `POST /api/check-crossword` must accept a
   guide the user never fetched online: the answers are derived from the **guide
   markdown** (the `(answer)` of each numbered question, the same regex as the parser)
   instead of `billetera_usuario.answer_fib`, **without changing** the response for the
   online path. The reward rules (profile score ≥ 50, cooldown, vault balance) are
   untouched.
5. **Entitlement snapshot.** The record stores the wallet address and the purchase
   state at download time. On open, if the current wallet is not the one that
   downloaded a paid course, the content is not rendered (and the record can be
   dropped). "Disconnect" and "delete wallet" remove the downloaded paid content.
6. **Revalidation every 24 h.** Each course carries a `revision` (a hash of the
   guides' content served by the API). When the app opens with a connection and the
   copy is older than 24 h (or the revision differs), the copy is refreshed in the
   background and the user is told ("the course was updated"). Free courses are
   refreshed on any visit; paid ones only while the wallet still has access.
6b. **The privacy switch of R-#259 applies to the downloaded list too.** The
   `contenido_cristiano` flag decides what the **device** shows: a downloaded
   Christian course is not listed offline (nor in the `/offline` page) unless the
   learner enabled "show Christian courses publicly", and "Disconnect"/"delete
   wallet" removes it. The risk is local, not public: a shared or inspected phone
   must not reveal the affiliation just by opening the app offline. Ties to R-#259
   §3.3 ("local stores") and to the whitepaper rule that the flag is honored by
   everything that lists courses.
7. **The `/offline` page and the course list read from the store**: a downloaded
   course lists its guides (not only the visited ones) and shows when it was last
   refreshed.
8. **Queue integration (R-#242):** an answer given offline for a downloaded guide is
   queued and replayed as today; the result of the review must reach the user (in-page
   message today; the `notifications` table variant is the pending half of R-#242).
9. **Storage hygiene:** "delete the app" and the browser's own eviction must not lose
   queued answers silently: pending submissions are kept in their own store and the
   download of a course never deletes them (R-#240 §4b item 9).

## 4. Acceptance criteria

- [x] A free course can be downloaded from the course page and read offline, guides
      **and** crosswords, including guides the user **never opened online**
      (the downloaded HTML lives in the `guides` store, the document is warmed into
      `learntg-pages`; see `doc/pwa-developer-guide.md` §Downloaded courses).
- [x] The offline crossword payload carries no answers (unit-tested and checked by the
      E2E spec reading the IndexedDB record: `placements[].word === '-'`, no `letter`).
- [x] Offline the user fills the crossword and submits: the button queues the answer,
      says it is saved and that it will be reviewed when there is a connection, and
      nothing is validated locally (R-#242).
- [x] On reconnect the queue drains, `POST /api/check-crossword` validates it (also for
      a guide never fetched online, deriving the answers from the guide markdown and
      matching by clue: `packages/rewards/src/lib/guide-answers.ts`), and the user gets
      the result plus the guide/course progress.
- [x] A purchased course can be downloaded while that wallet has access; another wallet
      on the same device does not see it (`belongsToWallet`, `/offline` filters).
- [x] The stored copy is revalidated at least once every 24 h when online; if a guide
      changed, the copy is refreshed and the user is told.
- [x] Disconnect and "delete wallet" remove the downloaded paid courses
      (`clearPrivateCourseCopies()` in `WalletSelector`, `WalletEventListener`,
      `ConnectWalletButton`, `WalletDialog`).
- [x] A downloaded course with `contenido_cristiano` is **not listed offline** unless the
      learner enabled the visibility switch (R-#259), and turning that switch off
      removes the copy: the device does not reveal the affiliation on its own.
- [x] Downloaded paid content is **not** readable from the generic HTTP cache only:
      the explicit store is the durable copy and it is deletable.
- [x] The course page shows the space it takes, lets the user remove the download, and
      warns when the device is running out of space.
- [x] Unit tests for the store, the download, the revision comparison and the answer
      parser; component test for the download button; E2E spec
      `offline-course-download` (download a free course → airplane mode → open a guide
      never visited online → check the stored puzzle has no answers).
- [x] `make test-e2e-offline` keeps passing on a production build: green on the
      2026-09-21/22 dev site (`offline-guide` 5/5, `offline-crossword` and
      `offline-course-download` skip themselves with a reason until this branch is
      deployed there).

## 4b. Decisions taken while implementing

- The **guide content** is not duplicated into the `courses` record: it stays in the
  existing `guides` store (one copy per guide, and `useCachedGuide` reads it without
  changes). The record keeps the guide list, the puzzles and the metadata.
- **Downloading warms the page cache** (`warmPageCache`). Without it, offline
  navigation to a never-visited guide would land on the `/offline` fallback even
  though the content is stored.
- The server **prefers the markdown-derived answers whenever every placement's clue
  matches a question**, falling back to `answer_fib` otherwise. This fixes a
  pre-existing bug (a stale `answer_fib` from another guide marked correct answers
  wrong) and is what makes an offline answer verifiable. If neither source is
  consistent with the placements, the route answers `422` with
  `invalidPuzzle` instead of marking the answer wrong.

## 5. Out of scope

- Downloading the whole platform or content the user has no access to.
- Video/audio lessons and their offline storage.
- Background sync while the app is closed (iOS limits it; the revalidation happens when
  the app is opened with a connection).
- Changing the reward rules or the scholarship formula.
- The accounting tool of the business course (that is R-#258) and the per-course
  entitlement model beyond the snapshot above.
