# R-#163: Referral Program for learn.tg

Implement a general referral program for the learn.tg platform with **three reward forms**:

1. **Form 1 — course purchases:** the referrer earns 10% of the course price when a referred user buys **any premium course** (including Global Disciples).
2. **Form 2 — missional scholarships:** the referrer earns 10% of the scholarship value when a referred user completes a crossword in a **missional course** (only "Una relación con Jesús"); the student keeps 100% of their scholarship.
3. **Form 3 — pastor bonus:** the referrer earns an additional **1 USDT** when a referred **pastor** purchases the **Global Disciples course**.

Provides a dedicated referral menu with: code, balance, history, and referral status.

**Funding rule:** all rewards are paid **from the referral wallet** (`NEXT_PUBLIC_REFERRAL_WALLET_ADDRESS`), never from scholarships or student funds. If the wallet has no funds, the reward is skipped.

**Architecture decision (REQ/35):** The referral program is part of the **core** of learn.tg, not a separate engine. It is a cross-cutting feature that affects all courses and users, has no contracts of its own, and does not reduce build time. It will only be extracted if a second consumer (e.g., sivel3) requires it.

## 1. Referral Program Overview

### 1.1 Activation
The referral program is activated when a user **purchases any premium course**. Premium courses include:
- Global Disciples Course (id 10 EN, 11 ES)
- Any other premium course added in the future (`porPagar > 0`)

### 1.2 Referral Reward Source

**All rewards are paid from the referral wallet, never from the student's scholarship.**

| Aspect | Decision |
|--------|----------|
| **Source** | Referral wallet (`NEXT_PUBLIC_REFERRAL_WALLET_ADDRESS`), funded by 10% of premium purchases (from pdJ reduction 55% → 50%) |
| **Form 1** | 10% of the course price on premium purchase, paid 50% USDT + 50% SLEARN |
| **Form 2** | 10% of the scholarship value on missional crossword; student keeps 100% |
| **Form 3** | 1 USDT bonus when referred pastor buys GD course (paid in USDT) |
| **No funds** | If the referral wallet is empty, the reward is skipped (logged, not silently swallowed) |
| **Atomicity** | Off-chain attribution: read `ReferralReward` event, credit referrer, pay from referral wallet |

### 1.3 Reward Formula

```
If the referred user earns scholarship USDT = 1.00 and SLEARN = 5 (missional course):

Referrer receives (paid from the referral wallet):
  USDT: 0.10 (10% of 1.00)
  SLEARN: 0.50 (10% of 5)

Student receives (100% of their scholarship — no deduction):
  USDT: 1.00
  SLEARN: 5.00

If the referred user is a pastor purchasing the GD course:
  Additional bonus: 1.00 USDT
```

### 1.4 Example by Course

| Course | Scholarship per guide | Referrer (10% + bonus) | Student (100%) |
|--------|-----------------------|------------------------|----------------|
| **Web3 & UBI** | 1 USDT + 1 SLEARN | 0.10 USDT + 0.10 SLEARN | 1.00 USDT + 1.00 SLEARN |
| **Global Disciples (missional)** | 1 USDT + 5 SLEARN | 0.10 USDT + 0.50 SLEARN + **1 USDT** (if referred is pastor) | 1.00 USDT + 5.00 SLEARN |
| **Other missional course** | 1 USDT + 1 SLEARN | 0.10 USDT + 0.10 SLEARN | 1.00 USDT + 1.00 SLEARN |

### 1.5 Pastor Referral Bonus (GD Course Only)

When a referred user who is a **pastor** purchases the **Global Disciples course**, the referrer receives an additional **1 USDT** bonus on top of the standard 10% reward.

| Condition | Bonus |
|-----------|-------|
| Referred user is a pastor (`church_relationship = 'pastor'`) | +1 USDT |
| Referred user purchases the GD course (`course_id = 10` or `11`) | +1 USDT |
| Both conditions met | **+1 USDT** |

**Funding:** Paid from the referral wallet (`NEXT_PUBLIC_REFERRAL_WALLET_ADDRESS`), same as the 10% reward. If the referral wallet has insufficient funds (< 1 USDT), the bonus is skipped (logged but not paid).

**Purpose:** Incentivize church members and other users to invite pastors to join the GD pilot. The 1 USDT bonus is a small but tangible reward that can be communicated clearly ("Invita a tu pastor y gana 1 USDT").

## 2. Referral Code and Tracking

### 2.1 Code Generation
- Each user receives a **unique referral code** upon purchasing a premium course
- The code is generated using `crypto.randomUUID()` and takes the first 8 characters
- The code is visible in the referral menu
- The code can be shared via link, QR code, or text
- Codes do not expire (`expires_at` can be NULL)

### 2.2 Referral Link Format
```
https://learn.tg/ref/{CODE}
```

### 2.3 Tracking
When a new user connects their wallet for the first time:
- If they used a referral link, the referrer is recorded
- If not, they can enter a referral code manually
- The referral relationship is stored in the database
- Each user can only claim a referral code once (`referral_claimed_at` tracks this)

## 4. Reward Payment (off-chain)

> **Superseded:** the earlier design routed referral rewards through
> `LearnTGVaultsV5` (`referrer`, `referrerUSDT`, `referrerSlearn`). The new
> design pays off-chain from the referral wallet — no contract change needed.

The `SLEARN.processPayment` sends `percentageReferral=10` to the single
`referralWallet` (50% USDT + 50% SLEARN minted via `mintAndReserve`). The backend
then:
1. Reads the `ReferralReward(referralWallet, usdtAmount, slearnAmount)` event.
2. Attributes the reward to the referrer of the paying user (from the DB).
3. Transfers the USDT + SLEARN from the referral wallet to the referrer using
   `PRIVATE_KEY_REFERRAL_WALLET`.

The contract does not calculate the per-referrer split; the backend handles all
attribution and payouts.

### Pastor Bonus (GD Course Only)

After the standard 10% reward is paid, the backend checks:

1. Is the referred user a pastor? (`church_relationship = 'pastor'` on the referred user's church)
2. Did they purchase the GD course? (`course_id = 10` or `11`)

If both conditions are met, the backend transfers an additional **1 USDT** from the referral wallet to the referrer.

```typescript
// lib/referral/pastor-bonus.ts
async function awardPastorReferralBonus(referrerId: number, referredId: number, courseId: number) {
  // 1. Check if referred is a pastor
  const referred = await db.selectFrom('usuario')
    .innerJoin('church', 'church.id', 'usuario.church_id')
    .where('usuario.id', '=', referredId)
    .select(['church.church_relationship'])
    .executeTakeFirst()
  
  if (referred?.church_relationship !== 'pastor') return

  // 2. Check if course is GD (id 10 or 11)
  if (![10, 11].includes(courseId)) return

  // 3. Check referral wallet has ≥ 1 USDT
  const balance = await getReferralWalletBalance()
  if (balance.usdt < 1) {
    logger.warn('Pastor referral bonus skipped: insufficient USDT in referral wallet')
    return
  }

  // 4. Transfer 1 USDT
  await transferFromReferralWallet(referrerId, 1, 'USDT')
  await recordReferralBonus(referrerId, referredId, courseId, 1, 'USDT', 'pastor_bonus')
}
```

**Idempotency:** The bonus is recorded in the `transaction` table with `type='referral_bonus'` and `subcategoria='pastor_bonus'` to prevent double payments.

**Transaction entry:**
```sql
INSERT INTO transaction (
    usuario_id, wallet, crypto, type, amount, balance_impact, date, hash,
    categoria, subcategoria, metadata
) VALUES (
    :referrer_id, :wallet, 'USDT', 'referral_bonus', 1.00, 1.00, NOW(), :hash,
    'referral', 'pastor_bonus',
    '{"referred_id": 456, "course_id": 10}'
);
```

CREATE TABLE referralcode (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER REFERENCES usuario(id) NOT NULL,
    code VARCHAR(20) UNIQUE NOT NULL,
    activated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP,                     -- NULL = never expires
    active BOOLEAN DEFAULT TRUE
);
```

### 6.2 Referral Relationships

```sql
CREATE TABLE referralrelationship (
    id SERIAL PRIMARY KEY,
    referrer_id INTEGER REFERENCES usuario(id) NOT NULL,

    referral_claimed_at TIMESTAMP,            -- When the code was claimed
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(20) DEFAULT 'pending'     -- 'pending', 'completed', 'paid'
);

## 9. Security

### 9.1 Validation Checks

| Check | Description |
|-------|-------------|
| **Code uniqueness** | Each referral code must be unique |
| **Valid course** | The completed course must be valid |
| **One time per relationship** | Each referral relationship pays only once per course |
| **No self-referral** | A user cannot refer themselves (enforced by backend) |
| **Referral claimed once** | A user can only claim one referral code |
| **Pastor check** | Pastor bonus only applies if referred user's `church_relationship = 'pastor'` |
| **GD course check** | Pastor bonus only applies to GD course (id 10 or 11) |

### 9.2 Anti-Fraud Measures

| Measure | Description |
|---------|-------------|
| **Unique wallets** | A user cannot refer themselves |
| **Course completion** | Rewards only paid after course completion |
| **Manual review** | Suspicious activity flagged for review |
| **Rate limiting** | Limited referral claims per day |
| **Idempotency** | No double payments (DB constraints + transaction checks) |
