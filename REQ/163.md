# R-#163: Referral Program for learn.tg (Actualizado)

Implement a general referral program for the learn.tg platform with **two reward forms**:

1. **Form 1 — course purchases:** the referrer earns 10% of the course price when a referred user buys **any premium course** (including Global Disciples).
2. **Form 2 — missional scholarships:** the referrer earns 10% of the scholarship value when a referred user completes a crossword in a **missional course** (only "Una relación con Jesús"); the student keeps 100% of their scholarship.
3. Provides a dedicated referral menu with: code, balance, history, and referral status.
4. Includes a **testimony system** for Global Disciples course completers to attest to their leader's impact.

**Funding rule:** both forms are paid **from the referral wallet** (`NEXT_PUBLIC_REFERRAL_WALLET_ADDRESS`), never from scholarships. If the wallet has no funds, the referrer receives nothing.

## Dependencies
- Existing course system (`cor1440_gen_proyectofinanciero`)
- Existing USDT and SLEARN contracts
- #161 (Global Disciples Course — activates referrals on premium purchase)
- #155 (Contract for Cluster/Country Funds — referral fund source)
- `transaction` table — referral rewards are value movements, must be recorded
- **LearnTGVaultsV5** — modified contract with flexible split (#196)

**Note:** Referral rewards are paid off-chain from the referral wallet (`PRIVATE_KEY_REFERRAL_WALLET`), not calculated by the contract. The `SLEARN.processPayment` only routes the 10% (from pdJ) into the referral wallet; the backend then attributes and pays each referrer.

## 1. Referral Program Overview

### 1.1 Activation
The referral program is activated when a user **purchases any premium course**. Premium courses include:
- Global Disciples Course
- Any other premium course added in the future

### 1.2 Referral Reward Source

**The reward is paid from the referral wallet, never from the student's scholarship.**

| Aspect | Decision |
|--------|----------|
| **Source** | Referral wallet (`NEXT_PUBLIC_REFERRAL_WALLET_ADDRESS`), funded by 10% of premium purchases (from pdJ reduction 55% → 50%) |
| **Form 1** | 10% of the course price on premium purchase, paid 50% USDT + 50% SLEARN |
| **Form 2** | 10% of the scholarship value on missional crossword; student keeps 100% |
| **No funds** | If the referral wallet is empty, the referrer receives nothing |
| **Atomicity** | Off-chain attribution: read `ReferralReward` event, credit referrer, pay from referral wallet |

### 1.3 Reward Formula

```
If the referred user earns scholarship USDT = 1.00 and SLEARN = 5 (missional course):

Referrer receives (paid from the referral wallet):
  USDT: 0.10 (10% of 1.00)
  SLEARN: 0.50 (10% of 5)

Student receives (100% of their scholarship — no deduction):
  USDT: 1.00
  SLEARN: 5.00
```

### 1.4 Example by Course

| Course | Scholarship per guide | Referrer (10%, from wallet) | Student (100%) |
|--------|-----------------------|----------------------------|----------------|
| **Web3 & UBI** | 1 USDT + 1 SLEARN | 0.10 USDT + 0.10 SLEARN | 1.00 USDT + 1.00 SLEARN |
| **Global Disciples (missional)** | 1 USDT + 5 SLEARN | 0.10 USDT + 0.50 SLEARN | 1.00 USDT + 5.00 SLEARN |
| **Other missional course** | 1 USDT + 1 SLEARN | 0.10 USDT + 0.10 SLEARN | 1.00 USDT + 1.00 SLEARN |

## 2. Referral Code and Tracking

### 2.1 Code Generation
- Each user receives a **unique referral code** upon purchasing a premium course
- The code is generated using `crypto.randomUUID()` and takes the first 8 characters
- The code is visible in the referral menu
- The code can be shared via link, QR code, or text
- Codes do not expire (`expires_at` can be NULL)

### 2.2 Referral Link Format
```
https://learn.tg/ref/{CODE}
```

### 2.3 Tracking
When a new user connects their wallet for the first time:
- If they used a referral link, the referrer is recorded
- If not, they can enter a referral code manually
- The referral relationship is stored in the database
- Each user can only claim a referral code once (`referral_claimed_at` tracks this)

## 3. Testimony System (For Global Disciples Only)

### 3.1 Purpose

When a referred user completes the Global Disciples course, they can fill out a **testimony form** attesting to the leader's impact. This is used to:
1. Calculate the leader's score for the **Program Director** role
2. Verify the leader's missionary activity
3. Reward leaders with additional points

### 3.2 Testimony Form

When a referred student completes the Global Disciples course, they receive a notification to "Testify for your leader."

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `presented_christ` | Checkbox | The leader introduced me to Christ for the first time |
| `discipled` | Checkbox | The leader discipled me (taught me to follow Christ) |
| `came_mission` | Checkbox | The leader came on a mission trip to my area |
| `invited_event` | Checkbox | The leader invited me to a Bible study/event |
| `helped_faith` | Checkbox | The leader helped me grow in my faith |
| `relationship` | Select | Pastor, Group Leader, Friend, Family, Other |
| `other_relationship` | Text | If "Other" is selected |
| `comments` | Textarea | Additional comments (optional) |

### 3.3 Testimony Flow

```mermaid
flowchart LR
    A[Referred user completes GD course] --> B[Receives notification to testify]
    B --> C[Fills out form with checkboxes]
    C --> D[Signs with wallet]
    D --> E[Testimony saved]
    E --> F[Leader accumulates points]
```

### 3.4 Testimony Database

```sql

    id SERIAL PRIMARY KEY,
    leader_id INTEGER REFERENCES usuario(id) NOT NULL,
    witness_id INTEGER REFERENCES usuario(id) NOT NULL,

    presented_christ BOOLEAN DEFAULT FALSE,
    discipled BOOLEAN DEFAULT FALSE,
    came_mission BOOLEAN DEFAULT FALSE,
    invited_event BOOLEAN DEFAULT FALSE,
    helped_faith BOOLEAN DEFAULT FALSE,
    relationship VARCHAR(50),

```

### 3.5 Testimony Score (For Program Director Selection)

| Criterion | Points |
|-----------|--------|
| Presented Christ | +10 |
| Discipled | +8 |
| Came on mission | +6 |
| Invited to event | +4 |
| Helped grow in faith | +4 |
| Is my pastor | +5 |
| Is my group leader | +3 |

```typescript
// lib/leader-score.ts
export function calculateLeaderScore(testimonies: Testimony[]): number {
  let score = 0
  for (const t of testimonies) {
    if (t.presented_christ) score += 10
    if (t.discipled) score += 8
    if (t.came_mission) score += 6
    if (t.invited_event) score += 4
    if (t.helped_faith) score += 4
    if (t.relationship === 'pastor') score += 5
    if (t.relationship === 'group_leader') score += 3
  }
  return score
}
```

## 4. Reward Payment (off-chain, supersedes V5 approach)

> **Superseded:** the earlier design routed referral rewards through
> `LearnTGVaultsV5` (`referrer`, `referrerUSDT`, `referrerSlearn`). The new
> design pays off-chain from the referral wallet — no contract change needed.

The `SLEARN.processPayment` sends `percentageReferral=10` to the single
`referralWallet` (50% USDT + 50% SLEARN minted via `mintAndReserve`). The backend
then:
1. Reads the `ReferralReward(referralWallet, usdtAmount, slearnAmount)` event.
2. Attributes the reward to the referrer of the paying user (from the DB).
3. Transfers the USDT + SLEARN from the referral wallet to the referrer using
   `PRIVATE_KEY_REFERRAL_WALLET`.

The contract does not calculate the per-referrer split; the backend handles all
attribution and payouts.

```sql
CREATE TABLE referralrelationship (
    id SERIAL PRIMARY KEY,
```

### 6.4 Transaction Table

Every referral reward payment creates entries in the `transaction` table:

```sql

    usuario_id, wallet, crypto, type, amount, balance_impact, date, hash,

    'referral', 'referrer',
    '{"referred_id": 456, "course_id": 1, "guide_id": 2}'
```

## 9. Security

### 9.1 Validation Checks

| Check | Description |
|-------|-------------|
| **Code uniqueness** | Each referral code must be unique |
| **Valid course** | The completed course must be valid |
| **One time per relationship** | Each referral relationship pays only once per course |
| **No self-referral** | A user cannot refer themselves (enforced by backend) |
| **Referral claimed once** | A user can only claim one referral code |

### 9.2 Anti-Fraud Measures

| Measure | Description |
|---------|-------------|
| **Unique wallets** | A user cannot refer themselves |
| **Course completion** | Rewards only paid after course completion |
| **Manual review** | Suspicious activity flagged for review |
| **Rate limiting** | Limited referral claims per day |
