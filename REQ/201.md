4. **Chai**: implement `network.provider.send`, `changeEtherBalances`, fix `revertedWithCustomError`.

## 2. Next.js tests — root cause identified

### `kysely-mocks.js` imports `vi` at the top level (affects ~15 suites, ~100 tests)

**Symptom**: `ReferenceError: mockSql is not defined` at `kysely-mocks.js:5`

**File**: `node_modules/@pasosdejesus/m/dist/test-utils/kysely-mocks.js`
```javascript
import { vi } from 'vitest';  // line 5 — fails in vitest setup context
```

**Mechanism**: `vitest.setup.ts` (line 21) imports `apiDbMocks` from the package. The `kysely-mocks.js` module imports `vi` at the top level. During vitest initialization, this circular import causes `vi` to be undefined, so `apiDbMocks` and its fields (`mockSql`, etc.) are undefined. Any `vi.mock()` referencing them fails.

### Immediate fix (learn.tg)

Inline the mock definitions in `vitest.setup.ts` without depending on the package:

```typescript
// Replace:
import { apiDbMocks } from '@pasosdejesus/m/test-utils/kysely-mocks'
const { mockExecuteTakeFirst, mockExecute, mockSqlExecute, mockSql, mockPgPool } = apiDbMocks

// With inline definition:
const mockExecuteTakeFirst = vi.fn()
const mockExecute = vi.fn()
const mockSqlExecute = vi.fn()
const mockSql = vi.fn(() => ({ as: vi.fn(), execute: mockSqlExecute }))
const mockPgPool = vi.fn()
// ... GlobalMockKysely class (already defined in vitest.setup.ts:32-80) ...
```

### Definitive fix (m)

Modify `packages/m/src/test-utils/kysely-mocks.ts` to NOT import `vi` at the top level. Options:
- Accept `vi` as a parameter to `createMockKysely({ vi })`
- Use lazy initialization: `let _vi: typeof vi; export function setVi(v: typeof vi) { _vi = v }`
