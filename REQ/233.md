# R-#233: Rails per session and remove billetera_usuario.token

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/233

**Status:** In progress — Phase 1 (additive) implemented 2026-09-14: the Rails course endpoints are public, the unused `usuarios#actualiza_mi_usuario` is removed, and Next no longer sends the token to Rails. Phase 2 (subtractive: remove `billetera_usuario.token`, `GET /api/auth/token` and the localStorage token) is pending deployment/verification.
**Created:** 2026-09-14
**Type:** Security / Refactor
**Dependencies:** R-#227 (https://github.com/pasosdeJesus/learn.tg/issues/227)
**Moved from:** R-#227 (Phase 2)

---

## 1. Objective

Phase 2 of R-#227: make Rails (`servidor/`) authenticate with the shared session
(or its own mechanism with a separate key/`audience`) and retire the
`billetera_usuario.token` column, so the client no longer needs to persist or send
an API token. This closes the remaining OWASP gaps of R-#227 (credential in the
URL/query and in `localStorage`).

## 2. Why a separate issue

Phase 2 touches the `servidor/` repo and is the highest-risk part; closing R-#227
with Phase 1 + the hardening already meets the original objective (an on-chain
operation is not lost to a 401 and identity is the session).

## 3. Measured scope (small surface)

- Rails: `app/helpers/application_helper.rb`
  (`usuarioBilleteraToken`/`verificaToken`) and **2 endpoints**:
  `cor1440_gen/proyectosfinancieros_controller#index/#show` and
  `usuarios_controller#actualiza_mi_usuario` (6 uses of `request[:token]`).
  **There are no Rails tests** for those routes.
- Next: `authorize()` (`auth-options.ts`), `app/api/auth/token`,
  `lib/authenticateUser.ts` (legacy fallback), `lib/auth-token.ts`, and the
  E2E/non-browser specs of R-#227's "Residual token dependency inventory".

## 4. Tasks

### 4.1 Immediate (low risk) — DONE (2026-09-14)

- [x] Reuse the existing token in `authorize()` instead of rotating it on every
      login (generate only on `insert`, or when the stored value is not a
      dedicated token). Implemented in
      `apps/nextjs/app/api/auth/auth-options.ts` (the lookup now selects `token`
      together with `usuario_id`; on update the stored dedicated token is kept).
      Tests: `app/api/auth/__tests__/auth-options.test.ts` (reuse of the existing
      dedicated token; regeneration for a legacy/non-dedicated value). Rails
      untouched, no schema change, trivial rollback.

### 4.2 Rails no longer requires the token — DONE (2026-09-14)

Chosen approach: the two Rails endpoints that used the token expose **public
course data**, so they no longer authenticate at all (no token, no session).

- [x] `cor1440_gen/proyectosfinancieros_controller#index/#show`: removed the
      `verificaToken` requirement (data is public; `walletAddress` only drives the
      `sinBilletera`/`conBilletera` filter).
- [x] Removed the unused `usuarios#actualiza_mi_usuario` endpoint (it had **no
      callers**), its route, and the now-unused
      `ApplicationHelper.usuarioBilleteraToken` / `verificaToken`.
- [x] Next stops sending the token to Rails (`app/[lang]/page.tsx`,
      `lib/hooks/useCourse.ts`); it still sends `walletAddress`.
- [ ] Deploy Rails + Next and verify (operator; Rails is not runnable in this VM).

### 4.3 Phase 2 (subtractive) — pending

- [ ] Remove `billetera_usuario.token`: migration to make it nullable, stop
      writing it in `authorize()`, then drop it.
- [ ] Remove `GET /api/auth/token`, `lib/auth-token.ts`, the `learn.tg.authToken`

- [ ] Migrate the E2E/non-browser specs to the session cookie.

### 4.4 Move the public course endpoints to Next — planned

Rails keeps only the backoffice (MSIP admin UI + Devise + `usuarios#foto` + its
share of the shared-schema migrations); the **public course API** moves to Next,
which already reads the same tables with Kysely (`lib/guide-utils.ts`,
`lib/course-access.ts`, `app/api/guide/route.ts`, `app/api/guide-status/route.ts`,
`app/api/courses/premium/*`).

- [x] Add `app/api/course-catalog` (list) and `app/api/course-catalog/[id]`
      (detail) reading `cor1440_gen_proyectofinanciero` /
      `cor1440_gen_actividadpf` directly, replicating the fields the frontend
      consumes (`titulo`, `subtitulo`, `idioma`, `prefijoRuta`, `imagen`,
      `resumenMd`, `creditosMd`, `porPagar`, `chain_id`, the
      `sinBilletera`/`conBilletera` filter and the `guias[]` array).
- [x] Point `app/[lang]/page.tsx` and `lib/hooks/useCourse.ts` at those Next
      routes, dropping `NEXT_PUBLIC_API_BUSCA_CURSOS_URL` /
      `NEXT_PUBLIC_API_PRESENTA_CURSO_URL` and the Rails CORS dependency for the
      public site.
- [x] Keep `walletAddress` only as an (untrusted) filter hint; no credential.
- [x] Do **not** delete `servidor/`: it is the admin backend (MSIP + `Cor1440Gen`,
      `Mr519Gen`, `Heb412Gen` mounted in `config/routes.rb`), Devise auth,
      `usuarios#foto`, and part of the schema migrations.

Rationale: after this, the public site talks only to Next (same-origin, no token,
no CORS) and Rails remains a pure backoffice. Independent of the Phase 2 token
removal.

## 5. Two-phase deployment

- **Additive phase:** Rails accepts the shared session (or a dedicated token)
  **in addition to** `billetera_usuario.token`; the column still exists but the new
  path is used. Monitor the `"No token"` / `"Different tokens"` logs for residual
  legacy usage.
- **Subtractive phase:** only once no legacy usage is observed, stop populating the
  column and then remove it (or leave it nullable/unused).

## 6. Audit of other pdJ clients

- Search the sivel and stable-sl repositories for uses of
  `billetera_usuario.token` (and of the token API in general).
- Document the findings and, if any client depends on the token, add a migration
  plan before the subtractive phase.

## 7. Acceptance criteria (OWASP gaps)

- [x] Rails endpoints no longer require a token: the course endpoints are
      **public** (no credential); `NEXTAUTH_SECRET` is not shared. (Chosen over
      "Rails per session": the data is public and the only other endpoint was
      unused.)
- [ ] No credential travels in the **URL/query**; if a token is still used, it goes
      in a header. (Closes R-#227 OWASP deviation 1.)
- [ ] The client **does not** persist credentials in `localStorage`. (Closes R-#227
      OWASP deviation 2.)
- [ ] The API token (if it still exists) has **short expiry and revocation**;
      `authorize()` does not rotate it (already the case since 2026-09-14).
      (Closes R-#227 OWASP deviation 3.)
- [ ] `NEXTAUTH_SECRET` is stable (not rotated across deploys/redeploys); rotating
      it invalidates every session and would break the migration.
- [ ] `billetera_usuario.token` is retired (or left nullable/unused) with the
      two-phase deployment of §5 and monitoring of the `"No token"` /
      `"Different tokens"` logs.
- [ ] Audit of other pdJ clients (§6) completed.
- [ ] E2E suite green incl. `premium-course-checkout`, `fresh-wallet-first-connect`,
      donations, and new tests for listing/detail/update-profile.
- [ ] Public course list/detail served by Next (`/api/courses`), not Rails
      (see §4.4).
- [ ] `audit-api-auth.mjs` with no regressions.
