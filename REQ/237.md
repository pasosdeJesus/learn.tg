### 1. Objective

Create `packages/pdj-wallet-next`, a Next.js-specific package that provides hooks and client components for the in-app wallet. It wraps `@learn-tg/pdj-wallet` with React state and UI.

### 4. Public API

```typescript
// packages/pdj-wallet-next/src/index.ts — real exports (2026-09-15)

export function useInAppWallet(): {
  status: 'loading' | 'no-wallet' | 'locked' | 'unlocked'
  walletInfo: WalletInfo | null
  error: string | null
  create: (pin: string) => Promise<WalletInfo>
  importExisting: (options: ImportWalletOptions) => Promise<WalletInfo>
  unlock: (pin: string) => Promise<WalletInfo>
  lock: () => Promise<void>
  remove: () => Promise<void>
  getProvider: () => Eip1193Provider | null
}

export { InAppWalletSetup } from './components/InAppWalletSetup'
export { InAppWalletUnlock } from './components/InAppWalletUnlock'
export { t, type Lang, type MessageKey } from './i18n'
export type { InAppWalletStatus, UseInAppWalletResult } from './useInAppWallet'
```

Note the real names: the import action is **`importExisting`** (not `import`,
which is a reserved word) and the hook also exposes **`error`**. Both components
take `lang?: 'en' | 'es'` plus a callback (`onDone(address)` for setup,
`onUnlocked(address)` for unlock). The package does not import learn.tg
internals: it has **no `@/` imports** (`grep -rn "from '@/" src` is empty).

### 5. Hook `useInAppWallet`

- `'use client'`.
- On mount, checks `hasWallet()`.
- If no wallet: `status = 'no-wallet'`.
- If wallet exists: `status = 'locked'`.
- After `unlock(pin)`: `status = 'unlocked'`, `walletInfo` set.
- After `lock()`: `status = 'locked'`, `walletInfo` cleared.
- After `remove()`: `status = 'no-wallet'`.
- `getProvider()` returns the EIP-1193 provider when unlocked, `null` otherwise.

**As implemented (important):** the state lives in a **module-level store** read
through `useSyncExternalStore`, so every instance of the hook agrees. Without it,
a component rendering `InAppWalletSetup` and the component consuming
`useInAppWallet()` kept separate copies and the UI looked broken after creating a
wallet (found in the operator's manual test on 2026-09-15, fixed in the same
branch). `resetInAppWalletStoreForTests()` exists for the test suite.

### 6. Component `InAppWalletSetup`

✅ Done (`src/components/InAppWalletSetup.tsx`, props `lang` and `onDone(address)`):

- Form: create new wallet OR import existing (mnemonic or private key).
- PIN input (6 digits, confirm), with mismatch and length validation.
- Warning: "Write down your recovery phrase. If you lose it, you lose access to your funds."
- On submit: calls `create` or `importExisting`.
- Shows recovery phrase after creation, with a copy button and a "continue" step.
- i18n support (en, es).

### 7. Component `InAppWalletUnlock`

✅ Done (`src/components/InAppWalletUnlock.tsx`, props `lang` and
`onUnlocked(address)`):

- PIN input (6 digits).
- Button "Unlock".
- Error on wrong PIN.
- i18n support (en, es).
