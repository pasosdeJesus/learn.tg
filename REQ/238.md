# R-#238: Integrate In-App Wallet in learn.tg


**Link:** https://github.com/pasosdeJesus/learn.tg/issues/238

**Status:** Proposal
**Created:** 2026-09-15
**Type:** Feature / Integration
**Priority:** High (blocks R-#242)
**Dependencies:** R-#236, R-#237

---

### 1. Objective

Integrate the in-app wallet into learn.tg's authentication flow, alongside the existing external wallet support. Create `WalletSelector` so users can choose between in-app and external wallets. Extend the wallet hooks (`useAuthAddress`, `useWallet`, `useWriteContract`) to work with the in-app wallet provider.

### 2. Changes

**New component `components/WalletSelector.tsx`:**

- `'use client'`.
- Uses `useInAppWallet()` and `useAuthAddress()`.
- If In-App Wallet is unlocked: shows address + disconnect.
- If In-App Wallet is locked: shows "Unlock" button.
- If no In-App Wallet: shows "Use in-app wallet" button + "Use external wallet" button (if `window.ethereum`).
- On choosing in-app: renders `InAppWalletSetup`.
- On choosing external: renders existing `ConnectWalletButton` logic.

**Extend `lib/hooks/useAuthAddress.ts`:**

- Add `inAppAddress` from `useInAppWallet()`.
- `address = sessionAddress || inAppAddress || storedAddress`.
- `isWalletAvailable = isInAppUnlocked || window.ethereum.eth_accounts().length > 0`.
- Add `isInAppUnlocked` flag.

**Extend `lib/hooks/useWallet.ts`:**

- `usePublicClient` and `useWalletClient` use `getInAppWalletProvider()` when the in-app wallet is unlocked, falling back to `window.ethereum`.

**Extend `lib/hooks/useWriteContract.ts`:**

- Use `getInAppWalletProvider()` when the in-app wallet is unlocked, falling back to `window.ethereum`.

**Extend `components/WalletEventListener.tsx`:**

- Listen for in-app wallet lock event.
- On lock: clear `sessionAddress`, call `signOut`.

**Update `components/Header.tsx`:**

- Replace `ConnectWalletButton` with `WalletSelector`.

**Update `doc/wallet-auth.md`:**

- Document the in-app wallet flow.
- Document `WalletSelector`.
- Document the provider EIP-1193.

### 3. Acceptance criteria

- [ ] `WalletSelector` exists and renders correctly in all states.
- [ ] `useAuthAddress` returns the in-app address when unlocked.
- [ ] `usePublicClient` and `useWalletClient` work with the in-app wallet.
- [ ] `useWriteContract` works with the in-app wallet.
- [ ] `WalletEventListener` signs out when the in-app wallet is locked.
- [ ] User can create an in-app wallet and sign in via SIWE.
- [ ] User can use an external wallet (existing flow preserved).
- [ ] `doc/wallet-auth.md` updated.
- [ ] E2E `fresh-wallet-first-connect` still passes.
