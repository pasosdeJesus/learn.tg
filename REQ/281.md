## 1. Problems (reported by the operator, 2026-10-06)

In the verifier dashboard, when the verifier edits a user (`/{lang}/admin` → user modal):

1. **The display name is not visible.** The modal edits the real `nombre` but never
   shows `nusuario`, the name the user publishes (it is what the leaderboard, the public
   profile and `name` in `/api/user/[id]` use). The verifier cannot tell the user's
   public identity.
2. **The yellow "User supplied this church info. Create it?" panel appears for
   non-Christians.** Choosing e.g. **Islam** still shows the panel (it is a
   **church**-creation control); it must appear only for Christians.
3. **"Assign Church" must disappear for non-Christians.**
4. **"Church Role" must disappear for non-Christians.**

"Christian" is `usuario.religion_id = 2` (see
[doc/church-registration.md](doc/church-registration.md)); the church role selector and
the church assignment only make sense for them.

## 2. Current behaviour

`UserEditModal` (`components/admin/AdminWidgets.tsx`):

- Initialises `nombre`, `email`, `pais_id`, `religion_id`, `place_of_worship`, … but
  **never `nusuario`** (the form has no display-name field).
- Renders **"Assign Church"** (`ChurchSelector`) unconditionally.
- Renders the yellow **"User supplied this church info. Create it?"** panel whenever
  `place_of_worship` and a country are set and there is no `church_id` — regardless of
  religion.
- Renders **"Church Role"** (`ChurchRoleSelect`) unconditionally.

## 3. Requirements

1. **Show the display name.** The modal shows the user's display name (`nusuario`) — at
   least read-only, next to the real name, so the verifier can identify the public
   identity. (Decide whether the verifier may edit it; the username is public and used
   in links, so read-only is the safe default.)
2. **Christians only for the church controls.** When the user is **not** a Christian
   (`Number(form.religion_id) !== 2`):
   - the yellow **"Create church"** panel does not render,
   - **"Assign Church"** does not render,
   - **"Church Role"** does not render.
3. **Keep the place-of-worship declaration for everyone.** The "Place of Worship" and
   "City of Place of Worship" fields stay for non-Christians: their declared place of
   worship feeds the profile score (9 points for non-Christians, see
   [doc/church-registration.md](doc/church-registration.md) §Profile score impact). Only
   the **church**-specific controls hide.
4. The condition reacts to the religion selector in the same modal (changing it to/from
   Christianity shows/hides the controls without reopening the modal).

## 4. Acceptance criteria

- [ ] The modal shows the user's display name (`nusuario`).
- [ ] With a non-Christian religion (e.g. Islam) selected: no yellow panel, no "Assign
      Church", no "Church Role".
- [ ] With `religion_id = 2` (Christian): the three church controls behave as today.
- [ ] The place-of-worship fields stay for non-Christians.
- [ ] `make type` and the affected suites green; `node bin/audit-api-auth.mjs` at
      `0 failed`; `node audit-crushrules.mjs` at 0 findings.

## 5. Testing

- `components/admin/__tests__/widgets.test.tsx` (or a new `UserEditModal` case):
  rendering the modal with `religion_id` 2 shows the three church controls; with a
  non-Christian religion they are absent and the display name is visible.
