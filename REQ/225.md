# R-#225: Configurable per-course price

**Enlace:** (pendiente — crear issue en GitHub pasosdeJesus/learn.tg)

**Created:** 2026-09-07

## 1. Objective

Hacer que el precio en USDT de un curso premium **se configure por curso en la
base de datos** y no en constantes del código. Cada curso guarda en
`cor1440_gen_proyectofinanciero` **dos países de referencia y sus dos precios
de referencia**, con los que se construye la curva lineal por HDI que hoy vive
hardcodeada en `packages/rewards/src/lib/premium-pricing.ts`.

Valores de referencia iniciales (curso Global Disciples):
**Sierra Leona → US$0.70** y **Colombia → US$3.00** (decisión 2026-09-07,
reemplaza los $2/$5 originales del R-#128 y la recalibración 0.7/3 a código).

Contexto actual a reemplazar:
`PRICE_A`/`PRICE_B` en `premium-pricing.ts` (puntos fijos 0.467→$0.70 y
0.788→$3) consumidos por `/api/courses/premium/price`, por el motor
`premiumPurchase` (validación de pago) y por el `CheckoutModal` (solo lectura
del precio de la API).

## 2. Design decisions

| Decision | Rationale |
|---|---|
| **Anclas en la misma fila del curso** | `cor1440_gen_proyectofinanciero` ya es el catálogo de cursos con `id`, `titulo`, `porPagar`, `chain_id`; evita una tabla extra y permite que cada curso (GD, otros premium) tenga su propia curva sin tocar código |
| **Curva lineal por HDI entre 2 puntos** | Misma fórmula del R-#128 (`p = A·hdi + B`, redondeo a 2 decimales), pero `A`/`B` derivados de los 2 países/precios de la fila del curso — cambia el *origen* de los datos, no el modelo matemático |
| **El HDI de cada país sale de `m_hdi`** | No se guardan HDIs en la fila del curso (evita duplicar datos que ya se actualizan por año); al leer se usa la fila más reciente de cada país de referencia |
| **Sin configuración → defaults** | Curso sin anclas usa los valores por defecto globales (Sierra Leona 0.70 / Colombia 3.00), igual al comportamiento actual: no hay regresión para cursos no migrados |
| **Cálculo siempre server-side** | El precio esperado se valida en `premiumPurchase` contra la DB en cada compra; el cliente solo muestra lo que devuelve la API (no se confía en el precio del navegador) |
| **Edición por ahora sin UI nueva** | Los valores se fijan con migraciones/scripts y quedan editables por el admin Rails existente; UI dedicada queda fuera de alcance (ver §7) |

## 3. Specification

### 3.1 Data model (migration on `cor1440_gen_proyectofinanciero`)

Nueva migración (única, aplicada a dev/mainnet) que agrega 4 columnas:

| Column | Type | Meaning |
|---|---|---|
| `precio_ref_pais1_id` | int (FK `msip_pais.id`) | País de referencia "bajo" (p. ej. Sierra Leona) |
| `precio_ref1_usd` | numeric(10,2) | Precio USDT del curso en ese país |
| `precio_ref_pais2_id` | int (FK `msip_pais.id`) | País de referencia "alto" (p. ej. Colombia) |
| `precio_ref2_usd` | numeric(10,2) | Precio USDT del curso en ese país |

Reglas:
- `precio_ref1_usd`/`precio_ref2_usd` > 0; los dos países deben existir y ser
  **distintos** (o la fila se considera sin configurar).
- Todos los campos NULL (default) ⇒ curso sin configuración propia.
- **Data migration:** la fila del curso Global Disciples se actualiza con
  Sierra Leona `→ 0.70` y Colombia `→ 3.00`.
- Regenerar `db/db.d.ts` con los nuevos campos.

### 3.2 Price calculation

Dado el curso `c` y el país del comprador con HDI `h`:

1. Cargar anclas de la fila: si las 4 columnas están seteadas usarlas; si no,
   usar los defaults (SL 0.70 / CO 3.00).
2. Resolver HDI de cada país de referencia y del país del comprador desde
   `m_hdi` (año más reciente). Si un país de referencia no tiene HDI ⇒ error
   config (500) claro; si el país del comprador no tiene HDI ⇒ 400 como hoy
   ("No HDI data for country").
3. `priceUSDT = round2( precio1 + (h − hdi1) · (precio2 − precio1) / (hdi2 − hdi1) )`
   (misma interpolación/extrapolación lineal que hoy; piso 0.01).
4. `priceSLEARN = round2(priceUSDT · rate · (1 − 0.10))` con `rate` leído del
   contrato SLEARN (`usdtToSlearnRate`, fallback 22) — sin cambios.

`premium-pricing.ts` pasa a **funciones puras parametrizadas**, p. ej.
`calculatePremiumPriceUsdt(hdi, refs)` con `refs = {hdi1, price1, hdi2, price2}`
y un `DEFAULT_REFS` (SL 0.7 / CO 3). Se eliminan `PRICE_A`/`PRICE_B` como
constantes globales: el código deja de ser la fuente de verdad de precios.

### 3.3 Endpoints/flows affected (sin cambio de contrato)

- `GET /api/courses/premium/price?courseId=…` — lee las anclas de ese curso
  (o defaults) en vez de las constantes; la respuesta conserva su forma actual
  (`priceUSDT`, `priceSLEARN`, `hdiUsed`, `country`) y puede añadir `courseId`.
- `POST …/premium/purchase` (motor rewards `premium-purchase.ts`) — calcula el
  `expectedPriceUSDT` del curso con las mismas anclas de DB antes de validar
  `totalValueUSDT ≥ expectedPriceUSDT − 0.01`.
- `CheckoutModal` / página del curso — sin cambios (consumen la API).
- Frontend `premium-price` (packages/rewards `dist`) — recompilar tras el
  cambio; los tests de la lib pasan a parametrizar las anclas.

### 3.4 Configuración (cómo se cambia un precio después)

1. Actualizar las columnas de la fila del curso (admin Rails / SQL / script
   `bin/` documentado), p. ej. subir Colombia a $4 sin tocar código.
2. El cambio es inmediato: precio/validación leen la DB por request.

### 3.5 Tests

- **Unidad (`packages/rewards`)**: `premium-pricing` con anclas parametrizadas
  (SL 0.467→0.70, CO 0.788→3.00 como caso GD; un caso no-GD con anclas
  distintas; extrapolación fuera del rango; piso 0.01; SLEARN 10 % descuento).
- **Motor `premium-purchase`**: pago insuficiente por debajo del precio
  derivado de anclas mockeadas del curso (0.5 USDT < 0.70 con anclas GD);
  curso sin anclas → defaults.
- **App (route price)**: respuesta correcta con anclas en DB mockeadas y
  fallback a defaults; país sin HDI → 400.

## 4. Acceptance criteria

- [ ] `cor1440_gen_proyectofinanciero` tiene las 4 columnas de anclas (2
      países + 2 precios) con la migración aplicada en dev y mainnet
- [ ] La fila del curso Global Disciples queda configurada: Sierra Leona
      $0.70 y Colombia $3.00 (fuente: DB, no código)
- [ ] No existen `PRICE_A`/`PRICE_B` globales; el precio de un curso se
      deriva de sus anclas (o de los defaults SL 0.7/CO 3 si no configura)
- [ ] `/api/courses/premium/price` devuelve $0.70 para un usuario de SL y $3
      para uno de CO en el curso GD (con los `m_hdi` 2023 vigentes)
- [ ] `premiumPurchase` rechaza pagos < precio esperado del curso y acepta ≥
      (validación contra anclas del curso)
- [ ] Cambiar solo los precios en la DB (sin redeploy de código) modifica el
      precio mostrado y el validado
- [ ] Suite rewards y tests de la ruta de precio en verde; `dist` recompilado
- [ ] REQ/128 y `premium-pricing` docs actualizados (mencionan configuración
      por curso; la tabla de precios pasa a ser "ejemplo con anclas GD")

## 5. Out of scope (for now)

- UI/endpoint admin para editar las anclas desde el sitio (se usa el admin
  Rails existente o migraciones/scripts)
- Precio en monedas locales / descuentos por país distintos del modelo HDI
- `priceSLEARN` específico por curso con tasa propia (sigue la tasa global)
- Validaciones antifraude nuevas (solo se mueve el origen del precio)
