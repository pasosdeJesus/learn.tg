# R-#225: Configurable per-course price

**Link:** (pending — create the issue in GitHub `pasosdeJesus/learn.tg`)

**Status:** Pending
**Created:** 2026-09-07

---

## 1. Objective

Make a premium course's USDT price **configurable per course in the database**
instead of in code constants. Each course stores **two reference countries and
their two reference prices** in `cor1440_gen_proyectofinanciero`, and those build
the linear HDI curve that today is hardcoded in
`packages/rewards/src/lib/premium-pricing.ts`.

Initial reference values (Global Disciples course):
**Sierra Leone → US$0.70** and **Colombia → US$3.00** (decision 2026-09-07,
replacing the original $2/$5 of R-#128 and moving the 0.7/3 recalibration into
data).

Current context being replaced: `PRICE_A`/`PRICE_B` in `premium-pricing.ts`
(fixed points 0.467→$0.70 and 0.788→$3), consumed by
`/api/courses/premium/price`, by the `premiumPurchase` engine (payment
validation) and by `CheckoutModal` (read-only price from the API).

## 2. Design decisions

| Decision | Rationale |
|---|---|
| **Anchors on the course row itself** | `cor1440_gen_proyectofinanciero` already is the course catalog with `id`, `titulo`, `porPagar`, `chain_id`; it avoids an extra table and lets each course (GD, other premium ones) have its own curve without touching code |
| **Linear HDI curve between 2 points** | Same formula as R-#128 (`p = A·hdi + B`, rounded to 2 decimals), but `A`/`B` derived from the course row's 2 countries/prices — the *origin* of the data changes, not the mathematical model |
| **Each country's HDI comes from `m_hdi`** | HDIs are not stored on the course row (avoids duplicating data that is updated yearly); reading uses the most recent row per reference country |
| **No configuration → defaults** | A course without anchors uses the global defaults (Sierra Leone 0.70 / Colombia 3.00), matching current behaviour: no regression for non-migrated courses |
| **Always computed server-side** | The expected price is validated in `premiumPurchase` against the DB on every purchase; the client only shows what the API returns (the browser price is never trusted) |
| **No new UI for now** | Values are set with migrations/scripts and remain editable through the existing Rails admin; a dedicated UI is out of scope (see §7) |

## 3. Specification

### 3.1 Data model (migration on `cor1440_gen_proyectofinanciero`)

One new migration (applied to dev/mainnet) adding 4 columns:

| Column | Type | Meaning |
|---|---|---|
| `precio_ref_pais1_id` | int (FK `msip_pais.id`) | "Low" reference country (e.g. Sierra Leone) |
| `precio_ref1_usd` | numeric(10,2) | Course USDT price in that country |
| `precio_ref_pais2_id` | int (FK `msip_pais.id`) | "High" reference country (e.g. Colombia) |
| `precio_ref2_usd` | numeric(10,2) | Course USDT price in that country |

Rules:
- `precio_ref1_usd`/`precio_ref2_usd` > 0; both countries must exist and be
  **different** (otherwise the row counts as not configured).
- All fields NULL (default) ⇒ the course has no configuration of its own.
- **Data migration:** the Global Disciples course row is set to Sierra Leone
  `→ 0.70` and Colombia `→ 3.00`.
- Regenerate `db/db.d.ts` with the new fields.

### 3.2 Price calculation

Given course `c` and the buyer's country with HDI `h`:

1. Load the row anchors: if all 4 columns are set use them; otherwise use the
   defaults (SL 0.70 / CO 3.00).
2. Resolve the HDI of each reference country and of the buyer's country from
   `m_hdi` (most recent year). If a reference country has no HDI ⇒ clear config
   error (500); if the buyer's country has no HDI ⇒ 400 as today ("No HDI data
   for country").
3. `priceUSDT = round2( price1 + (h − hdi1) · (price2 − price1) / (hdi2 − hdi1) )`
   (same linear interpolation/extrapolation as today; floor 0.01).
4. `priceSLEARN = round2(priceUSDT · rate · (1 − 0.10))` with `rate` read from the
   SLEARN contract (`usdtToSlearnRate`, fallback 22) — unchanged.

`premium-pricing.ts` becomes **parameterized pure functions**, e.g.
`calculatePremiumPriceUsdt(hdi, refs)` with `refs = {hdi1, price1, hdi2, price2}`
and a `DEFAULT_REFS` (SL 0.7 / CO 3). `PRICE_A`/`PRICE_B` as global constants are
removed: code stops being the source of truth for prices.

### 3.3 Endpoints/flows affected (no contract change)

- `GET /api/courses/premium/price?courseId=…` — reads that course's anchors (or
  the defaults) instead of the constants; the response keeps its current shape
  (`priceUSDT`, `priceSLEARN`, `hdiUsed`, `country`) and may add `courseId`.
- `POST …/premium/purchase` (rewards engine `premium-purchase.ts`) — computes the
  course's `expectedPriceUSDT` with the same DB anchors before validating
  `totalValueUSDT ≥ expectedPriceUSDT − 0.01`.
- `CheckoutModal` / course page — unchanged (they consume the API).
- Frontend `premium-price` (packages/rewards `dist`) — recompile after the
  change; the library tests become anchor-parameterized.

### 3.4 Configuration (how a price is changed later)

1. Update the course row's columns (Rails admin / SQL / documented `bin/`
   script), e.g. raise Colombia to $4 without touching code.
2. The change is immediate: both the displayed price and the validation read the
   DB per request.

### 3.5 Tests

- **Unit (`packages/rewards`)**: `premium-pricing` with parameterized anchors
  (SL 0.467→0.70, CO 0.788→3.00 as the GD case; a non-GD case with different
  anchors; extrapolation outside the range; floor 0.01; SLEARN 10 % discount).
- **`premium-purchase` engine**: insufficient payment below the price derived
  from the course's mocked anchors (0.5 USDT < 0.70 with GD anchors); course
  without anchors → defaults.
- **App (price route)**: correct response with mocked DB anchors and fallback to
  defaults; country without HDI → 400.

## 4. Acceptance criteria

- [ ] `cor1440_gen_proyectofinanciero` has the 4 anchor columns (2 countries +
      2 prices) with the migration applied on dev and mainnet
- [ ] The Global Disciples course row is configured: Sierra Leone $0.70 and
      Colombia $3.00 (source: DB, not code)
- [ ] No global `PRICE_A`/`PRICE_B` remain; a course's price derives from its
      anchors (or the SL 0.7/CO 3 defaults when unconfigured)
- [ ] `/api/courses/premium/price` returns $0.70 for a Sierra Leone user and $3
      for a Colombian one on the GD course (with the current 2023 `m_hdi`)
- [ ] `premiumPurchase` rejects payments below the course's expected price and
      accepts ≥ (validated against the course anchors)
- [ ] Changing only the prices in the DB (no code redeploy) changes both the
      displayed and the validated price
- [ ] Rewards suite and the price-route tests green; `dist` recompiled
- [ ] REQ/128 and the `premium-pricing` docs updated (they mention per-course
      configuration; the price table becomes "example with GD anchors")

## 5. Out of scope (for now)

- Admin UI/endpoint to edit the anchors from the site (the existing Rails admin,
  migrations or scripts are used)
- Prices in local currencies / per-country discounts different from the HDI model
- Course-specific `priceSLEARN` with its own rate (the global rate still applies)
- New anti-fraud validations (only the origin of the price moves)
