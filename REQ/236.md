### 1. Objective

Create `packages/pdj-wallet`, a framework-agnostic TypeScript library for a self-custodied in-app wallet. It handles:

- Wallet creation (new mnemonic) and import (existing mnemonic or private key).
- Encryption with AES-256-GCM + PBKDF2 (600,000 iterations).
- Storage in IndexedDB (browser), memory (tests), file (Node.js E2E).
- Message signing (`signMessage`), transaction signing (`signTransaction`), typed data signing (`signTypedData`), and SIWE signing (`signSIWE`).
- Export of mnemonic and private key (PIN-protected).

The library must be usable from Next.js, from Node.js E2E tests, and (in the future) from sivel3 and stable-sl.

### 4. Public API

```typescript
// packages/pdj-wallet/src/index.ts — real exports (2026-09-15)

export interface WalletInfo {
  address: `0x${string}`          // checksummed (EIP-55)
  chain: ChainName                // 'celo' | 'celoSepolia' (DEFAULT_CHAIN = celoSepolia)
  createdAt: number
}

export interface CreateWalletOptions {
  pin: string
  chain?: ChainName
  storage?: StorageAdapter
}

export interface ImportWalletOptions {
  mnemonic?: string
  privateKey?: `0x${string}`
  pin: string
  chain?: ChainName
  storage?: StorageAdapter
}

// Lifecycle
export async function createWallet(options: CreateWalletOptions): Promise<{ walletInfo: WalletInfo; mnemonic: string }>
export async function importWallet(options: ImportWalletOptions): Promise<WalletInfo>
export async function unlockWallet(pin: string, storage?: StorageAdapter): Promise<WalletInfo>
export async function lockWallet(): Promise<void>
export async function deleteWallet(storage?: StorageAdapter): Promise<void>
export async function hasWallet(storage?: StorageAdapter): Promise<boolean>
export async function getWalletInfo(storage?: StorageAdapter): Promise<WalletInfo | null>

// PIN-protected export (no side effects on the session)
export async function exportMnemonic(pin: string, storage?: StorageAdapter): Promise<string>
export async function exportPrivateKey(pin: string, storage?: StorageAdapter): Promise<`0x${string}`>

// Session state (module-level; added for the provider and for callers that need
// to know whether a key is in memory)
export function isUnlocked(): boolean
export function getUnlockedAccount(): InAppWallet['account'] | null
export function getUnlockedInfo(): WalletInfo | null

// Signing (only while unlocked)
export async function signMessage(message: string | { raw: `0x${string}` }): Promise<`0x${string}`>
export async function signTypedData(typedData: Record<string, unknown>): Promise<`0x${string}`>
export async function signTransaction(tx: Record<string, unknown>): Promise<`0x${string}`>
export async function signSIWE(message: string): Promise<`0x${string}`>

// Provider, crypto and signer helpers
export function getInAppWalletProvider(options?: ProviderOptions): Eip1193Provider | null
export async function encryptSecret(plaintext: string, pin: string): Promise<EncryptedSecret>
export async function decryptSecret(secret: EncryptedSecret, pin: string): Promise<string>
export const KDF_ITERATIONS = 600_000
export function newMnemonic(): string
export function normalizeMnemonic(mnemonic: string): string
export function addressFromMnemonic(mnemonic: string, index = 0): `0x${string}`
export function privateKeyFromMnemonic(mnemonic: string, index = 0): PrivateKey
export function accountFromMnemonic(mnemonic: string, index = 0)
export function accountFromPrivateKey(privateKey: PrivateKey)

// Storage and types
export { MemoryStorage } from './storage/memory'
export { IndexedDBStorage } from './storage/indexeddb'
export { CHAIN_IDS, DEFAULT_CHAIN } from './types'
export type {
  ChainName, CreateWalletOptions, ImportWalletOptions, StorageAdapter,
  StoredWallet, WalletInfo, Eip1193Provider, Eip1193RequestArgs,
} from './types'
```

**What is encrypted:** a JSON payload with the private key and, when there is one,
the recovery phrase (`{ v: 1, privateKey, mnemonic? }`). The phrase is kept
because it cannot be derived from the private key and `exportMnemonic` has to
return it. Records written before this format (bare private key ciphertext) still
unlock: `parseSecret` accepts both.

**Where `FileStorage` lives:** it is exported by the `./storage` subpath
(`import { FileStorage } from '@learn-tg/pdj-wallet/storage'`) and **not** by the
package root, because it imports `node:fs/promises`: keeping it out of the root
avoids dragging `node:` builtins into a browser bundle.

**Nothing is left out of the original API**: `exportMnemonic`,
`exportPrivateKey` and `FileStorage` were implemented on 2026-09-15 (§6, §10).

### 5. Encryption

✅ Done as planned (`src/crypto.ts`, 100 lines):

- **Algorithm:** AES-256-GCM (`encryptSecret` / `decryptSecret`).
- **Key derivation:** PBKDF2, 600,000 iterations, SHA-256, 16-byte salt
  (exported as `KDF_ITERATIONS`, asserted by `crypto.test.ts`).
- **IV:** 12 bytes, random per encryption (a fresh salt and IV each time,
  `crypto.test.ts`).
- **Web Crypto API** (`crypto.subtle`) for browser and Node.js (Node 18+ has `crypto.subtle`).
- A wrong PIN fails closed, and the decrypted key is checked against the stored
  address before it is used.
- **Argon2id** documented as future evolution (no implementation in MVP).

### 7. Provider EIP-1193

`getInAppWalletProvider()` returns a provider that supports:

- `eth_requestAccounts` / `eth_accounts` → returns `[address]`.
- `eth_chainId` → returns the chain ID in hex.
- `personal_sign` → signs with `signMessage`.
- `eth_sendTransaction` → signs with `signTransaction` and broadcasts.
- `wallet_switchEthereumChain` → no-op (always on the configured chain).

This provider is used by `usePublicClient`, `useWalletClient`, and `useWriteContract` in learn.tg when the in-app wallet is unlocked.

**As implemented** (`src/provider.ts`): `getInAppWalletProvider(options?)` returns
`null` while the wallet is locked (it reads the module session) and otherwise a
provider flagged `isPdJWallet: true` that answers `eth_requestAccounts`,
`eth_accounts`, `eth_chainId`, `net_version`, `wallet_switchEthereumChain`
(no-op), `personal_sign`, `eth_signTypedData_v4`, `eth_signTransaction`,
`eth_sendTransaction` and `wallet_getCapabilities`. `eth_sendTransaction`
requires the provider to be created with `rpcUrl` (it signs and POSTs
`eth_sendRawTransaction`); any other method rejects. `on`/`removeListener` are
no-ops. Covered by `provider.test.ts` (5 tests).

### 8. Signing

✅ Done as planned:

- `viem` is used for message signing, transaction signing and typed data signing
  (`src/signer.ts` derives the account from the mnemonic or the private key).
- `signSIWE(message)` uses `signMessage` with EIP-191 wrapping.
- The private key is decrypted into memory only while the wallet is unlocked;
  `lockWallet()` and `deleteWallet()` wipe it, and any signing call while locked
  rejects.

  to 11 here (the repo is pinned to pnpm 10). The package `test` script calls
  `../../apps/nextjs/node_modules/.bin/vitest run --config vitest.config.ts`
  directly, so it works without pnpm.
