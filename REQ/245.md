# R-#245: Testing plan for `pdj-wallet` packages

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/245

**Status:** Proposal
**Created:** 2026-09-15
**Type:** Testing / Documentation
**Priority:** High (blocks the R-#244 verification)
**Dependencies:** R-#236, R-#237

---

### 1. Objective

Define the testing strategy for the `pdj-wallet` packages so that tests are fast (<5 min automated), lightweight (<1 GB RAM), and runnable on OpenBSD/adJ. Avoid the 45-minute full E2E suite for wallet-only changes.

### 2. Testing layers

| Layer | Scope | Tool | Time | Memory |
|---|---|---|---|---|
| **Unit (core)** | `pdj-wallet` functions | Vitest | seconds | <1 GB |
| **Unit (next)** | `pdj-wallet-next` hooks/components | Vitest + Testing Library | seconds | <1 GB |
| **Integration (learn.tg)** | `useAuthAddress`, `WalletSelector`, `useWriteContract` | Vitest (existing) | seconds | <1 GB |
| **E2E (minimal)** | In-app wallet flow on dev site | Puppeteer (existing) | ~30 s | <1 GB |
| **Manual (PWA)** | Service worker, offline | Chrome mobile | minutes | — |

### 3. Commands

**Reality check (verified 2026-09-15):** engine packages have no
`vitest.config.ts` and their `package.json` `test` script points to a file that
does not exist, so `pnpm test` inside a package fails; on top of that, corepack
resolves pnpm 11 here, which this repo does not support (it is pinned to pnpm
10). Run the package tests from `apps/nextjs`, which owns the dependency graph:

```bash
# Core wallet (fast)
cd apps/nextjs && ./node_modules/.bin/vitest run \
  --root ../../packages/pdj-wallet --config ./vitest.config.ts

# Next components (fast)
cd apps/nextjs && ./node_modules/.bin/vitest run \
  --root ../../packages/pdj-wallet-next --config ./vitest.config.ts

# Integration in learn.tg (fast)
cd apps/nextjs && make test-hooks test-components

# Minimal E2E (fast)
cd apps/nextjs && CHROME_PATH=/usr/local/bin/chrome make test-e2e-spec SPEC=in-app-wallet

# Full E2E (slow, regression only)
cd apps/nextjs && CHROME_PATH=/usr/local/bin/chrome make test-e2e
```

Note: the engine package `test` scripts in `packages/rewards` and
`packages/gdcluster` are broken the same way; fixing them (adding a
`vitest.config.ts` that extends the app's) is a prerequisite worth doing while
creating the new packages.

### 4. Test data

**Fixtures:**

- Known mnemonic: `test test test test test test test test test test test junk` (Hardhat default).
- Known private key: `0xac0974...` (Hardhat default).
- Known SIWE message: `example.com wants you to sign in...`.

**Storage:**

- `MemoryStorage` for unit tests.
- `FileStorage` for E2E (Node.js).
- `fake-indexeddb` for `IndexedDBStorage` unit tests (not yet a dependency — add it as a devDependency of `packages/pdj-wallet`).

**RPC:**

- Mock RPC for `getInAppWalletProvider` unit tests.
- Celo Sepolia for E2E.

### 5. Minimal E2E spec

**File:** `e2e/specs/in-app-wallet.spec.mjs`

**Steps:**

1. Launch browser.
2. Go to `learn.tg:9001/en/test/wallet`.
3. Create wallet (PIN: `123456`).
4. Get the address.
5. Build SIWE message.
6. Sign with in-app wallet.
7. POST to `/api/auth/callback/credentials`.
8. Verify session cookie set.
9. Go to `/en/profile`.
10. Verify address displayed.

**Time:** ~30 s.

### 6. Test page for manual development

**File:** `app/[lang]/test/wallet/page.tsx`

**Purpose:** a simple page that creates a wallet, signs SIWE, and displays the result. Used for manual development and debugging.

**Not for production:** the page must be removed or gated before production.

### 7. Documentation

**File:** `doc/pdj-wallet-testing.md`

**Content:**

- How to run unit tests.
- How to run the minimal E2E spec.
- How to test manually the service worker.
- How to test manually offline guide and crossword.
- Troubleshooting (OpenBSD-specific issues).

### 8. Acceptance criteria

- [ ] `packages/pdj-wallet` has unit tests; the package suite passes in <10 s (run from `apps/nextjs`, see §3).
- [ ] `packages/pdj-wallet-next` has unit tests; the package suite passes in <10 s (run from `apps/nextjs`, see §3).
- [ ] `e2e/specs/in-app-wallet.spec.mjs` exists and passes in <1 min (CHROME_PATH + IPDES/PUERTOPRU as in doc/e2e-testing.md).
- [ ] `app/[lang]/test/wallet/page.tsx` exists for manual development.
- [ ] `doc/pdj-wallet-testing.md` published.
- [ ] Total automated test time <5 min.
- [ ] Total memory <1 GB per test run.
