# R-#286: Reconcile scholarships in the database and the chain

Keep the local record of crossword scholarships (`transaction`, one row per token) in
agreement with the chain, so a guide the vault already paid never looks *unpaid* and the
platform stops sending no-op transactions.

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/286
**Created:** 2026-10-15
**Status:** In progress — the handler change, the engine helper and the reconciliation script
landed (2026-10-15); the backlog run on production is pending.
**Type:** Bug / Data
**Priority:** Medium — the payment is not lost (the vault refuses the duplicate), but the
learner sees the guide as unpaid and the platform pays gas for a transaction that pays nothing.

---

## 1. What happened (measured 2026-10-15)

A learner solved guide G4 (`actividadpf_id = 14`) of course 2 ("A relationship with Jesus").
The vault answered `ScholarshipAlreadyPaid(2, 14, 0x2e2c…)` and the transaction moved **no**
tokens (`token_transfers: []`), while the course's guide list showed the guide **without the
USDT icon**.

`app/api/guide-status/route.ts` decides the icon from `transaction`
(`type='scholarship' AND crypto='usdt' AND metadata->>'guideId' = <actividadpf_id>`), a
deliberate change (https://github.com/pasosdeJesus/learn.tg/issues/279) from
`guide_usuario.amountpaid`, which mixes tokens and produced a false USDT icon on a
SLEARN-only payment. The gap: payments made **before** that per-token recording existed, or
**migrated from an older vault**, are marked paid on-chain
(`guidePaidUSDT`/`guidePaidSLEARN`) without a local row.

Measured for guide 14: the local `slearn` row exists (`0x0e7e2540…`, a **V4** transaction that
paid **SLEARN only**), there is **no `usdt` row**, and `guide_usuario.amountpaid = 680000`
(0.68 USDT). The V4→V5 seed (`scripts/verify-v5-migration.ts`,
`db/backups/v4-guidepaid-*.csv`) is what marked the guide paid on-chain.

## 2. Fixes

**a) The handler reconciles on every submission**
(`packages/rewards/src/routes/check-crossword.ts`). The old "safety net" required **both**
tokens in `transaction`; now the **chain is the authority**:

1. If a token is paid on-chain (`getStudentGuideStatus`) and has no row, the row is written
   (`recordMissingScholarshipRows`).
2. If **both** tokens are already paid, the vault is **not called** (no more no-op
   `ScholarshipAlreadyPaid` transaction) and the learner is told the guide was already paid
   (`msg[locale].scholarshipPaid`, `alreadyPaid: true`).

**b) Backlog**: `apps/nextjs/scripts/reconcile-scholarships.ts`. It walks the addresses already
in the database (`billetera_usuario` × `guide_usuario`, `points = 1`), reads
`getStudentGuideStatus` on the **active** vault (amounts) and the explorer **by address** (the
proof `hash`), and writes the missing rows. Dry-run by default; `--fix` writes; `--wallet`,
`--course`, `--limit`, `--concurrency`, `--no-hashes`. What it cannot prove is **reported**,
never invented.

The hash is the on-chain proof, so it is recorded: the script lists the wallet's incoming
USDT/SLEARN transfers (paged by the explorer), reads each transaction and, when its method is
`payScholarship`, takes `(courseId, guideId, student)` from the decoded parameters. That also
finds the **historical vaults** (V3/V4) without listing them by hand, and needs **no block
scanning** (which is what made the old `--scan` mode expensive). A payment may move both tokens
in one transaction or be paid in two (partial payments), so the hash is kept **per token**.

## 4. Verification

`packages/rewards` `tsc -b` clean and `87 tests` green; app `tsc --noEmit` clean; the
`check-crossword` route test 17/17. Dry run against Celo mainnet for the affected wallet:
23 candidates, 17 with an on-chain payment, **7 with a missing row**, of which **5 recovered
their proof hash** and **2 were reported without a hash** (the USDT of course 2/guide 14 and
course 105/guide 112).

The script also prints the environment it resolved (`NEXT_PUBLIC_NETWORK`, `PGDATABASE`, the
RPC origin, the explorer and the **token addresses of the `.env` against the vault's**
`usdtToken()`/`slearnToken()`), and checks the **reverse** direction (a local row with no
on-chain backing) as a report. Running the local copy against mainnet shows this mismatch,
which is the same shape of bug that makes the wallet panel show USDT as zero — the panel uses
the `NEXT_PUBLIC_*` addresses, the vault uses its own:

```
  USDT  env                 0x0d130F97…556a6   <-- NO COINCIDE   (Sepolia)
  USDT  vault.usdtToken()   0x48065fbB…483D5e                     (mainnet)
```
