# R-#209: F-#209 Problem donating for country fund from en/gdcluster/ranking in development site

## Problem Description
In development sites, routing GD scholarship funds to `ClusterFunds` frequently fails with a "Nonce provided for the transaction is lower than the current nonce" error. 

**Initial Symptoms (Server Console):**
```
USDT transferred to ClusterFunds: 10000000, tx: 0xdd412b353feaf94252442ada2ca08fa1b1946bdcc9fe5fb6d05fa41f77fb6d5e
POST /api/gdcluster/donations/verify 500 in 2.5s
⨯ unhandledRejection: Error: invalid type: boolean `true`, expected enum CodeFrameColorMode
```

## Investigation Findings
The root cause in development appears to be concurrent transaction execution without proper sequential nonce management in `routeToClusterFunds`. When multiple transactions (e.g., token transfers and contract interaction) are sent rapidly, the backend wallet client doesn't wait for the previous transaction's nonce to be updated on-chain.

**Mitigation:** 
Implemented manual nonce management in `routeToClusterFunds` (`lib/gd-cluster-routing.ts`) by fetching the pending nonce and incrementing it sequentially for each step. Diagnostic logs (`[gd-debug]`) were added to track transaction flow and nonce values to facilitate further troubleshooting if issues persist.

**Note:** Production seems unaffected, suggesting the issue may be exacerbated by network latency or local environment configurations (e.g., rapid node response times) in development setups.
