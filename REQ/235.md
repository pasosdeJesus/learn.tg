## 1. Objective

Give **every page and component one single, standard mechanism** for
authenticated, same-origin API calls, replacing the ad-hoc per-page
`walletAddress`/`token` query building and the cold-session workarounds. The
mechanism must be robust for real users **without environment or test hacks**
(a real user does not have `MOCK_COURSE_LIST` or any special flag).

## 2. The mechanism

`lib/hooks/useAuthedApi.ts`:

- **Identity**: the NextAuth session address, with the `localStorage` fallback
  for the cold-session bug (https://github.com/pasosdeJesus/learn.tg/issues/208,
  NextAuth #5719), via `useAuthAddress`.
- **`ready`**: false while a connected user's address has not resolved yet, so
  pages **wait** instead of firing an anonymous request (the cause of the false
  "cooldown" and 0% progress).
- **`mismatch`**: detects a partial login (session vs localStorage fallback
  point to different wallets) so pages stop instead of mixing state.
- **`withWallet`**: appends only the identity hint (`walletAddress`) to a URL.
- **`authedGet` / `authedPost` / `authedPatch` / `authedDelete`**: same-origin
  requests that authorize through the **session cookie**. Mutations add
  `walletAddress` to both the query and the body (routes read it from either
  place). **No token is ever sent by the app.**

Rationale: the session cookie is the credential (R-#227/R-#233); the token was
only a legacy fallback for non-browser clients. Dropping it from the client
removes R-#227 OWASP deviations 1 (credential in URL) and 2 (credential in
`localStorage`).
