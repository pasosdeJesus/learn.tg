# R-#255: Admin entry in the header menu for verifier wallets

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/255 (create it from this
file if it does not exist yet)

**Status:** Implemented (2026-09-21, branch `mvppwa`) — the ☰ menu shows **Admin**
(`/{lang}/admin`) only for a wallet listed in `NEXT_PUBLIC_VERIFIER_WALLET`, in both
languages, and no request is made to decide it. Covered by `Header.test.tsx`
(7 tests: verifier, non-verifier, guest) and `make type` is green.
**Created:** 2026-09-21
**Type:** UX
**Priority:** Low-Medium — the verifier UI works and is reachable by URL, but a
verifier who does not remember `/{lang}/admin` has no way to find it.
**Dependencies:** R-#227 (admin auth), R-#213 (verifier dashboard)

---

## 1. Objective

A wallet listed in `NEXT_PUBLIC_VERIFIER_WALLET` should see an **Admin** entry in
the header menu (☰) that opens `/{lang}/admin`, in English and Spanish, and only
while it is authenticated.

## 2. What exists today

- `/{lang}/admin` (with `users`, `churches` and the calendar) is a verifier-only
  page: it compares the session address against `NEXT_PUBLIC_VERIFIER_WALLET` and
  renders "access denied" otherwise.
- The header menu (`components/Header.tsx`) lists Courses, Leaderboard,
  Transparency, Referrals and, with a session, Profile and the Lensenia donation
  page. Nothing points at the admin area, so the verifier has to type the URL.
- `GET /api/admin/check-verifier` exists (public by design) but the header already
  has the address, so no extra request is needed.

## 3. Decision

- Detect the verifier **client-side** with the same rule the admin pages use:
  the session address (or the `learn.tg.sessionAddress` fallback of #5719)
  lowercased, compared against the `NEXT_PUBLIC_VERIFIER_WALLET` list.
- Add the entry only when authenticated and the address is a verifier, so an
  anonymous visitor never sees it (the page keeps its own server-side check; the
  menu is convenience, not a security control).
- Label from the shared i18n dictionary (`navAdmin`), English and Spanish.

## 4. Acceptance criteria

- [x] A verifier wallet with a session sees "Admin" in the ☰ menu and it opens
      `/{lang}/admin` (both languages).
- [x] A non-verifier authenticated wallet and an anonymous visitor do not see it.
- [x] No extra network request is made to decide (no `/api/admin/check-verifier`
      call from the header).
- [x] Unit test covers the three cases (verifier, non-verifier, anonymous).
- [x] `make type` green.

## 5. Out of scope

- Moving the verifier UI or changing its authorization (R-#227 rules stand).
- A verifier dashboard inside the wallet panel.
