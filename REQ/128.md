# #128: Premium Course Payments with Dynamic Pricing (Actualizado)

Enable users to purchase premium courses using the already-deployed `SLEARN.processPayment()` function (from I129). Add dynamic pricing based on user's country (HDI). No contract changes needed — all logic is already in SLEARN.sol from I129.

**Depends on:** I129 (SLEARN token launch, contracts deployed and operational), #155 (ClusterFunds for GD course), #196 (LearnTGVaultsV5 for scholarship split)

**Supersedes:** #148 task 1 (premium course payments with SLEARN) — this is now the authoritative payment spec; #148 tracks the remaining post-launch features (burn, stable-sl swap, church distribution, transparency, governance). The referral program is tracked in #163.

---

## Summary of Key Decisions

| Decision | Details |
| :--- | :--- |
| **Payment method** | Mixed USDT + SLEARN (same `SLEARN.processPayment()` used for donations) |
| **Price calculation** | Linear `p = A*hdi + B`, calibrated to Sierra Leone ($2) and Colombia ($5). SLEARN price = USDT price × 22 × 0.90 (10% discount) |
| **Distribution percentages (Standard)** | Premium payment distribution (50% pdJ, 10% vault, 10% reward, 10% missional, 5% UBI, 10% referrals, 5% churches) — per SLEARN-WHITEPAPER.md §3.1.2. Referrals raised to 10% (funded from pdJ, NOT from scholarships). |
| **Distribution percentages (GD)** | Global Disciples course: 40% pdJ, 10% Cluster/Country Fund, 10% vault, 10% reward, 10% missional, 5% UBI, 10% referrals, 5% churches. The cluster 10% is routed off-chain via `ClusterFunds.sol` (#155) (see §1.3). |
| **SLEARN burning** | Handled inside `SLEARN.processPayment()` (user's SLEARN are burned, reserve USDT released) |
| **Access control** | After payment, a record in `premium_course_usuario` grants access to the course guides |
| **UI** | Show price in SLEARN, allow user to choose mixed payment (slider) |
| **HDI Source** | `m_hdi` table (pais_id, year, hdi) — already populated from OWID CSV |

## 1. Backend Changes (learn.tg)

### 1.1 Dynamic Price Calculation

**File:** `app/api/courses/premium/price/route.ts` (new)

**Input:** `courseId`, `userWallet` (JWT authenticated)

**Output:** `priceUSDT`, `priceSLEARN`, `hdiUsed`, `country`

**Logic:**
```typescript
// 1. Get user's country from KYC (self.xyz verification)
const country = await getUserCountry(userWallet);

// 2. Get HDI for country from m_hdi table
const hdi = await getHDI(country.pais_id, 2022); // Use latest year

// 3. Calculate USDT price with the two-point linear formula
//    p = A * hdi + B, calibrated so:
//      Sierra Leone (hdi 0.467) → $2
//      Colombia     (hdi 0.788) → $5
const A = (5 - 2) / (0.788 - 0.467);
const B = 2 - A * 0.467;
const priceUSDT = A * hdi + B;

// Round to 2 decimal places
const roundedPriceUSDT = Math.round(priceUSDT * 100) / 100;

// 4. Convert to SLEARN (10% discount for paying in SLEARN)
const rate = await slearnContract.usdtToSlearnRate(); // 22
const slearnDiscount = 0.10;
let priceSLEARN = roundedPriceUSDT * rate * (1 - slearnDiscount);

// 5. Apply minimum SLEARN (to avoid dust)
// Minimum 1 SLEARN unit = 0.01 SLEARN (since 2 decimals)
const minSLEARN = 1;
priceSLEARN = Math.max(priceSLEARN, minSLEARN);
```

**Mixed payment rule (USDT + SLEARN):** the SLEARN paid is valued at the
discounted rate `rate * (1 - slearnDiscount)`. A payment of `u` USDT plus
`s` SLEARN is valid iff:

```
u + s / (rate * (1 - slearnDiscount)) >= priceUSDT
```

Equivalently, the full SLEARN price (100% SLEARN) is `priceUSDT * rate * (1 - slearnDiscount)`.

**Response:**
```json
{
  "priceUSDT": 2.00,
  "priceSLEARN": 39.60,
  "hdiUsed": 0.467,
  "country": "Sierra Leone"
}
```

### 1.2 Purchase Endpoint

**File:** `app/api/courses/premium/purchase/route.ts` (new)

**Input:** `courseId`, `usdtAmount`, `slearnAmount`, `referralAddress` (optional)

**Process:**
```typescript
// 1. Verify user is authenticated (JWT from SIWE)
// 2. Calculate expected price (same as price endpoint)
// 3. Verify mixed payment:
//    usdtAmount + slearnAmount / (rate * (1 - slearnDiscount)) >= expectedPriceUSDT
// 4. Verify user has sufficient SLEARN balance (if slearnAmount > 0)
// 5. Call SLEARN.processPayment() with:
//    - payer: user wallet
//    - usdtAmount: user's USDT contribution
//    - slearnAmount: user's SLEARN contribution
//    - courseId: premium course ID
//    - percentages: based on course type (GD vs standard)
//    - referralAddress: if user came from referral
// 6. Wait for transaction receipt
// 7. Record enrollment in premium_course_usuario table
// 8. Return success + transaction hash
```

### 1.3 Premium Distribution Percentages

#### Standard Courses (all premium except GD)

| Destination | Percentage | Notes |
| :--- | :--- | :--- |
| pdJ Treasury | 50% | Operations & creators |
| Course Vault | 10% | Implied (`100 - totalPct`) |
| Student Reward | 10% | Minted as SLEARN via `mintAndReserve` |
| Missional Courses | 10% | 5% USDT, 5% SLEARN |
| UBI | 5% | UBI wallet |
| Referrals | 10% | Referral wallet — 10% of the payment to the referrer |
| Churches | 5% | Registered and verified churches |
| **Total** | **100%** | |

Maps to `SLEARN.processPayment()` args:
`pdJ=50, reward=10, missional=10, ubi=5, referral=10, churches=5` (vault = 10%).

#### Global Disciples Course

The 10% that would otherwise go to pdJ is routed to the Cluster/Country Fund.
`processPayment` has **no cluster destination**, so this is done off-chain
(Option B) via `ClusterFunds.sol` (#155):

1. Backend receives the user's USDT/SLEARN payment.
2. Backend routes **10%** of the payment to `ClusterFunds.sol`:
   - First `transfer()` the 10% USDT and SLEARN from the backend wallet to
     `ClusterFunds.sol` (calldata-stuffing pattern, **no `approve`** — the
     `IERC20` ABI has no `approve`; `processDonation`/`processCountryDonation`
     only record, they do not pull tokens).
   - Then call `processDonation(clusterWallet, ...)` if the user's church is in
     a cluster (`church.cluster_wallet`),
   - else `processCountryDonation(countryCode, ...)` for the user's country
     (`church.country_id`) if it is in the pilot (Sierra Leone / Colombia),
   - else `processCountryDonation('SL', ...)` to Sierra Leone.
3. Backend calls `SLEARN.processPayment()` for the remaining 90%, with pdJ
   reduced (40% of the original total instead of 50%).

| Destination | % of original |
| :--- | :--- |
| pdJ Treasury | 40% |
| Cluster/Country Fund | 10% |
| Course Vault | 10% |
| Student Reward | 10% |
| Missional Courses | 10% |
| UBI | 5% |
| Referrals | 10% |
| Churches | 5% |
| **Total** | **100%** |

> **Implementation note:** `processPayment` uses integer percentages and has no
> cluster slot, so the exact 90%-remainder split (pdJ 50%, vault ~11%, etc.)
> is finalized during Phase 3 together with #155. The routing decision tree
> above is fixed.

### 1.4 Database Schema

**New table:** `premium_course_usuario`

```sql
CREATE TABLE premium_course_usuario (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER NOT NULL REFERENCES usuario(id),
    course_id INTEGER NOT NULL REFERENCES cor1440_gen_proyectofinanciero(id),
    purchased_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    usdt_amount_paid DECIMAL(10,2),
    slearn_amount_paid INTEGER, -- in 2 decimals (100 = 1.00 SLEARN)
    transaction_hash VARCHAR(66) NOT NULL,
    expires_at TIMESTAMP, -- NULL = lifetime access
    UNIQUE(usuario_id, course_id)
);
```

### 2.4 Course Access Control (Server-Side)

Premium course guides must only be visible to users who purchased the course.
The `premium_course_usuario` table is the source of truth for access.
Enforcement is server-side so a direct API call cannot bypass it.

**Enforcement in `app/api/guide/route.ts`:**
1. `authenticateUser()` resolves `usuario_id` from wallet + token.
2. Load the course `porPagar`. If `0` or NULL, the course is free and access is
   allowed.
3. If premium, require a row in `premium_course_usuario`
   (`usuario_id` + `course_id`).
4. No row, return `403` with `{ error: 'purchase required' }`.

**Frontend behavior:**
- `app/[lang]/[pathPrefix]/[pathSuffix]/page.tsx`: on no-access, show the
  purchase modal (or link to the course page) instead of the guide content.
- `app/[lang]/[pathPrefix]/page.tsx` (course listing): premium courses not yet
  purchased show "Buy" instead of a guide link; purchased and free courses show
  the guide list.
- Guide navigation (`useGuideNavigation`) excludes guides the user cannot
  access, based on the same `premium_course_usuario` check.

**Free courses are unaffected** (`porPagar = 0` or NULL).

#### Verified worship city (all paid courses)

The price of every paid course depends on the buyer's country (`pais_id` →
`m_hdi`), and `pais_id` is **self-reported** — there is no country
verification. The verifier-confirmed church city stands in for it:

- `usuario.verified_city_id` when the place of worship has a centro poblado,
  or
- `usuario.verified_place_of_worship_location` (free text) otherwise — e.g.
  Freetown has no centro poblado in the catalog, so the verifier confirms the
  text location (the admin "Ciudad Verificada" toggle falls back to this
  field automatically).

**Every premium course purchase requires a verified worship city**, enforced
server-side by `canPurchasePremiumCourse` in `lib/course-access.ts` on both the
`purchase-eligibility` endpoint and `POST /api/courses/premium/purchase`
(403 with reason key `verified_city_required`).

#### Global Disciples course eligibility (GD pilot)

The GD course (id=10 `/gdcluster`, id=11 `/redgd`) has additional rules. The
pilot forms clusters in **Colombia and Sierra Leone** through **non-Zionist
churches**. Final access model (clarified 2026-08-13):

1. **Non-Christians cannot see the GD course** in the course lists (`/en`,
   `/es`). The course card is hidden unless `usuario.religion_id = 2`
   (Cristianismo).
2. **Any Christian can see the presentation** and open it
   (`/en/gdcluster` / `/es/redgd`), see its content, and see the ranking link.
   The presentation links to `gdcluster/ranking` / `redgd/ranking`, where
   **anyone** (public) can donate.
3. **Guides are premium** (purchase required), like any other premium course.
   The course has **6 guides** (`G1`..`G6`); guides not yet published show
   their availability date in the title (migration
   `20260813180000_restore_gd_guides_and_subtitle`).
4. **The "Buy" button is only enabled** when the user is a **Christian**
   (`religion_id = 2`) **and**:
   - from a pilot country (`usuario.pais_id` in `[170, 694]` = Colombia, Sierra
     Leone), **and**
   - has a **verified worship city** (see above — verified_city_id or
     verified_place_of_worship_location), **and**
   - the user answered **no** to the single Gaza question in their own profile
     (`usuario.position_israel_gaza='no'`, i.e. does NOT support Israel in the
     Gaza genocide). Supporting Israel there → considered Zionist → no Buy.

A US Christian, or a Sierra Leone/Colombia member who answered `yes` (or left
blank) to the Gaza question, sees the same as a US Christian: presentation +
ranking link, **no Buy**.

This replaces the earlier three-question check (covenant/remnant/gaza answered
at church registration): the Zionist gate is now a single per-user Gaza
question answered in the profile. The non-Zionist check is a **purchase
eligibility** gate, not a guide-viewing gate (guides are gated by
`premium_course_usuario` only).

**Course completion gate:** the cluster tool (`POST /api/cluster`) requires the
pastor to have **taken the GD course** (a `premium_course_usuario` row for
course 10 or 11) before creating a cluster.

**Implementation:**
- `lib/course-access.ts`:
  - `canAccessCourse(db, userId, courseId)` — premium-only guide gate
    (`premium_course_usuario`); no course-specific GD guide gate.
  - `canPurchasePremiumCourse(db, userId, courseId)` — purchase eligibility
    for **every** paid course: verified worship city required; GD adds the
    pilot gates via `canPurchaseGDCourse`.
  - `canPurchaseGDCourse(db, userId)` — GD pilot eligibility (Christian,
    pilot country, verified worship city, single per-user Gaza question).
  - `hasVerifiedWorshipCity(user)` — `verified_city_id` or
    `verified_place_of_worship_location`.
- `app/api/courses/[courseId]/purchase-eligibility/route.ts` (new) — returns
  `{ eligible, reason }`; enforces `canPurchasePremiumCourse` for all courses.
- `POST /api/courses/premium/purchase` — denies purchases with `403` when
  `canPurchasePremiumCourse` fails (all paid courses, not only GD).
- Course page (`/[lang]/[pathPrefix]/page.tsx`) — hides Buy / shows reason for
  ineligible GD users.
- Course listing (`/[lang]/page.tsx`) — hides GD cards for non-Christians.
- `POST /api/cluster` — requires the pastor to have purchased the GD course.
- Profile page (`/[lang]/profile/page.tsx`) — asks the single Gaza question;
  `/api/profile` persists `position_israel_gaza`.
- Migration `20260813190000_add_gaza_position_to_usuario` — adds
  `usuario.position_israel_gaza`.
