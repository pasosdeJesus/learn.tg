# R-#218: Footer hydration mismatch — legal links render `//privacy-policy` on the client

## Problem Description

On every page load, React logs a hydration mismatch in the Footer. The legal
links (`Privacy Policy`, `Terms of Service`) render with the locale prefix on
the server but without it on the client:

```
<LinkComponent href="//privacy-..." ...>   ← client
  <a href="//privacy-policy"
     ...
- href="/en/privacy-policy"                 ← server
```

Result: `href="//privacy-policy"` (a protocol-relative URL that points to the
wrong host) instead of `/en/privacy-policy`. This won't be patched up by React.

## Technical Context

The mismatch is caused by `components/Layout.tsx` (client component), which
derives `lang` from `window.location.href` on the client while the server uses
a hardcoded fallback:

```tsx
let lang = 'en'
if (typeof window !== 'undefined') {
  const purl = window.location.href.split('/')
  lang = purl.length > 3 ? purl[3] : 'en'
}
```

- Server render: `typeof window === 'undefined'` → `lang = 'en'` always.
- Client render (hydration): `lang` comes from parsing
  `window.location.href.split('/')` — which can yield `''` (or a different
  segment) depending on the URL shape (e.g. trailing slashes, root path).
- `<Footer lang={lang} />` (Layout.tsx:22) then renders
  `<Link href={`/${lang}/privacy-policy`}>` → `//privacy-policy` when `lang`
  is empty.

The console log (see REQ/216, `tmp/c.txt`) shows `<Footer lang="">` on the
client while the server HTML has `/en/privacy-policy`.

## Impact

- React hydration mismatch warnings on every page (console noise; the tree is
  not patched up).
- The legal links can point to a protocol-relative URL (`//privacy-policy`)
  that resolves to the wrong origin in some contexts — bad for SEO, analytics
  and link correctness.
- Symptom of a broader issue: `lang` derived from `window` is not
  SSR/hydration-safe.

## Suggested Solutions (fix)

1. **Derive `lang` from Next navigation (recommended)**: in `Layout.tsx`, use
   `useParams()` (or `usePathname()`) from `next/navigation` — it hydrates
   consistently with the server:

   ```tsx
   import { useParams } from 'next/navigation'
   const params = useParams<{ lang?: string }>()
   const lang = (params.lang as string) || 'en'
   ```

2. **Pass `lang` from the server layout**: `app/[lang]/layout.tsx` already has
   `lang` in its params — pass it down to `RootLayoutClient`/`Layout` as a prop
   instead of parsing `window.location`.
3. **Fallback in the Footer**: if `lang` is empty, default to `'en'` (defensive,
   but does not fix the root cause).

## Suggested Solutions (diagnosis)

1. Confirm the mismatch on a URL with/without trailing slash
   (`https://learn.tg/en` vs `https://learn.tg/en/`) — the `split('/')` parsing
   is sensitive to the URL shape.
2. After switching to `useParams`, re-check the console for
   "A tree hydrated but some attributes..." on load.
