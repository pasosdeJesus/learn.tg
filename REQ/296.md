## 1. Objective

Replace the free-form "first year total + PDF" that the cluster presentation uses today
(https://github.com/pasosdeJesus/learn.tg/issues/161 §9) with a **structured form** that produces
the **draft budget of the first three years** and the **detailed year-4 budget with
self-sufficiency**, from the minimum data a cluster can actually know before starting.

The form is rendered from a **markup** (a versioned document the app reads), so the fields,
labels, validations and computed values live in one place instead of in JSX, the same markup can
render the printable/PDF version, and the exported document can be read by GD.

## 2. Inputs (the minimum)

Everything is in **USD**; payments stay in USDT/SLEARN as today.

### 2.1 Churches (sum of a per-church field)

| Input | Where | Notes |
|-------|-------|-------|
| `members_count` | `church` (new column) | Filled per church by its lead pastor; the cluster budget **sums** the members of its member churches |
| `estimated_students` | per church, optional | Initial estimate of students each church can bring; the form shows the sum next to the cohort estimate |

The budget never asks again for the members: it reads `sum(church.members_count)` of the
churches in the cluster and stores the sum it used (so a later change of a church does not
silently rewrite an approved budget).

### 2.2 Cohorts and prices

| Input | Type | Notes |
|-------|------|-------|
| `cohorts_per_year` | integer 1-4 | Number of cohorts started each year |
| `students_per_cohort` | integer | Estimated students per cohort (one value, or one per cohort for the three years) |
| `price[year][cohort]` | money | Price per student for each cohort of years 1-3 |
| `gd_subsidy[year]` | money | Part of that price covered by GD's funding, per year |

Guided rule (validated, not assumed): the price **increases** cohort by cohort in a way
consistent with the partial funding GD provides, and the **last cohort of year 3 must cover the
full cost per student plus a margin** — otherwise the form blocks the draft and says which number
to raise.

### 2.3 Program director

| Input | Type | Notes |
|-------|------|-------|
| `director_hours[cohort]` | hours | Director's work hours per cohort |
| `director_hourly_rate` | money/hour | Rate used to cost those hours |
| `director_hours_other` | hours | Training, GD meetings, budget revisions, supervision |

The director's cost is computed (`hours × rate`) and compared with the total budget: the form
warns when the director's share is unrealistic for the number of students.

### 2.4 Other costs

Cost lines per year, each with a category, a description, an amount and a recurrence
(once per year / per cohort / per student): materials, travel and transport, venue, faculty or
facilitators, food, communications, equipment, administration, contingency. The minimum set is
pre-filled by the markup; the cluster may add lines inside the allowed categories.

### 2.5 Schedule of the first three years

A timeline of dated activities: cohort start/end dates and, **before** the first cohort starts,
the **GDT training**, the **SBD training**, the budget revision and the interaction with GD.
Each activity has `id`, `name`, `start`, `end`, `depends_on[]` and a category
(`training` / `cohort` / `gd` / `budget` / `other`).

Validations: training activities must end before the first cohort starts; cohorts of the same
year cannot overlap by more than the shared activities allow; everything fits in the three-year
window; a cohort cannot start without its assigned director hours.

## 3. Outputs

| Output | Detail |
|--------|--------|
| **Draft of the three years** | Per year: students, income (prices × students), GD subsidy, director cost, other costs, result, cumulative | 
| **Detailed year 4** | The same, with `gd_subsidy = 0` and the price needed to cover **full costs plus the margin**; break-even per cohort and the year the program becomes self-sufficient |
| **Financial model** | Break-even point per cohort, cumulative cash by year, share of the budget that depends on the subsidy, sensitivity to `students_per_cohort` (±20 %) |
| **Document** | Printable/PDF version of the budget (the draft the pastors approve and pdJ reviews) and a **CSV/JSON export** |
| **The five data of §9** | `budget_total` (year 1, as today) and `budget_draft_path` are filled from the generated document, not typed by hand |

The approval hash of https://github.com/pasosdeJesus/learn.tg/issues/161 §9 keeps covering the
five data; with this form it also covers the **budget document version**, so editing the budget
invalidates the approvals exactly as changing the total does today.

## 4. Markup

A versioned JSON document (`budget-markup` v1) describes the form; the app renders it, validates
it and prints from it. Shape (draft):

```json
{
  "version": 1,
  "currency": "USD",
  "sections": [
    {
      "id": "churches",
      "title": { "en": "Churches and students", "es": "Iglesias y estudiantes" },
      "fields": [
        { "id": "members_total", "type": "computed", "formula": "sum(churches.members_count)", "readOnly": true },
        { "id": "cohorts_per_year", "type": "integer", "min": 1, "max": 4, "required": true },
        { "id": "students_per_cohort", "type": "integer", "min": 1, "required": true }
      ]
    },
    {
      "id": "prices",
      "title": { "en": "Prices per cohort", "es": "Precios por cohorte" },
      "fields": [
        { "id": "price", "type": "matrix", "rows": "year:1..3", "columns": "cohort:1..cohorts_per_year", "unit": "money" },
        { "id": "gd_subsidy", "type": "row", "rows": "year:1..3", "unit": "money" }
      ]
    },
    {
      "id": "director",
      "title": { "en": "Program director", "es": "Director del programa" },
      "fields": [
        { "id": "director_hours", "type": "row", "rows": "cohort", "unit": "hours" },
        { "id": "director_hourly_rate", "type": "money", "required": true }
      ]
    },
    {
      "id": "costs",
      "title": { "en": "Other costs", "es": "Otros costos" },
      "fields": [
        { "id": "cost_lines", "type": "table", "columns": ["category", "description", "amount", "recurrence", "year"] }
      ]
    },
    {
      "id": "schedule",
      "title": { "en": "Schedule", "es": "Cronograma" },
      "fields": [
        { "id": "activities", "type": "table", "columns": ["name", "category", "start", "end", "depends_on"] }
      ]
    }
  ],
  "validations": [
    "members_total > 0",
    "last_cohort_price >= cost_per_student * (1 + margin)",
    "gd_subsidy[4] == 0",
    "training_ends_before_first_cohort"
  ],
  "computed": ["income", "director_cost", "year_result", "break_even", "self_sufficiency_year"]
}
```

Decisions to settle with the operator before implementing: the exact cost categories and their
order, the default `margin` (proposed 10 %), whether `students_per_cohort` is one value or a
per-cohort row, and whether year 4 is a projection inside the same document or a separate
section.

## 5. Data model (draft)

| Table | Columns |
|-------|---------|
| `church` | `members_count integer` (new) |
| `clustergd_budget` | `id`, `clustergd_id`, `version`, `status` (`draft` / `reviewed` / `locked`), `markup_version`, `document jsonb`, `year1_total`, `year4_total`, `self_sufficiency_year`, `created_by`, `updated_at` |
| `clustergd_budget_history` | `id`, `budget_id`, `changed_by`, `changed_at`, `diff jsonb` |

One budget per cluster and version; the presentation locks the version it approved (consistent
with §9's `requested` / `under_review` / `approved` / `sent` lock).

## 6. Permissions and lifecycle

| Who | What |
|-----|------|
| Lead pastor of a member church | Reads the budget |
| Initiator | Creates and edits the **draft**, generates the document, submits it for review |
| pdJ (verifier) | Reviews, comments and returns it (the presentation's `returned` unlocks the edition) or approves it |
| Approved/locked states | The budget and its total are read-only; editing creates a new version |

Routes follow `doc/api-security.md`: authenticated for the cluster's pastors, admin-only for the
review transitions.

- **R-#161** (https://github.com/pasosdeJesus/learn.tg/issues/161): consumes this form for

## 8. Acceptance criteria

- [ ] A pastor of the cluster fills the form, saves a draft, reloads and sees the same numbers.
- [ ] `members_total` is the sum of `church.members_count` of the member churches and does not
  change retroactively when a church updates its count (the version keeps the value it used).
- [ ] The draft is **blocked** with a clear message when the last cohort's price does not cover the
  full cost per student plus the margin, and when a training activity ends after the first cohort
  starts.
- [ ] The three-year draft, the year-4 detail and the financial model (break-even, cumulative cash,
  subsidy dependency, ±20 % sensitivity) render from the markup.
- [ ] The generated document is the one approved by the pastors and reviewed by pdJ; changing the
  budget invalidates the approvals (same hash behaviour as today).
- [ ] `budget_total` and `budget_draft_path` of R-#161 are filled from the form, not typed.
- [ ] CSV/JSON export contains every input and every computed value, with the markup version.
- [ ] Unit tests for the formulas (income, director cost, per-cohort cost, break-even,
  self-sufficiency year) and for each validation; route tests for permissions and lock;
  one E2E that fills the form, generates the document and requests the presentation with the
  computed total.

## 9. Out of scope

- Accounting and execution (budget vs real): belongs to
  https://github.com/pasosdeJesus/learn.tg/issues/258 and
  https://github.com/pasosdeJesus/learn.tg/issues/273.
- Currency conversion and multi-currency budgets: one budget in USD.
- The country-fund split and the release of the cluster fund (R-#161 §10, R-#294).
- Replacing the PDFs of the director's offer: only the budget document is generated here.

## 10. Open questions for the operator

1. Exact cost categories (the list in §2.4) and whether a cluster may create its own.
2. Margin for the last cohort (proposed 10 %).
3. `students_per_cohort`: one value for all cohorts or a row per cohort.
4. Year 4: one more section of the same document, or a separate document.
5. The PDF layout: one page per year plus a summary, or a single table.
6. Whether the schedule lives inside the budget document or as its own view of the cluster.
