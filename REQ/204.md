## Simplified for learn.tg (Phase 1)

We don't need `encuestapersona` (person-based surveys) or `planencuesta`
(complex survey date planning with tokens). For learn.tg's use case:

- `formulario` → form definition (e.g., "GD Characterization")
- `campo` → fields with types, validation, layout
- `opcioncs` → options for select fields
- `respuestafor` → a user's response to a form
- `valorcampo` → individual field values (EAV)
- `encuestausuario` → links user to response (with date tracking)
- (Skip `encuestapersona` and `planencuesta` for Phase 1)

## API Endpoints

| Endpoint | Auth | Description |
|----------|------|-------------|
| `GET /api/mr519/forms` | Admin | List form definitions |
| `GET /api/mr519/forms/:id` | Public | Form definition with fields + options |
| `POST /api/mr519/forms/:id/responses` | User | Submit response (creates respuestafor + valorcampos) |
| `GET /api/mr519/responses/:id` | User | Get user's response with values |
| `POST /api/admin/mr519/forms` | Admin | Create form with fields |
| `PUT /api/admin/mr519/forms/:id` | Admin | Update form fields |

## Integration with GD Course

1. Admin creates `formulario` with `nombreinterno: 'gd_characterization'`
2. Fields include zionism questions, pastoral info
3. GD course page checks: `SELECT 1 FROM encuestausuario eu JOIN respuestafor r ON r.id = eu.respuestafor_id WHERE r.formulario_id = :fid AND eu.usuario_id = :uid`
4. If no response → redirect to `DynamicForm`
5. `DynamicForm` renders all fields, user submits
6. Creates `respuestafor` + `valorcampo` + `encuestausuario`
