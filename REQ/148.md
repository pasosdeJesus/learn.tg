## ⏳ Dependencies
- Issue #129 completed (SLEARN and LearnTGVaultsV4 on mainnet, initial mint done).

## 🚧 Pending tasks

### 1. Premium Course Payments with SLEARN

- [ ] Modify backend so that when a user buys a premium course:
  - User approves SLEARN spending (or signs a transfer).
  - Backend calls `SLEARN.burn(address user, uint256 amount)` to burn the SLEARN paid.
  - `SLEARN` emits `Burn` event for auditing.
- [ ] Optional: allow mixed payments (partial USDT, partial SLEARN).

### 2. Burn Functionality in SLEARN Contract

- [ ] Verify backend has `BURNER_ROLE`.
- [ ] Implement `burnFrom` function (if using allowance) for more flexibility.

### 3. Automated Referral Program

- [ ] Ensure `SLEARN.processPayment` already handles referral distribution (design done, needs backend to pass `referralAddress` correctly).
- [ ] Create contract or script to distribute USDT accumulated in `referralWallet` to referrers (based on on-chain events).
- [ ] Display referral stats and pending rewards on user profile.

### 4. SLEARN ↔ Leone (SLE) Swap (stable-sl)

### 6. Advanced Transparency Dashboard

### 7. Governance (Phase 4 of Whitepaper)

### Distribution Percentages (from SLEARN-WHITEPAPER.md §3.1.2)

Premium course payments flow through `SLEARN.processPayment()` with these percentages:

| Destino | % | Descripción |
|---|---|---|
| pdJ treasury (ops + creadores) | 55% | learn.tg operations + creator revenue |
| Course vault | 10% | 0.5 USDT vault + 0.5 USDT → SLEARN reserve |
| Student reward (cashback) | 10% | `mintAndReserve` → SLEARN al estudiante |
| Missional courses | 10% | 0.5 USDT vault + 0.5 USDT → SLEARN reserve |
| UBI + Referrals | 10% | UBI (CELO) + referidos |
| Churches | 5% | Iglesias registradas y verificadas |
| **Total** | **100%** | |

Comparado con donaciones a cursos (`DONATION_PCT` ya implementado en `add-donation/route.ts`):

| Destino | Donación | Premium |
|---|---|---|
| pdJ | 5% | 55% |
| Reward (cashback) | 10% | 10% |
| Missional | 5% | 10% |
| UBI + Referral | 5% | 10% |
| Churches | 5% | 5% |
| Course vault | 70% | 10% |

`SLEARN.processPayment` recibe los porcentajes como parámetros — el backend decide cuáles usar sin modificar el contrato. Solo se requiere que suma ≤ 99%.
