# R-#213: E2E Test Infrastructure — Robust Authentication & Unified Wallet Mock

Make E2E tests reliable by unifying the two competing auth mechanisms into a single helper, implementing a complete `window.ethereum` mock with EIP-6963, real RPC methods, and programmatic session setup. Fix specific fragile specs (`admin-dashboard`, `church-persistence`).

---

**Created:** 2026-08-21
**Status:** Pendiente

---

## Rationale

Currently 4–5 of 15 E2E specs fail intermittently, all due to auth fragility:

| Root Cause | Impact |
| :--- | :--- |
| Two competing auth patterns (`setupSIWEMock` UI-driven vs `simulateSIWE` API-driven) | Inconsistent auth state — some specs pass on cookie, others on localStorage |
| `helpers/siwe-wallet-mock.mjs` has no EIP-6963 dispatch | wagmi v2+ does not detect the mock wallet |
| `helpers/siwe-wallet-mock.mjs` missing `eth_call`, `eth_getBalance`, `eth_blockNumber` | Console errors, loading spinners never resolve |
| `admin-dashboard` reads auth from localStorage (`learn.tg.authToken` = CSRF nonce) | Nonce expires, stale localStorage causes 403 |
| `church-persistence` verifies with DOM regex | Does not actually check DB persistence |

---

## 1. Unified Helper: `setupE2EAuth(page, wallet, privateKey, chainId)`

**File:** `e2e/helpers/e2e-auth.mjs` (new)

Replaces both `setupSIWEMock` and `simulateSIWE` with a single helper that:

1. **Injects `window.ethereum`** via `evaluateOnNewDocument` with:
   - EIP-1193 methods: `eth_chainId`, `eth_accounts`, `eth_requestAccounts`, `personal_sign` (real ECDSA via `page.exposeFunction`)
   - EIP-6963: dispatches `eip6963:announceProvider` on inject and on every page load
   - RPC methods: `eth_call`, `eth_getBalance`, `eth_blockNumber`, `eth_gasPrice`, `eth_estimateGas` — all return plausible defaults via `page.exposeFunction` bridging to a real viem `PublicClient`
   - `eth_sendTransaction`: returns a fake tx hash (`0x` + `cd`.repeat(32))

2. **Runs `simulateSIWE` programmatically** after wallet injection, establishing:
   - NextAuth session cookie (real `Set-Cookie` via `fetch` inside `page.evaluate`)
   - `learn.tg.sessionAddress` + `learn.tg.authToken` in localStorage (for legacy compatibility)

3. **Returns `{ sessionAddress, authToken }`** for specs that need to make API calls.

### API

```js
import { setupE2EAuth } from '../helpers/e2e-auth.mjs'

const { sessionAddress, authToken } = await setupE2EAuth(page, address, privateKey, chainId)
// page is now authenticated: session cookie set, ethereum mock active
```

### Implementation Notes

- `setupE2EAuth` must be called **before** `page.goto()` so the mock is in place before any React code runs
- The `simulateSIWE` step runs via `page.evaluate` so the cookie lands in the browser's jar
- For `personal_sign`, bridge to Node.js `privateKeyToAccount` via `page.exposeFunction('__signSiwe', ...)` (same as current `siwe-wallet-mock.mjs`)
- For RPC methods, bridge to a Node.js `createPublicClient` via `page.exposeFunction('__rpcCall', ...)` — the mock calls `eth_call` etc. against the real RPC
- Legacy `setupSIWEMock` and `simulateSIWE` remain for backward compatibility but all new specs use `setupE2EAuth`

## 2. Fix `admin-dashboard.spec.mjs`

### Problem
Uses localStorage `learn.tg.authToken` (CSRF nonce) for admin API calls. Nonce can expire, and the dual cookie+localStorage state drifts.

### Solution
- Use `setupE2EAuth` from §1
- After auth, make admin API calls via `page.evaluate` using `fetch` with credentials: `'include'` (sends session cookie automatically)
- Fall back to `authToken` from `setupE2EAuth` return value if cookie-based calls fail

### Change
```diff
- const token = localStorage.getItem('learn.tg.authToken')
- const q = `wallet=${addr}&token=${token}`
- const r = await fetch(`/api/admin/users?${q}`)
+ const r = await fetch('/api/admin/users', { credentials: 'include' })
```

## 3. Fix `church-persistence.spec.mjs`

### Problem
Verifies church persistence by scraping DOM with regex after reload — fragile and doesn't check actual DB state.

### Solution
After saving church, reload, then call `GET /api/profile` (with auth cookie) and verify `church_id` is present in the JSON response.

### Change
```diff
- const churchAfter = await page.evaluate(() => ... regex ...)
- if (churchAfter.includes('Afghanistan')) ok(...)
+ const profileRes = await page.evaluate(async () => {
+   const r = await fetch('/api/profile', { credentials: 'include' })
+   return r.json()
+ })
+ if (profileRes.church_id) ok('Church persisted in DB')
```

## 5. Non-Goal: Changing the Auth Architecture

The CSRF-nonce-as-auth-token pattern (`siwe-auth-flow.md` §1) is **not** changed — it works in production. The E2E fix only changes how tests authenticate, not the backend auth system. Changing the backend token system is a separate REQ.
