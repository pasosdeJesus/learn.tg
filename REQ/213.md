# R-#213: E2E Test Infrastructure — Robust Authentication & Unified Wallet Mock

Make E2E tests reliable by unifying the two competing auth mechanisms into a single helper, implementing a complete `window.ethereum` mock with EIP-6963, real RPC methods, and programmatic session setup. Fix specific fragile specs (`admin-dashboard`, `church-persistence`).

---

**Created:** 2026-08-21
**Status:** En progreso

---

## Rationale

Currently 4–5 of 15 E2E specs fail intermittently, all due to auth fragility:

| Root Cause | Impact |
| :--- | :--- |
| Two competing auth patterns (`setupSIWEMock` UI-driven vs `simulateSIWE` API-driven) | Inconsistent auth state — some specs pass on cookie, others on localStorage |
| `helpers/siwe-wallet-mock.mjs` has no EIP-6963 dispatch | wagmi v2+ does not detect the mock wallet |
| `helpers/siwe-wallet-mock.mjs` missing `eth_call`, `eth_getBalance`, `eth_blockNumber` | Console errors, loading spinners never resolve |
| `admin-dashboard` reads auth from localStorage (`learn.tg.authToken` = CSRF nonce) | Nonce expires, stale localStorage causes 403 |
| `church-persistence` verifies with DOM regex | Does not actually check DB persistence |

---

## 1. Unified Helper: `setupE2EAuth(page, wallet, privateKey, chainId, baseUrl)`

**File:** `e2e/helpers/e2e-auth.mjs` (new)

Replaces both `setupSIWEMock` and `simulateSIWE` with a single helper that:

1. **Injects `window.ethereum`** via `evaluateOnNewDocument` with:
   - EIP-1193 methods: `eth_chainId`, `eth_accounts`, `eth_requestAccounts`, `personal_sign` (real ECDSA via `page.exposeFunction`)
   - EIP-6963: dispatches `eip6963:announceProvider` on inject and on every page load
   - RPC methods: `eth_call`, `eth_getBalance`, `eth_blockNumber`, `eth_gasPrice`, `eth_estimateGas` — return plausible defaults
   - `eth_sendTransaction`: returns a fake tx hash (`0x` + `cd`.repeat(32))

2. **Runs `simulateSIWE` programmatically** after wallet injection, establishing:
   - NextAuth session cookie (real `Set-Cookie` via `fetch` inside `page.evaluate`)
   - `learn.tg.sessionAddress` + `learn.tg.authToken` in localStorage (for legacy compatibility)

3. **Returns `{ sessionAddress, authToken }`** for specs that need to make API calls.

### API

```js
import { setupE2EAuth } from '../helpers/e2e-auth.mjs'

const { sessionAddress, authToken } = await setupE2EAuth(page, address, privateKey, chainId, baseUrl)
// page is now authenticated: session cookie set, ethereum mock active
```

## 3. Non-Goal: Changing the Auth Architecture

The CSRF-nonce-as-auth-token pattern (`siwe-auth-flow.md` §1) is **not** changed — it works in production. The E2E fix only changes how tests authenticate, not the backend auth system. Changing the backend token system is a separate REQ.
