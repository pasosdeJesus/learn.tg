# F-#200: bin/m credentials:register-type and bin/m sync-cache should fill/(verify and fill) course_id in the table

## Description

When registering a credential type via `bin/m credentials:register-type --course-id <ID>`, the contract correctly stores the mapping `courseIdToTokenId[courseId] = tokenId` and `tokenIdToCourseId[tokenId] = courseId`. However, the `credential_metadata` table in the database does not get the `course_id` field populated, leaving it `NULL` for all course-related tokens.

This breaks the relationship between a course in `cor1440_gen_proyectofinanciero` and its corresponding SBT token.

## Current Behavior

```bash
# Contract has the mapping
$ bin/m wallet:call --name learntg --to <CREDENTIALS_ADDRESS> \
  --function "courseIdToTokenId(uint256)" --args "10" --network celo
# Returns: 15 ✓

# But database has course_id = NULL
$ bin/m db:console "SELECT token_id, course_id, name FROM credential_metadata WHERE token_id = 15;"
 token_id | course_id |                      name
----------+-----------+-------------------------------------------------
       15 |    [NULL] | Tools to Bring Global Disciples to Your Cluster
```

## Affected Commands

### 1. `bin/m credentials:register-type`

When called with `--course-id`, the command:
- ✅ Registers the credential type on-chain (including `courseIdToTokenId` mapping)
- ❌ Does NOT save `course_id` to `credential_metadata` in the database

### 2. `bin/m credentials:sync-cache`

When called, the command:
- ✅ Syncs token names, soulbound status, and other metadata
- ❌ Does NOT read `courseIdToTokenId` or `tokenIdToCourseId` from the contract
- ❌ Does NOT update `course_id` in `credential_metadata`

## Expected Behavior

### For `register-type`

When `--course-id` is provided, the command should:
1. Register the credential type on-chain
2. **Insert or update `credential_metadata.course_id`** with the provided course ID

### For `sync-cache`

When syncing tokens, the command should:
1. Read existing metadata from the contract
2. **Read `tokenIdToCourseId(tokenId)` from the contract** for each token
3. If the returned value > 0, **update `credential_metadata.course_id`** with that value

## Implementation Notes

### Location

- `src/blockchain/credential-cache.ts` — contains the `sync-cache` logic
- `src/tasks/credentials.ts` or similar — contains `register-type` logic

### Suggested Changes

#### In `register-type`:

```typescript
// After successful on-chain registration
if (courseId && courseId > 0) {
  await db.insertInto('credential_metadata')
    .values({
      token_id: tokenId,
      chain_id: network,
      course_id: courseId,
      // ... other fields
    })
    .onConflict((oc) => oc.column('token_id').doUpdateSet({
      course_id: courseId,
      updated_at: new Date(),
    }))
    .execute()
}
```

#### In `sync-cache`:

```typescript
// For each token, read courseId from contract
const courseId = await contract.read.tokenIdToCourseId([tokenId])
if (courseId > 0) {
  await db.updateTable('credential_metadata')
    .set({ 
      course_id: Number(courseId),
      updated_at: new Date(),
    })
    .where('token_id', '=', Number(tokenId))
    .execute()
}
```
