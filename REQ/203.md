# R-#203: Web3 Engine System — Modular Course Plugins

Design a pluggable "engine" system inspired by Rails engines and `m eng:credentials`.
Each course or feature group ships as a self-contained module with its own database
schema, API routes, frontend components, smart contracts, and tests. Compilable
independently, pluggable into learn.tg.

---

## Motivation

The GD cluster course (`gdcluster`) currently mixes course content with a dedicated
smart contract (`ClusterFunds`), donation system, ranking, and contact tracking.
As more courses add their own contracts and logic, learn.tg needs a modular
architecture where each course engine can be:

- **Developed in isolation** — compile and test independently
- **Added or removed** without touching core learn.tg
- **Namespaced** — no collisions between engines (API, DB, routes)
- **Versioned** — engines can evolve independently of the host app

## Inspiration

| Source | Pattern |
|--------|---------|
| Rails engines | Self-contained gems with migrations, routes, views, tests |
| `m eng:credentials` | Plugin system: `eng:credentials:*` commands, isolated blockchain logic |
| `@pasosdejesus/mpdj` | PdJ-specific plugin that extends `m` without modifying it |
| Remix IDE plugin system | Each plugin declares `profile`, `methods`, `events` |

## Namespace Conventions

| Layer | Pattern | Example |
|-------|---------|---------|
| API | `/api/{engine}/...` | `/api/gdcluster/ranking/clusters` |
| Pages | `/[lang]/{engine}/...` | `/en/gdcluster/ranking` |
| DB tables | `{engine}_*` prefix | `clustergd`, `gdcontact` |
| Components | `{Engine}*` prefix | `GdDonateModal`, `GdContactTracker` |
| CLI commands | `eng:{engine}:*` | `eng:gdcluster:deploy`, `eng:mr519:create-form` |

## Where Source Code Lives

Engines start as **packages in the learn.tg monorepo**. If another project
(e.g., sivel3) needs them, they graduate to the `m` monorepo.

```
learn.tg/
  packages/
    gdcluster/       ← @learn-tg/gdcluster
    mr519/           ← @learn-tg/mr519
  apps/
    nextjs/
    hardhat/

# If adopted by sivel3 → moves to:
m/packages/gdcluster/   ← @pasosdejesus/gdcluster
m/packages/mr519/        ← @pasosdejesus/mr519
```

Each engine package provides:

| Directory | Purpose | Example (mr519) |
|-----------|---------|-----------------|
| `src/commands.ts` | CLI commands registered in `m` | `eng:mr519:create-form` |
| `src/server/` | API route handlers | `POST /api/mr519/forms/:id/responses` |
| `src/components/` | React components | `<DynamicForm>`, `<FormField>` |
| `db/migrations/` | PostgreSQL migrations | `001_create_mr519_gen_tables.ts` |
| `contracts/` | Solidity + Hardhat (if engine has contracts) | `ClusterFunds.sol` |
| `engine.json` | Manifest: name, version, stage, deps | `{ "name": "mr519", "stage": "local" }` |

## Graduation from learn.tg to m

`engine.json` tracks the lifecycle:

```json
{
  "name": "mr519",
  "version": "0.1.0",
  "stage": "local",
  "dependencies": { "@learn-tg/mr519": "workspace:*" }
}
```

When `stage: "shared"`:
1. Move `learn.tg/packages/{name}/` → `m/packages/{name}/`
2. Update `engine.json`: `"stage": "shared"`, dependencies → `@pasosdejesus/{name}`
3. `pnpm publish` from `m`
4. learn.tg references `@pasosdejesus/{name}` instead of workspace `@learn-tg/{name}`

## Integration Points

### 1. Database

Engine migrations run alongside core migrations. The host app's migration runner
discovers packages via `packages/*/db/migrations/`:

```typescript
import { discoverEngines } from '@/lib/engines'
for (const engine of discoverEngines()) {
  await runMigrations(path.join('packages', engine.name, 'db', 'migrations'))
}
```

### 2. API Routes

Engine route handlers are imported directly from the package:

```typescript
// app/api/gdcluster/ranking/clusters/route.ts
export { GET } from '@learn-tg/gdcluster/server/ranking/clusters/route'
```

### 3. Frontend Pages

```typescript
// app/[lang]/gdcluster/ranking/page.tsx
export { default } from '@learn-tg/gdcluster/components/RankingPage'
```

### 4. Smart Contracts

Compiled and deployed from `packages/{engine}/contracts/`:

```sh
cd packages/gdcluster/contracts
pnpm hardhat compile
pnpm hardhat run scripts/deploy.ts --network celoSepolia
pnpm hardhat test
```

### 5. Components

```typescript
import { GdDonateModal } from '@learn-tg/gdcluster/components/GdDonateModal'
```

### 6. CLI Commands

Registered via `m` plugin system:

```typescript
// packages/gdcluster/src/commands.ts
import { registerCommands } from '@pasosdejesus/m/plugin'
registerCommands({
  'eng:gdcluster:deploy': { handler: deployClusterFunds },
  'eng:gdcluster:ranking': { handler: printRanking },
})
```

### 7. Tests

```sh
pnpm test                           # core + all engine packages
pnpm test --filter @learn-tg/gdcluster
cd packages/gdcluster && pnpm test
```

## Migration Path

### Phase 1 — Move GD code to packages/gdcluster/

Move existing `app/api/gdcluster/`, `app/[lang]/gdcluster/`, contracts under
`packages/gdcluster/`. Routes become thin re-exports from the package.

### Phase 2 — Engine manifest + CLI commands

Add `engine.json`, `src/commands.ts`, register `eng:gdcluster:*` in `m`.

### Phase 3 — Build tooling

Scripts to compile engines independently, run engine-specific tests.

### Phase 4 — Generic engine template

`pnpm create engine my-course` generates scaffold.
