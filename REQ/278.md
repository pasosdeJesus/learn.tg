## 1. Current state

The leaderboard (`/api/leaderboard` → `lib/leaderboard-queries.ts` →
`components/LeaderboardTable.tsx`) shows these columns, all sortable:

| Column | Source |
|---|---|
| Rank, User, Country, [Religion] | `usuario`, `msip_pais`, `religion` |
| Profile Score | `usuario.profilescore` |
| SLEARN | **net balance** (`SUM(balance_impact)` over `transaction`) |
| Scholarship (USDT) | `SUM(amount)` of `transaction` `type = 'scholarship' AND crypto = 'usdt'` |
| UBI (CELO) | `SUM(amount)` of `type = 'ubi-claim' AND crypto = 'celo'` |
| Donations (USDT) | `SUM(amount)` of `type = 'donation' AND crypto = 'usdt'` |
| SBTs | `credential_emission`, filtered by the https://github.com/pasosdeJesus/learn.tg/issues/259 visibility rule |

Default sort is `slearn_balance` desc. `usuario.excluir_leaderboard = true` opts a
user out. The board does not show the **work on the guides**.

## 2. Change requested (operator, 2026-10-02)

The course page draws, in front of each guide, the marks the student earned: a
**checkmark** (passed), the **USDT** scholarship and the **SLEARN** scholarship. The
leaderboard must **add up those three marks across all the student's guides**, in three
columns, with the **main column being the sum** (default order desc). **All courses count**
(every published course, free and paid).

| Column | Meaning | Same rule as |
|---|---|---|
| **Guías aprobadas** (checkmarks) | Guides passed | `/api/guide-status` → `completed` |
| **Guías con beca USDT** | Guides whose USDT scholarship was paid | `receivedScholarship` |
| **Guías con beca SLEARN** | Guides whose SLEARN scholarship was paid | `receivedSlearnScholarship` |
| **Greens / Verdes** (**main**) | **Sum of the three** | computed in SQL |

- The main column is **"Greens"** in English and **"Verdes"** in Spanish (the SQL key
  can be `verdes`).
- These are **counts of guides**, not token amounts. The existing columns (SLEARN
  balance, USDT/SLEARN token amounts, UBI, donations, SBTs) are **kept**.
- The sum is computed in the **SQL query** (the fastest option that keeps sorting and
  pagination correct; a client-side sum would only order the current page).
- The exact meaning of each mark already lives in `app/api/guide-status/route.ts`, and
  the leaderboard must reuse it so the board and the course page always agree:
  - **aprobada**: `guide_usuario.points > 0`;
  - **beca USDT pagada**: `guide_usuario.amountpaid > 0`;
  - **beca SLEARN pagada**: a `transaction` row with `crypto = 'slearn'`,
    `type = 'scholarship'` and `metadata->>'guideId' = actividadpf_id` for that guide.
- A guide that is approved but **not paid** (profile score < 50, empty vault, cooldown)
  counts **1** in "Guías aprobadas" and **0** in the paid columns; that is how the
  course page shows it.
- **SLEARN bonuses are not effort.** Some SLEARN is granted for something other than
  doing guides (the 22-SLEARN pastor bonus is paid when the pastor registers, not for
  guides), which is exactly why the column counts **guides with a SLEARN scholarship**,
  never the SLEARN balance.

## 3. Data and privacy

- New aggregates per user: `guide_approved`, `guide_usdt`, `guide_slearn`, and
  `verdes = guide_approved + guide_usdt + guide_slearn`.
- **Public surface**: the counts must apply the same visibility rule as `sbt_count`
  (`usuario.mostrar_cursos_publico`, and for **category B** courses only when
  `mostrar_cursos_sensibles_publico` is true), otherwise the board would reveal that a
  student studies category B (sensitive) content. The rule lives in one place
  (`packages/rewards/src/lib/course-privacy.ts`, re-exported by
  `apps/nextjs/lib/privacy-visibility.ts`); reuse it, do not write a new one.
  The join is `guide_usuario` → `cor1440_gen_actividadpf` →
  `cor1440_gen_proyectofinanciero`.
- Keep `usuario.excluir_leaderboard` as the opt-out.
- Only `nusuario` is exposed; never the real `nombre` (see `doc/api-security.md` §1).
