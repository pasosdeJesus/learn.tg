**Link:** https://github.com/pasosdeJesus/learn.tg/issues/278

(§4) and agree with the profile's rank; the score does not move with the country filter. The

## 1. Objective

The board and the course page must tell the same story: the **work on the guides**, the
**referrals**, the token columns, and **one global rank** that does not depend on the column the
visitor sorts by. The board is `/api/leaderboard` → `lib/leaderboard-queries.ts` →
`components/LeaderboardTable.tsx`.

## 2. Columns

| Column | Source |
|---|---|
| Rank, User, Country, [Religion] | `usuario`, `msip_pais`, `religion` |
| Platform Score | `platform_score`, §4 |
| Guide Score / Approved / Paid USDT / Paid SLEARN | `guide_usuario` + `transaction`, §3 |
| Profile Score | `usuario.profilescore` |
| SLEARN | net balance (`SUM(balance_impact)` over `transaction`) |
| Scholarship (USDT) | `SUM(amount)`, `type = 'scholarship' AND crypto = 'usdt'` |
| UBI (CELO) | `SUM(amount)`, `type = 'ubi-claim' AND crypto = 'celo'` |
| Donations (USDT) | `SUM(amount)`, `type = 'donation' AND crypto = 'usdt'` |
| SBTs | `credential_emission`, filtered by the R-#259 rule |
| Referrals | `referralrelationship` where the user is the referrer, §5 |

Default order: `platform_score` desc (§4). `usuario.excluir_leaderboard = true` opts a user out of
the board. Only `nusuario` is exposed, never the real `nombre` (`doc/api-security.md` §1). The
board's population is region type 1 only (§4); the three figures it publishes per row are
`platform_score`, `profilescore` and the referral count.

## 3. Guide score — the marks the course page draws

The course page draws, in front of each guide, the marks the student earned: the
**checkmark** (passed), the **USDT** scholarship and the **SLEARN** scholarship. The board
counts them **per guide** with the same rule as `/api/guide-status`, so the two surfaces
cannot disagree:

- **approved**: `guide_usuario.points > 0`;
- **USDT scholarship paid**: `guide_usuario.amountpaid > 0`;
- **SLEARN scholarship paid**: a `transaction` row with `crypto = 'slearn'`,
  `type = 'scholarship'` and `metadata->>'guideId'` = the guide's `actividadpf_id`.

`guide_score` is their sum ("Puntaje en Guías"/"Guide Score"). A guide that is approved but
not paid counts 1 in "approved" and 0 in the paid columns. **All published courses count**,
free and paid. The SLEARN bonus is not effort (22 SLEARN go to the pastor when registering,
not for guides), which is why the column counts **guides with a SLEARN scholarship**, never
the SLEARN balance.

## 4. `platform_score` — the ranking

```
platform_score = 0.35 * n(guide_score)
               + 0.15 * n(referral_count)
               + 0.15 * n(donations_usdt)
               + 0.15 * n(sbt_count)
               + 0.10 * n(slearn_balance)
               + 0.10 * n(profilescore)
```

It **orders** the board (and the profile's rank) and is **published per row** (§2).

- **`n(x)`: min-max over `ln(1 + max(x, 0))`**, in 0–100 after the weighted sum. One rule for
  all six components. `percent_rank()` was rejected: in skewed components (referrals,
  donations, SBTs) it turned the weight into a binary bonus (the first referral jumped to the
  top percentile). `ln(1 + x)` compresses the tail, and a flat component or a one-row
  population contributes **0** instead of dividing by zero.
- **Population — region type 1 only**: the board (`excluir_leaderboard IS NOT TRUE`) whose owner
  is **not** in region type 2 (`msip_pais.tipo_region <> 2`; `NULL` counts as region type 1).
  Computed **before** the country filter, so a student's score and rank do not change with the
  visitor's filter. Because the population carries no region type 2, the formula has no region
  branch: the same six components weigh for every published row.
- **Canonical order**: `platform_score DESC, usuario_id ASC`. `usuario_id` is unique, so the
  order is total and pagination cannot repeat or skip users. The board's **Rank** column
  (`ROW_NUMBER()` over that order) and the profile's rank (`/api/user/[id]`) use the same
  definition, so they cannot diverge.
- **Cost**: computed in SQL. Measured at 24 ms over ~570 users (three times the previous
  query) on the population **before** this revision (region type 1 only); the current
  population is smaller, so the figure is an upper bound until it is re-measured.

## 5. Referrals

`referral_count` counts the `referralrelationship` rows where the user is the referrer — the
**total** (pending and completed together) — in its own subquery grouped by referrer, so the join
cannot multiply the rows of `transaction`. It is published **per student** (the population is
region type 1 only, §4), and the board's summary also shows the platform total
(`totalReferrals`, scoped to the selected country when the board is filtered). The detail
(pending, completed, payouts) stays in `/api/referral/stats`, which authenticates the owner.

## 6. Population, privacy and opt-out

- **Region type 1 only.** The board — and the rank it yields — leaves out the students whose
  country is region type 2 (`msip_pais.tipo_region`; `NULL` counts as region type 1). Their
  profile still publishes their guide score, but neither a rank nor a `platform_score` (both are
  defined on the board's population). The board's summary totals keep aggregating the whole
  platform.
- The counts apply the same visibility rule as `sbt_count`: `usuario.mostrar_cursos_publico`,
  and for **category B** courses only when `mostrar_cursos_sensibles_publico` is true.
  Otherwise the board would reveal that a student studies category B content. The rule lives
  in `packages/rewards/src/lib/course-privacy.ts`, re-exported by
  `apps/nextjs/lib/privacy-visibility.ts`; it is a **TypeScript predicate** with no SQL
  fragment, so the query restates the conditions (SBT subquery and guide subquery). Removing
  that duplication is recorded in https://github.com/pasosdeJesus/learn.tg/issues/252.
- `excluir_leaderboard` applies to the **board**: the profile still publishes that user's
  guide score (the opt-out is about appearing in the ranking, not about hiding the work), but
  not a rank or a platform score, which are defined on the board's population.
- The profile (`/[lang]/user/[id]`) shows the guide score instead of the SLEARN balance and also
  publishes the platform score, the profile score and the referral count (§2). The owner reads
  their own figures in the authenticated `/api/profile` and `/api/update-scores`.
- **Between surfaces.** The guide columns are shown on the board for every published row, and
  the board no longer lists region type 2 students, while the church directory
  (https://github.com/pasosdeJesus/learn.tg/issues/164) hides `guide_score` in region type 2. The
  two no longer overlap.
- The public totals (`getLeaderboardTotals`) aggregate the token amounts and the referrals of
  the whole platform: they are aggregates, not per-person data, and they are part of the
  transparency surface.
- **The country surfaces are region type 1 too.** The country filter lists only region type 1
  countries, and `getLeaderboardTotals` applies the same rule when a country is selected, so a
  request for a region type 2 country returns no rows and zero totals (a whole country is type
  1 or type 2 in `msip_pais`, and a per-country total for a region type 2 country would point
  at its single student). The transparency breakdown per country
  (`getLeaderboardTotalsByCountry`) follows the same rule; the platform-wide totals stay as
  they are.

## 8. Acceptance criteria

- [x] The three guide columns and their sum match the per-guide mark of the course page.
- [x] All published courses count; a category B course with the switch off does not.
- [x] `excluir_leaderboard = true` hides the user from the board.
- [x] The board's Rank and the profile's rank are the same number.
- [x] The board lists only region type 1 students (`msip_pais.tipo_region <> 2`; `NULL` as region type 1).
- [x] `platform_score` is computed in SQL as the weighted sum of the six normalized components, with no region branch.
- [x] The canonical order is `platform_score DESC, usuario_id ASC`.
- [x] A student's rank does not change with the country filter.
- [x] `platform_score`, `profilescore` and `referral_count` are published **per row** on the board and on the profile.
- [x] A region type 2 or opted-out user has no rank and no platform score on the profile, but keeps the guide score, the profile score and the referral count.
- [x] The board can be sorted by `platform_score`, by `profilescore`, by `referral_count` and by each published component.
- [x] `MetricsExplanation.tsx` documents the formula, the weights and the normalization.
- [x] `make type` and the affected suites green; `bin/audit-api-auth.mjs` at 0 failed; `node audit-crushrules.mjs` at 0 findings.

  is rejected.
- `app/api/user/[id]/__tests__/route.test.ts`: the profile returns the rank, the guide score, the

  gets the guide score but no rank and no platform score.
- Manual: load `/en/leaderboard`, sort by each column, filter by country, and compare one
  student against their profile and their course page.

## 10. Out of scope

- Persisting `platform_score` (it is computed on the fly; a materialized view can be added if
  the population grows and the query becomes expensive).
- Exposing the intermediate values of the formula.
- A score history over time.
