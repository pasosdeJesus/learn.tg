## Root cause (hypothesis)

Both failing routes rely on mocks registered via `vi.mock` **inside helper
functions** (`setupCrosswordMocks()` / `setupApiMocks()`), invoked from
`beforeAll` — not at the top level of the test file:

```ts
// test-utils/crossword-mocks.ts
setupRemarkFillInTheBlankMock() {
  vi.mock('@/lib/remarkFillInTheBlank.mjs', () => ({
    remarkFillInTheBlank: mockRemarkFillInTheBlank,
  }))
}
// … also vi.mock('crossword-layout-generator-with-isolated', …)
```

```ts
// app/api/guide/__tests__/route.test.ts
beforeAll(async () => {
  setupMocks()
  setupCrosswordMocks()   // ← vi.mock called here, not at top level
  setupApiMocks()
  const mod = await import('../route')
  GET = mod.GET
})
```

vitest 3.x no longer honors `vi.mock` registered this way (mock registration is
hoisted to the top of the module; calls made inside helpers/`beforeAll` are not
applied). The real modules then run in the test (`remarkFillInTheBlank.mjs`,
`crossword-layout-generator-with-isolated`) and throw, so the routes return 500.

This worked under vitest 2.1.9 (more lenient hoisting) — hence the regression
only appears after REQ/205.
