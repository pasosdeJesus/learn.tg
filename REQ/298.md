# R-#298: Compile, test and deploy the contracts with `contract:*` from `m` (no Hardhat)

**Link:** https://github.com/pasosdeJesus/learn.tg/issues/298
**Created:** 2026-11-09
**Status:** Implemented and verified (2026-11-12) — ready to close. The plan in sections 3-5 is kept
as the record of the migration; results in sections 8 and 9.
**Type:** Contracts / build tooling
**Priority:** Medium — removes a heavy dependency tree (Hardhat, toolbox, ignition, gas-reporter,
coverage, typechain-hardhat, ts-node) and the OpenBSD native addon patch that exists only for it.

## 1. Objective

1. Replace Hardhat in **both** Solidity projects (`apps/contracts` and
   `packages/gdcluster/contracts`) with `bin/m contract:*` (`m` >= 0.37, `@pasosdejesus/contract-test`
   >= 0.3.5): `compile`, `test`, `typechain`, `deploy`, `verify`, `checkdeploy`, `node`, `clean`.
2. Keep the artifacts in Hardhat's shape, so `sync-abis.mjs`, `typechain` and every consumer of
   `apps/web/abis` keep working without changes.
3. Keep the compiler **pin unchanged (0.8.24)**, so the bytecode stays identical and the already
   verified deployments do not need re-verification.
4. Keep the test suites as they are (**92** cases in `apps/contracts`, **7** in the `gdcluster` engine):
   `contract:test` mocks the Hardhat modules the tests import.
5. End with no `hardhat` (or `@nomicfoundation/*`, `@nomiclabs/*`) in the dependency tree.

## 3. Decisions

### D1. Keep the pin at 0.8.24 (the only choice that changes bytecode)

| Option | How | Consequence |
|---|---|---|
| **Keep 0.8.24 (chosen)** | add `solc@0.8.24` as a devDependency of `apps/contracts` (the project's `solc` wins over the bundled 0.8.26) | artifacts **byte-identical** to the ones Hardhat produced: no re-verification, no new deployments |
| Move to 0.8.26 / native 0.8.37 | nothing to install | ABI and storage unchanged, deployed bytecode changes; applies to new deployments only and the default `evmVersion` moves to `cancun`, so it must be written explicitly |

If the pin ever moves, set `evmVersion` explicitly in the config (0.8.25+ defaults to `cancun`) and
re-verify only the contracts deployed from then on.

### D2. One literal config per project

`m-contracts.config.ts` (`contract:compile`/`deploy`/`verify` read it with regular expressions: a
literal object, no imports, `solc`/`optimizer`/`viaIR`/`evmVersion` before `networks`):

- `apps/contracts/m-contracts.config.ts`: pin `0.8.24`, optimizer 200, `viaIR: true`, the four networks
  and the two explorers (`celo`, `celoSepolia` with `BLOCKSCOUT_API_KEY`; `base`, `base-sepolia` with
  `BASESCAN_API_KEY`).
- `packages/gdcluster/contracts/m-contracts.config.ts`: same compiler block and networks; no explorer
  block (its verification runs from `apps/contracts`).

`contracts.config.json` is not enough here: it has no networks/explorer block and would force `--rpc`
on every deploy.

### D3. The tests stay as they are, and `run-tests.mjs` disappears

`bin/m contract:test` provides `hre.ethers`, `hre.network`, `hre.artifacts`, `loadFixture`,
`time.increase`/`increaseTo` and the chai matchers (`reverted`, `revertedWith`, `revertedWithCustomError`,
`emit`, `withArgs`). The usage measured in §2.3 is inside that set.

- Delete `apps/contracts/run-tests.mjs` and `packages/gdcluster/contracts/run-tests.mjs`, the `apps/`
  symlink directory and the `node_modules` symlink the engine creates.
- Add `types/hardhat-chai.d.ts` (copied from the `m:create` template) and include it in
  `apps/contracts/tsconfig.json`, because no installed package carries the matcher types once
  `@nomicfoundation/hardhat-toolbox` is gone.
- The engine project has **no `node_modules` of its own**: `run-tests.mjs` symlinked it to
  `apps/hardhat/node_modules`, which no longer exists, so its contract tests cannot run today (§2.3).
  Decision: add `packages/gdcluster/contracts` to `pnpm-workspace.yaml` and declare its devDependencies
  there (`chai`, `@openzeppelin/contracts`, `solc` (same pin as the other project), `tsx`,
  `@pasosdejesus/contract-test`, `@pasosdejesus/edr`, `ethers`) with `catalog:` versions; the command
  then resolves them from the project itself and `run-tests.mjs` (and its symlink) disappears. Fallback
  while that is not done: repoint the symlink to `apps/contracts/node_modules` from a script, never by
  hand.

### D4. Deploy and verify

| Hardhat today | Replacement (as implemented) |
|---|---|
| `hardhat run scripts/X.ts --network $NET` for the deploy and operational scripts | `node --import tsx scripts/X.ts` behind the same `bin/` wrappers; the runtime is `scripts/lib/ethers-cli.ts` (plain `ethers`, the network from `NEXT_PUBLIC_NETWORK`, the deployer wallet and factories/contracts from `artifacts/`) |
| `hre.run('verify:verify')` in the seven `contractVerification*` scripts | `bin/verify-source <Contract>` (`scripts/verify-source.ts`): reads the constructor arguments from the deployment JSON and calls `bin/m contract:verify` |
| task `check-transfer` (`hardhat.config.ts`) | deleted with the config; the transfer check is `publicClient.getTransactionReceipt` in a one-off script |
| `scripts/old/**`, `bin/old/**`, `ignition/`, `bin/prepadJ.sh` | deleted |

Keeping the scripts (instead of rewriting each deploy as `contract:deploy`) preserves the post-deploy
work they do (role grants, fee configuration, multi-contract wiring, the extra fields of
`deployments/*.json`: `usdtAddress`, `slearnAddress`, `pdjTreasury`, `initialOwner`) and the exact shape
`sync-abis.mjs`, `lib/deployments` and `contract:checkdeploy` read. `contract:deploy`/`contract:verify`
remain available and documented for a new contract or a one-off deploy.

### D5. Delete the OpenBSD glue

`bin/prepadJ.sh`, the `prepadJ` script and the `build` shortcut that called it exist only to compile and
patch Hardhat's `@nomicfoundation/solidity-analyzer`. Without Hardhat they are dead weight; `make all`
from the root already runs `pnpm install` before the builds.

## 4. Migration steps (additive until step 6)

1. **Measure and back up the artifacts.** `cp -R apps/contracts/artifacts /tmp/artifacts-hardhat` and
   run the parity harness of `m/doc/contract-compile.md` §0 (`SOLC_PARITY_SOURCES=… SOLC_PARITY_VIA_IR=1`).
2. **Pin.** `pnpm add -D solc@0.8.24` in `apps/contracts` (from the repo root, one workspace) and check
   `node -e "console.log(require('solc/package.json').version)"` from that app.
3. **Configs.** Add both `m-contracts.config.ts` (D2). Keep `hardhat.config.ts` untouched for now.
4. **Compile and compare.** `bin/m contract:clean && bin/m contract:compile`, then the comparison script
   of the `m` doc (it must print `artifacts identical (abi + deployedBytecode)`).
5. **Tests.** `bin/m contract:test` in `apps/contracts` (92). For the engine project, first make it a
   workspace member with its own dependencies (D3); then `bin/m contract:test` there (7). `make type`
   for `apps/contracts` with `types/hardhat-chai.d.ts` in `tsconfig.json`.
6. **Typechain and ABIs.** `bin/m contract:typechain --target ethers-v6 --out-dir typechain-types` and
   `node sync-abis.mjs`; `git status apps/web/abis` must be clean.
7. **Deploy and verify** (D4) against `celoSepolia`, comparing against the current wrappers.
8. **Remove Hardhat** (the step that stops being additive): drop `hardhat`,
   `@nomicfoundation/hardhat-chai-matchers|ethers|ignition-ethers|network-helpers|toolbox|verify`,
   `@nomiclabs/hardhat-ethers`, `hardhat-gas-reporter`, `solidity-coverage`, `@typechain/hardhat` and
   `ts-node` from `apps/contracts/package.json`, and `hardhat`, `@nomicfoundation/hardhat-toolbox`,
   `ts-node` from `packages/gdcluster/contracts/package.json`; keep `typechain`, `@typechain/ethers-v6`,
   `tsx`, `chai`, `ethers`, `@openzeppelin/contracts`, `@pasosdejesus/contract-test`,
   `@pasosdejesus/edr`. Point the scripts at the new commands:

   ```json
   "scripts": {
     "compile": "node scripts/sync-usdt.mjs && bin/m contract:compile && node sync-abis.mjs",
     "test": "bin/m contract:test",
     "clean": "bin/m contract:clean",
     "run:node": "bin/m contract:node",
     "build": "pnpm compile && pnpm tsc"
   }
   ```

   Delete `hardhat.config.ts`, `ignition/`, `cache/`, both `run-tests.mjs`, `bin/prepadJ.sh` and the
   `apps/` symlink.
9. **Makefile and docs.**
   - root `Makefile`: `test` still enters `apps/contracts` (`pnpm test` -> `contract:test`); `type` and
     `check` unchanged.
   - `apps/contracts/README.md`: commands table (`compile`, `test`, `deploy`, `verify`), the pin and
     `m-contracts.config.ts`, and the note that the OpenBSD addon patch is gone.
   - `ARCHITECTURE.md` §Web3 Engines (the "`contract:test` (from `apps/web`) runs `apps/contracts/test`"
     sentence describes a target that does not exist today: it must point to `apps/contracts`).
   - `doc/deploy-credentials.md` and `REQ/293.md` mention `pnpm compile`/`bin/next/deployLearnTGVaultsV6`:
     keep the same entry points through the new scripts.

## 6. Risks and notes

- **Bytecode**: identical only while the pin stays 0.8.24 (§D1). Changing it is a separate decision with
  its own verification.
- **OpenBSD**: the runner falls back to `@ethereumjs/vm` (`OpenBSD detected — using @ethereumjs/vm
  fallback (EDR not available)`), so `@pasosdejesus/edr` stays as a dependency for the other platforms.
- **`typechain-types/` is gitignored**: `contract:clean` removes it together with `artifacts/`, `cache/`
  and `dist/`; `pnpm tsc` (which copies the `.d.ts` into `dist/`) must run after `contract:typechain`.
- **Operational scripts** that read chain state (`testClusterFunds`, `set-slearn-per-course`,
  `migrateClusterFundsV1ToV2`) need a viem rewrite before `hardhat` is uninstalled; the deploy/verify
  families are covered by `contract:deploy`/`contract:verify`.
- **`deployments/` extra fields**: `sync-abis.mjs` and `lib/deployments` read that directory; a deploy
  that writes only the generic fields silently drops `usdtAddress`/`slearnAddress`/`initialOwner`.
- **`prepadJ.sh`** is OpenBSD-only and exits immediately elsewhere; removing it does not affect Linux/CI.

## 8. Implementation result (2026-11-09)

- **Pin and config.** `solc@0.8.24` added to `apps/contracts` devDependencies;
  `m-contracts.config.ts` written for both projects. Comparing against Hardhat's
  `build-info` showed the settings it had used were `evmVersion: paris` (not the
  compiler's default), so the config states it: with any other target the deployed
  bytecode changes.
- **Compile and tests.** `bin/m contract:compile` writes the 40 artifacts and
  `bin/m contract:test` runs **92** cases in `apps/contracts` and **7** in the engine,

  `@nomicfoundation/hardhat-toolbox/network-helpers.js` and
  `@nomicfoundation/hardhat-network-helpers`; `types/hardhat-modules.d.ts` keeps them
  typechecking).
- **Parity.** `abi` and `deployedBytecode` are identical for **39 of 40** artifacts.
  `next/LearnTGVaultsV6.sol` differs only in the CBOR metadata hash: its source changed
  after Hardhat's last build (the artifact was stale, same length and same code bytes,
  first difference at byte 22984 of 23070). V6 is not deployed, so nothing to
  re-verify.
- **Typechain and ABIs.** `bin/m contract:typechain` regenerates 113 typings and
  `pnpm tsc` passes; `node sync-abis.mjs` leaves `apps/web/abis` **unchanged**
  (`git status` clean).

### 8.3 Known gaps left out of scope

- `bin/m contract:checkdeploy` (part of `make check`) reports two errors for the
  **V3** and **V6** `celoSepolia` deployment JSONs: those files are gitignored and are
  not in this clone (V6 is not deployed by design, R-#293). The finding is
  environmental, not caused by this migration. Both are addressed:
  - **V3** = `0x8f2F458366ef5EB49de17052d01e608Bdc32Ff2c`, recorded in
    `apps/contracts/deployments/LearnTGVaults/V3/celoSepolia.json` (gitignored: each
    machine/deploy needs the file). Evidence: it implements the full 22-function
    surface of the committed `LearnTGVaultsV3.sol` (including `setAmountPerGuide`),
    holds the current USDT/SLEARN, is owned by the backend wallet and has **zero**
    balance, i.e. it is the vault migrated to V4. The other candidate,
    `0x0db4bb854235aEe7067396aCd3Ed81CFF010dDD7`, is also `VERSION = 3` but from an
    earlier revision (no `setAmountPerGuide`), with older tokens and test funds left.
  - **V6** is declared in `contract-check.json` under `allowMissingDeployments` with
    the reason, which needs the `@pasosdejesus/contract-test` release described in
    §8.4; with the built `m` code the check reports `0 error(s)`.
- The operational `scripts/*.ts` are not part of `pnpm tsc` (the tsconfig includes
  `scripts/lib` only, as before the migration); they run through `tsx`.

Two test-infrastructure problems surfaced while running the suites and were fixed on
the way (the catalog moved `@pasosdejesus/m` from 0.37.9 to 0.37.15 in the install,
which made them visible):

- `apps/web/lib/__tests__/kysely-db.test.ts` expected `PG_POOL_MAX ?? 10` while
  `.config/kysely-db.ts` defaults to 20, so `make test` failed on a shell without the
  variable; the expectation now matches the code (20) and passes with or without it.
- `apps/web/vitest.setup.ts`: the radix mocks of `@pasosdejesus/m` register a
  `@radix-ui/react-dialog` mock **without `Portal`** and, because that import runs after
  the hoisted `vi.mock` calls, it won over the app's own mock; `WalletPanel.test.tsx`
  failed with `No "Portal" export`. The app now re-registers its dialog mock at runtime
  (`vi.doMock`), which is the one actually used.

### 8.4 Improvement in `m`: ignore sources and accept an absent deployment

`contract:checkdeploy` only knew how to accept **literals** (`allowAddresses`); a reference the tree
cannot satisfy (a gitignored deployment, a contract not deployed yet) was always an error. Added to
`m/packages/contract-test` (`src/check-deploy.ts`, `src/i18n.ts`, `doc/contract-checkdeploy.md`):

| What | Where |
|---|---|
| `--ignore <glob>` (repeatable) skips matching sources in both parts of the check | `parseArgs` / `ignoredSources` |
| `ignoreFiles: string[]` in `contract-check.json` (so a bare `make check` honors them) | `repoConfig` |
| `allowMissingDeployments: { "<contract> <version> [network]": "<reason>" }` accepts a `DEPLOYMENT_MISSING` per contract and version and prints the reason as a note | `allowedMissing` |

Tests: `__tests__/check-deploy.test.ts` grew to 23 cases (the six new ones cover the config and the
option paths); the package suite is 149 passed / 5 skipped. Measured against this repo with the built
code: `0 error(s), 13 warning(s)`.

**Pending, operator side:** release `@pasosdejesus/contract-test` (version bump and publish; `m` work
item 52/60) and bump `catalog:@pasosdejesus/contract-test` in `pnpm-workspace.yaml`. Until then the
installed 0.3.5 ignores the new keys and `make check` keeps reporting the V6 error.

sat in `devDependencies` while imported at runtime; they moved to `dependencies`, together with
`@pasosdejesus/usdt`, `generated-msip` and `generated-wallet` (reported by `eng:verify` 0.37.18 and
confirmed after 0.37.19 extended the audit to `components/` and `lib/`).

**Residual, by design:** `apps/contracts/deployments/` is gitignored, so the V3/V4/V5 JSONs must exist
on each machine that runs the deploy or verify scripts; a clone without them loses those scripts, not
the build or the tests.

**Closing:** the requirement is done; the remote issue and the local file are closed by the operator
with `bin/m req:close 298` (it syncs the file, closes the issue and removes `REQ/298.md`).
