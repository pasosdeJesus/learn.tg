## 1. Principle: the interface is the manual

The learner should not have to read a manual to use the site: the interface teaches **as it is
used**. Default screens stay **super simple** and help appears **contextually** — when something
is empty, when it is the first time, when there is an error or when the user asks. Long prose
belongs in the course and in the docs; the UI keeps a one-line reason and a link.

| Idea | Where | Shape |
|---|---|---|
| First-run callouts (coach marks), one per surface, dismissible and remembered per device | header pill, wallet panel, guide page, course page | a small callout pointing at the control ("Create your wallet here — free, no app to install"), with **Learn more →** |
| Each state names the next action, not the error | `WalletSelector`, `WalletPanel`, `GoodDollarClaimButton`, `CeloUbiButton`, `CheckoutModal`, `DonateModal` | already partly true (the GoodDollar button names locked/provider/network); extend to premium/UBI/referral |
| Inline help, a `?` next to the operation | create/import, send, buy, donate, claim UBI, privacy switch | a popover with 2-3 lines + a link to the course guide or the relevant `doc/` page |
| Empty states that teach | collectibles, scholarships, vault empty, notifications | "No collectibles yet — complete 100% of a course; see Guide 3" |
| One clear "Help / How this works" entry | header or footer | links to the help hub (§4) that lists the student topics |
| Progressive disclosure | everywhere | the minimal control is shown; the explanation lives behind the `?`/callout |
| Bilingual and accessible | all the above | EN/ES through `createComponentT`; `aria-label`/`role` as the wallet rings already do |

The model is the payment modals: they already say **why** the wallet cannot sign and offer the
unlock action (`wallet-unlock-request`); the same pattern should cover every blocked state.

## 2. The course: mention every feature, link the rest

The guides must **mention exhaustively** what the learner can do, each item short (the 400-600
word rule of `doc/guide-writing.md` is kept) and with a **link to the secondary page/doc** where
the steps live. Guide 2 already links to `/en/migration-in-app-wallet`; that is the pattern.

Topics to add (as short mentions + links), from the source review:

| Topic | Link target |
|---|---|
| Sign in and the wallet states (in-app vs external, sign the SIWE message, disconnect, partial login) | the header pill itself + `doc/wallet-auth.md` |
| Daily wallet use: lock/unlock (fingerprint/Face ID), auto-lock, receive (QR), **send** CELO/USDT/SLEARN, lock now, delete, recover the password | a `doc/` page (today `doc/pdJ-wallet.md`) |
| **Buy a premium course** (price by country/HDI, pay in USDT or SLEARN, discount) | the course page and `CheckoutModal` |
| **Donate** to a course vault (10 % back in SLEARN) and to campaigns | `/en/donations`, `DonateModal` |
| **Referrals** (10 %, +1 USDT to pastors) | `/en/referrals` |
| **Privacy of sensitive content (category B)** (publish or not; device copies deleted) and revoking a credential | `/en/settings` |
| **Identity verification**: self.xyz (passport) and scheduling the interview | `/en/profile` |
| Notifications bell (offline results) | R-#162 |
| Leaderboard, transaction history, transparency | `/en/leaderboard`, `/en/user-transactions`, `/en/transparency` |
| Crossword mechanics (up to 5 questions shown, retakes, offline queue, cooldown) | Guide 3 (today thin) |
| Add SLEARN to an external wallet | the home button |

Rules: EN (`resources/en/web3-and-ubi/`) and ES (`resources/es/web3-e-ibu/`) stay in sync, 6-8
comprehension questions per guide with the answer in the **last** parentheses, and the relative
links use the in-app style (`[Guide 3](../guide3)` for the course, `/en/<page>` for the rest).

## 3. A help hub and secondary pages

- **Help hub**: a public page `/{lang}/help` (ES `/{lang}/ayuda`) that indexes the student topics
  and links to the secondary pages and docs. It is the single "manual" entry the interface points
  to (the `?` popovers and the header entry link here).
- **Secondary pages** for the key topics, using the **same pattern as the migration guide** —
  a public page that reads a Markdown file and is cached by the service worker:
  `components/migration/MigrationGuidePage.tsx` + `lib/migration-guide.ts` reads
  `doc/migration-in-app-wallet/{en,es}.md` and serves `/{lang}/migration-in-app-wallet`
  (and `/es/migracion-billetera-app`). Reuse it for:
  - wallet daily use (from `doc/pdJ-wallet.md`),
  - offline / install the app (from `doc/pwa-user-guide.md`),
  - premium purchase, donations, referrals, privacy of sensitive content (category B), verification and UBI
    claiming.
- **Docs stay the source of truth**: the pages are thin readers of `doc/<topic>/{en,es}.md`, so
  the content has one home and both the course and the UI help link to it.
- Add a short **student-docs index** (`doc/README.md` or a section in the existing docs) and
  reference it from `AGENTS.md` / `apps/nextjs/CONTRIBUTING.md`.

## 4. Acceptance criteria

- [ ] Every operation with a blocked/empty state in the wallet, guide, premium purchase, donation,
      UBI claim, referral and privacy surfaces says the **next action** and (when useful) links to
      the course or a secondary page, EN and ES.
- [ ] First-run callouts exist for at least: create the wallet, the collectibles tab, the privacy
      switch and the offline download control; each is dismissible and remembered per device.
- [ ] The collectibles/scholarships/notifications empty states teach how to get the first item.
- [ ] A `?`-help entry next to create/import, send, buy, donate, claim UBI and the privacy switch
      opens a short explanation with a "learn more" link.
- [ ] The Web3 & UBI course mentions every topic of §2 with a working link, in EN and ES, keeping
      the guides within 400-600 words and 6-8 comprehension questions.
- [ ] `/{lang}/help` exists, is linked from the header/footer and lists the secondary pages.
- [ ] At least the wallet-daily-use and offline pages exist with the migration-guide pattern and
      are cached offline.
- [ ] `make type`, the affected suites and the route audit are green; EN/ES parity checked.

## 5. Testing plan

- **Unit**: the help/callout components (render, dismissal stored, EN/ES) and the empty-state
  strings; a test that every `?`-help link resolves to an existing route.
- **E2E (Puppeteer, dev site)**: a first-visit run asserts the create-wallet callout points at the
  pill and disappears after dismissal; the collectibles empty state shows the "complete a course"
  line; the `?` popover opens and its link navigates; `/{lang}/help` lists the topics.
- **Content**: a relative-links check for the course guides (the guide pages fail on a broken
  in-course link) and the EN/ES guide-name parity check used by the course tests.
- **Manual (operator)**: walk the whole student journey on a phone with a new wallet and confirm
  the UI explains each step without reading a guide.

## 6. Notes

- This requirement is the umbrella of the interface/course/docs improvements; the wallet panel and
  GoodDollar specifics are R-#276, and the GoodDollar claim is R-#275.

- The help hub and the secondary pages are public (no session); they should be readable offline
