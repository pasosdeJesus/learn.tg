## 3. Gaps to close

All six are closed (2026-11-19); the notes say where each one landed.

1. **Guide 2, the 6-character code.** Remove it from the text and from its comprehension question
   (Q4): the product deleted the code in R-#299. The guide must teach the two real ways to invite —
   the **candidate list** (referrals) and the **wallet** of a verified pastor. *Done: the text and
   the questions are rewritten, and `guides-content.test.ts` fails if the code reappears.*
2. **Guide 2, "before you invite".** One short checklist: account, in-app wallet, verified profile,
   Web3&UBI + A relationship with Jesus, GD course paid. (The 22 SLEARN welcome bonus is a separate
   gift, not a payment for the course.) It is the order the product already enforces through its
   candidate filter. *Done: the five steps are in "Your task" ("Tu tarea").*
3. **The evaluation is painted in four cards.** `ClusterPresentationPanel` renders that block
   outside the `section` guard, so a returned request repeats it under Budget, Director, Approvals
   and Present to GD. Show it once, in **Present to Global Disciples**. The evaluation is a single
   text field (`gd_evaluation`); there is no separate "suggestions" field. *Done: the panel guards
   it with the `section`.*
4. **The release is invisible from `/cluster`.** After `answered`, the private page should show the
   release: `fund_released_at`, the USDT amount (`fund_released_amount`), the SLEARN amount
   (`fund_released_slearn`) and the hash or link to the transaction. Data already available from
   `GET /api/cluster/[id]`; no new endpoint. *Done: the release card shows amounts, date and the
   explorer link.*
5. **Donate from the public page** (decided: yes). `/{lang}/clusters/[slug]` now has a **Donate to
   the cluster fund** button fed by `donation_wallet` from that API: the wallet is published only
   while donations are accepted (type-1 country, fund not released, cluster not presented) and it
   reuses `DonateModal` (80 % fund / 10 % pdJ / 10 % cashback). Guide 3 points there. *Done.*
6. **The budget the course talks about is the fourth year's.** See §4.2: make it consistent in
   guides 4 and 6 (and their questions); the page's card is the reference. *Done: both languages say
   "fourth year" and keep the 45/30/15/0 table.*

### 4.2 The budget is the fourth year's; the first years are cheaper for the student

Decided (2026-11-15):

- The number the cluster must plan is the **fourth-year budget**: Global Disciples covers the
  **45 / 30 / 15 / 0 %** curve, so from year 4 the academy stands on its own. That is the amount the
  page asks for (`clustergd.fourth_year_budget`) and the one the pastors approve and pdJ sends with
  the presentation.
- In the **first years the students should pay less**, with the difference covered by Global
  Disciples: a lower price is what fills the first cohorts and builds the good will the academy
  needs. The guide must say so with the arithmetic, instead of presenting a flat price for four
  years.
- Guide 4 therefore teaches: the line items, the worked example, the **four-year curve** (what GD
  covers each year, what students pay, what the cluster must raise) and the **fourth-year total** as
  the goal; guide 6 ties the pastors' approval to that budget.

### 4.3 Diagrams: written in the guide, rendered offline (decided)

The source lives **inside the guide**, in a fenced Mermaid block whose info string carries the alt
text, so the diagram and the paragraph that explains it move together:

````markdown
```mermaid Three churches invite two others each
flowchart LR
  A[Church 1] --> C[Cluster]
```
````

`apps/web/lib/remarkMermaid.mjs` (wired into `guideProcessor`, `apps/web/lib/guide-markdown.mjs`)
replaces the block with `<img src="/img/diagrams/<hash>.svg" alt="…">`. An image, not inline SVG,
because the guide HTML is also built **in the browser**: `mermaid` is tens of megabytes, a flowchart
takes seconds, and the course page renders with `allowDangerousHtml: false`. The `<img>` also keeps
`guideImageUrls` working, so the diagram is cached for offline reading.

The SVG is generated **before the commit**, from Node, with no Chromium and no Mermaid runtime in the
app; the file name is a hash of the source, so editing a diagram creates a new file and the old one
is pruned:

```sh
cd apps/web
node bin/mmd2svg.mjs --scan ../../resources --out public/img/diagrams --theme neutral
```

- Renderer: **`@speajus/mermaid-to-svg`** (`apps/web` devDependency). Pure Node — Mermaid parser +
  ELK.js + React `renderToStaticMarkup`, text measured with jsdom — so it works on OpenBSD/adJ:
  measured 2026-11-15, flowchart 2–6 s and sequence under 100 ms.
- Themes `default · dark · forest · neutral`; the guides use `neutral` to match the page, and
  `--force` regenerates when the theme changes.
- `@mermaid-js/mermaid-cli` is **not** used (it needs Puppeteer/Chromium); `sebastianjs`
  (`node-canvas`) is not used either.
- Both files are committed: the guide holds the source, the `.svg` is the artifact the site serves
  (and the service worker caches for offline reading).
- `apps/web/lib/__tests__/guides-consistency.test.ts` fails when a diagram has no SVG generated or
  no alt text, so a forgotten scan does not reach the commit.
- `make all` / `make prod` run the same command (target `make diagrams`, after `pnpm i`): 0.3 s and
  no renderer import when there is nothing new, so the build never ships a guide without its SVG.
- A standalone `.mmd` still works (`node bin/mmd2svg.mjs diagrama.mmd salida.svg`) for diagrams
  outside a guide.

`guides-consistency.test.ts` (it does not duplicate it; 4 tests, both green 2026-11-19) and fails
on: fewer than 8 questions or a

the stale "6-character code" reappearing in any guide, a guide that points nowhere (every guide
must link to the cluster page or to another guide), and a different number of sections between
languages. It prints the word count per guide.
